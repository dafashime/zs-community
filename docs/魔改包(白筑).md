白筑魔改版 = **生产服自研"魔改层" + 一批被替换的魔改模块**，与 base（原版 218 模块）的关系是"整体替换 + 覆盖层"：

## 4. 解密方法

生产 `mir2.zip` 头 `30 31`（"01" sign）+ XXTEA，密钥 = `strrev(08 75 4D 69 52 40 59 0B 47 6F 6D 67 21 38 34 07)`（即引擎 `ORIGINAL_XXTEA_KEY` 反转）：

```php
// 见 _mumu/decrypt_prod_mir2.php
$t = new XXTEA();
$t->setKey(strrev("\x08\x75\x4D\x69\x52\x40\x59\x0B\x47\x6F\x6D\x67\x21\x38\x34\x07"));
$d = $t->decrypt(substr(file_get_contents('…/mir2.zip'), 2));
// $d 前 2 字节 = PK，产物 = _mumu/_prod_mir2_dec.zip（204 条目）
```

运行器：`Quick-Cocos2dx-Community-3.6.5\quick\bin\win32\php.exe`。
`config.zip` 为标准 zip，直接可读；其中字节码条目同为生产格式，需转码。

## 5. 字节码格式研究（核心结论）

### 5.1 已查实事实

1. **生产字节码头与本地一致**：`1B 4C 4A 02 02`（LuaJIT 2.00 BC），与本地 beta2/master 编译产物**头部完全相同**；
2. **生产字节码带 0x17-XOR 指令混淆**：
   - 上游 LuaJIT v2.1.0-beta2 原始实现（`ls->mode` 含 `p` 时生效）：`p[i] ^= ((i+1)*0x17) & 0xff`（每个 proto 的指令数组，读入后/写前处理）；
   - 见 `BETA2_PROTECTED_REPRODUCIBILITY.md`（`external/lua/luajit/`）明文记载与 `beta2-protected.patch`；本地运行时把该门控改成了 `ls->pe`（protected 读）门控；
   - **生产发布方编译产物 = 混淆流**（即"beta3+ 格式"表象的真相）；
3. **格式本身无差异**：用官方 **master LuaJIT（git 1ee778a，版本串 2.1.1787165859）**从 rebuilt-src 明文源码编译的全部 4 个包，**在本机 beta2 运行时上完整运行**（启动→服务器列表→ticket→选角→进游戏→背包全链路 ✅）。结论：只要**解除混淆**，生产包即可在本机运行；
4. 生产运行时证据：卧龙 APK `lib/x86/libcocos2dlua.so` 版本串 `"LuaJIT 2.1.0-beta2"` —— 生产运行时是**带反混淆特性的 beta2 系**；
5. 曾怀疑的"常量池差异"（`attempt to perform arithmetic on a function value`）**全部由混淆导致**（混淆流被按明文读 → 指令被 XOR 破坏 → 常量错读）。`head_bcdump.h` 相对 `b2_bcdump.h` 确有新 flags（`BCDUMP_F_BITOP 0x10`、`BCDUMP_F_DETERMINISTIC 0x80000000`），但**本题不构成阻碍**（可作为 LuaJIT 版本差异的旁证记录）。

## 9. 已知阻塞（按严重度）

**a. 生产启动自旋（✅ 已解决，2026-08-24 定位+修复）**
- 原判断："授权/看门狗 while 自旋" —— **不成立**。真实因果链：
  1. 组装包里的 `mir2.bzconfig` 是**损坏的文本 chunk**（换行丢失，行尾 `--注释` 把下一行的 `}` 吃进注释 → `def.fadeLabel` 等 table 永不闭合 → **Lua 语法错误**）。损坏版来自 `_prod_final/cfg_mir2.bzconfig.chunk`（54,527B/1256行，带 BOM）；干净版 = `_prod_conv2/cfg_mir2_bzconfig.chunk`（47,055B/1377行，UTF-8，且 `gateIP=127.0.0.1` 已打本地补丁），与服务器明文 `D:\MirServerZS\knphp\wwwroot\assets\res\mir2.bzconfig` 一致（1377 行）。
  2. `LuaStack::luaLoadChunksFromZIP` 的**栈残留 bug**（引擎侧）：条目 `luaLoadBuffer` 失败时错误串留在栈上且不弹出；下一个成功条目执行 `lua_setfield(L,-2,...)` 时索引到残留字符串 → 抛 `attempt to index a string value` → **整个 zip 加载中止**，之后的条目全部丢失（`mir2.init` 不在 preload → `module 'mir2.init' not found`）。
  3. 因此 mod 模式永远停在 modpatch 加载失败的黑屏/upt 场景 —— 并非授权自旋。
- 修复：`build_mod_final.php` 改为**跳过损坏的 cfg bzconfig**（保留干净的 `_prod_conv2` 版本）；`_prod_final/cfg_mir2.bzconfig.chunk` 已用干净版覆盖（原件备份为 `*.corrupt.bak`）。重建后 220 条全部可加载。
- 元凶之二（组装顺序）：生产包内容是"prod 204 + cfg 16"，**cfg 层同名模块覆盖 prod**（btnCallbacks/bag/storage/storage1 共 4 个重名，属设计如此）；打包顺序必须 **prod 先、cfg 后覆盖**，且 zip 必须用 minizim 兼容格式（PHP ZipArchive / bsdtar 均可；**.NET ZipArchive 生成的文件在 minizip 遍历时丢条目，不可用**）。

**b. 登录场景 76 秒闲置看门狗（当前 mod 模式最后一关）**
- 生产行为：登录场景（`mir2.scenes.login.scene` 的调度回调）启动约 76 秒后调用 `os.exit(nil)`（字符串池 `bztime/bzmir/exit/byebye` 即此逻辑）—— 不是授权，是"请在登录界面尽快登录"的超时。
- 本地绕过：`upt/main.lua` 的调试插桩拦截 `os.exit`（记录调用栈、进程保持存活）——已在库内；或**在 76 秒内完成登录**（推荐，最终还是要登录）。
- 实测：拦截后进程存活，登录界面与本地 8088 已互通（屏幕公告"天龙巨献…"即来自本地 `/account` 响应）。

**c. `mir2.cc` 未包含依赖**
- 魔改 `btnCallbacks` require `mir2.cc`；该模块只在完整生产包内（已含于 220 条目，无需单独处理）。

**d. 生产配置域**
- 生产默认 `zy03.zym2.com.cn` / 密码 `7g9egjkew`；本地已覆盖（bzconfig `gateIP=127.0.0.1`，实测 `def.gateIP=127.0.0.1:8088`、`def.loginCenter=http://127.0.0.1:8088`）。注意本地过黄口令是 **mir2666（8089）**，mod 默认 sf 端口是 **8088** —— 若服务器列表不走 8088 `/account` 而走 `/serverlist?password=`，需 `def.setSF('127.0.0.1', 8089, 'mir2666')`。

**e. config.zip 条目 `mir2.scenes.main.ui.lua` 后缀**
- 生产条目名带 `.lua`，require 找不到 → 已改名 `mir2.scenes.main.ui`（生产端通过热更落盘到文件系统加载，本机走 preload 需改名）。
