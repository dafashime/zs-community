# 列表界面展示（base / mod 两模式对比）

> 研究记录 · 2026-08-24
> 范围：**登录流程中的"服务器列表界面"**（loginScene → areas 层 → 选服 → 进入游戏 → login 层）
> 证据来源：base 明文源码、mod 字节码反汇编（luajit -bl）、运行时 `bzUIConfig` 配置 dump、素材包二进制扫描（ZC6 TOC / 字符串检索）、运行时 `res.getpack('rs'):getFileData()` 实测

---

## 1. 一句话结论

**base 模式：界面结构写死在代码里**（`mir2.scenes.login.areas.lua` 明文，UI 素材路径硬编码 `pic/login/*`，素材随客户端内置）。
**mod 模式：界面完全由配置驱动**（`mir2.bzUIConfig.loginArea` 一张表决定图片/位置/文案/动画/按钮，素材走 `pic/bzmir/newui/*`，且品牌素材由 APK/热更下发，通用包会缺）。**且 mod 配置层（bzconfig.zip / config.zip）是明文源码（§3.5）——界面与交互逻辑可直接读改，无加密。**

同样的"列表页"，base 是**老 UI**（战神经典 `pic/login/*`），mod 是**白筑新 UI**（`pic/bzmir/newui/*` + 动画主 logo + 配置化按钮）。

## 2. base 模式（明文源码）

### 2.1 模块与流程

```text
mir2.scenes.login.scene（登录场景）
  └─ onEnterTransitionFinish
       └─ showLayer("areas", true, handler(self, self.onRepServerList))
            └─ areas 层（mir2.scenes.login.areas，580 行明文）
                 ├─ ctor → self:requestServerList()
                 ├─ requestServerList:
                 │    POST http://def.loginCenterIP:def.loginCenterPort/account
                 │    解析 ret.serverlist.{verinfo,shopurl,servers,notice,last}
                 │    → g_data.login:setVerInfo/setShopUrl/setServerList/setNotice/setNetLastName
                 │    → self:loadServer()          ← 渲染列表
                 ├─ loadServer:  经典 UI（硬编码）
                 │    - 推荐区组按钮 res.gettex2("pic/login/b5.png")/b6.png
                 │    - 按 g_data.login.verinfo 逐版本追加区组按钮
                 │    - 上次服务器 pic/login/last.png
                 └─ selectServer(data): （点进某个服务器后）
                      - 返回按钮 pic/login/return.png
                      - 当前服务器面板 pic/login/curren_ser.png
                      - “进入游戏”按钮 pic/login/b7.png（按下 b8.png）
                      - enterGame():
                           def.setGameServer(data.zoneid, data.zoneip, data.area,
                                             clientVer, data.serverinfo,
                                             data.ConfigName, data.ConfigVer)
                           if data.ConfigName and data.ConfigVer → requestConfigZip()
                           else → self.serverlistCallback()
```

### 2.2 关键点

- **UI 素材路径全部硬编码**：`pic/login/b5.png`、`b6.png`、`b7.png`、`b8.png`、`return.png`、`curren_ser.png`、`last.png`
- **数据源**：`def.loginCenterIP:Port/account`（本地 = 127.0.0.1:8088 ✓）
- **账户登录界面**：`serverlistCallback → scene.onRepServerList() → def.lazyLoadConfig() + showLayer("login", def.loginCenterIP, def.loginCenterPort, loginEnd)`
- 全链路源码可改、可读（`client-other/res/rebuilt-src/mir2/mir2.scenes.login.{scene,areas,login,loginer}.lua`）

## 3. mod 模式（白筑，字节码还原）

### 3.1 模块与流程（反汇编还原）

```text
mir2.scenes.login.scene（编译版，与 base 同族）
  └─ onEnterTransitionFinish → showLayer("areas", ...)
       └─ areas 层（mir2.scenes.login.areas，4300 行反汇编）：
            ├─ ctor:
            │    self.scene / self.serverlistCallback
            │    self:requestServerList()
            │    self.reqTimes = 5        ← 请求重试上限
            │    self.curTimes = 0
            │    self.areaCfg = bzUIConfig.loginArea   ← ★ UI 布局唯一来源
            │    self.baseDir = "pic/bzmir/newui/login/"
            │    self.firstVisit = true
            ├─ requestServerList:
            │    POST http://%s:%s/account         （与 base 同一 URL，格式不变）
            │    → 写入 g_data.login.* → self:loadServer()
            ├─ getVerName(def.verid):
            │    优先 def.verid；否则 io.readfile(device.writablePath.."res/data/ver.zip") ← 数据版本包
            ├─ loadServer / selectServer：
            │    所有图片/位置/文案来自 self.areaCfg（loginArea）：
            │    return.png / changeAccount / 当前线路 / b9/b10 / new / heat_XXPA / 公告区 ...
            └─ 选服 → gotoscene "sfselect" 或进入 login 层
```

#### 3.5.5 方法论：mod 界面"重配置不改代码"

改 mod 列表界面 = 直接编辑命中表的明文模块，重打包进 cfg 层即可：
- 换主 logo / 按钮图 / 位置 / 文案 → 改 `mir2.bzUIConfig`（`loginArea` 及 `loginScene` 等）
- 改按钮行为 → 改 `mir2.scenes.main.console.btnCallbacks`（明文！）
- 改底部控件 → 改 `mir2.scenes.main.console.widget._def`
- 打包方式：与 modpatch 组装一致（cfg 层最后覆盖），或用 `LuaLoadChunksFromZIP` 单独下发 `config.zip`（生产机制）

## 5. 数据链路（两模式共用，mod 扩展）

```text
client ── POST http://127.0.0.1:8088/account ──→ 天龙启动器(8088)
   ← serverlist{verinfo, notice, servers:[{zoneip:127.0.0.1:7000, zonename:红月复古, ...}], last}
          │
          ├─（mod 扩展）res/data/ver.zip 是否存在 → def.verid
          ├─（mod 扩展）ConfigName/ConfigVer 存在 → GET /downloadconfig/ → config/<serverId>/<zoneid>/ZvzzMir2.zip
          │        └─ 解包 → config/serverlist.json（配置包内列表）等数据
          └─ 选服 → showLayer("login", bzmir.gateIP:Port, loginEnd)（mod）/ def.loginCenterIP:Port（base）
                   └─ login layer → loginer:login(id,psw) → GET /account?id&psw → code:0 + ticket
                            └─ connectServer → TCP 127.0.0.1:7000（LoginGate）
```

本地服务器事实（已实测）：
- `/account` GET（id/psw）返回 `code:0 + ticket + list{servers...}`；`des` 字段="您的账号已经被封!"（仅为文案，code=0 即成功）
- `/serverlist?password=mir2666` 仅 **openresty 8089** 提供（8088 天龙启动器**不提供**，会超时）—— mod 的 `def.sfAuthUrl` 需指向 `127.0.0.1:8089/mir2666`（main.lua 已自动 patch）

## 6. rs.zip 素材谱系（谁有什么，谁缺什么）

| 版本 | 大小 | 格式 | 是否含红月品牌素材(bzmir/newui) | 说明 |
|---|---|---|---|---|
| base/红月原包 `client-other/res/rs.zip` | 104,405,432B | ycPack `www.sdo.com.ZC6.` | ✅ | base 模式自带（也含 bzmir 目录！） |
| 红月 APK `assets/res/rs.zip` | 104,405,432B（同） | ycPack ZC6 | ✅ | **与 base 原包完全同尺寸（=同一份）** |
| 白筑 PC `BaiZhuClient/res/rs.zip` | 97.34MB | ycPack ZC6 | ❌ 缺 mainlogo/newui/logo | mod 生产通用包，品牌素材靠下发 |
| 白筑 dev `proj.android_no_anysdk/assets/res/rs.zip` | 131.7MB | **JSON 头新格式**（`{"m":"..."}`） | 部分（diynpc/logo，非 newui/logo） | 开发版/新格式素材封装 |
| www 热更 `assets/rs/` | 碎片 | 散文件 | ❌（仅 effect/tu、itemstyle/jianjia） | 生产热更只下特殊素材 |

**当前部署结论**：mod 模式使用 **红月包 rs.zip（=base 原包）** —— 素材最全，base/mod 两模式共用无冲突。
