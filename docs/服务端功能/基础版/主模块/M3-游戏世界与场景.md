# M3 游戏世界与场景

> 系列目录:[服务端功能文档目录](../目录.md)
> 子模块:[M3-S1 进入游戏与地图加载](../子模块/M3-S1-进入游戏与地图加载.md) · [M3-S2 对象感知与角色呈现](../子模块/M3-S2-对象感知与角色呈现.md) · [M3-S3 自身移动与位置交互](../子模块/M3-S3-自身移动与位置交互.md) · [M3-S4 场景切换与小退退出](../子模块/M3-S4-场景切换与小退退出.md)

M3 是最大最核心的主模块:覆盖玩家从选人确认进入游戏世界,到接收地图数据、看到周围对象(玩家/怪物/NPC/英雄/摆摊/地面物品/事件)、自己走跑转身开门、以及切图/小退/大退/掉线重连的**全部场景层协议**。入口分发器是 `mir2.scenes.main.ground.lua :: processMsg`(对象感知主入口)与 `mir2.scenes.main.scene.lua :: processMsg`(场景级控制消息),二者都在 main 场景 ctor 中通过 `net.add` 注册(`mir2.scenes.main.scene.lua :: ctor`)。

## 共享报文说明

以下记录被 M3 多个子模块引用,统一在此展开;线上编码一律小端、文本 GBK,对齐规则见[目录 §1.4](../目录.md)。

### TDefaultMessage 场景字段通用约定

绝大多数场景/对象消息沿用同一套字段习惯(`ground.lua` 各分支的读取方式即为权威):

| 字段 | 场景消息中的含义 |
|---|---|
| recog | **对象 id(roleid)**。注意:TDefaultMessage.recog 是 int32;对象唯一 id 在消息头里就是按整数传递的(`g_data.player:setRoleID(msg.recog)`,`ground.lua :: SM_LOGON 分支`)。只有个别扩展记录里的 ID 字段才用 8 字节 double 承载(如 TEventMessage2.id)。客户端全程以该数值为键索引 `map.heros/npcs/mons` 表 |
| param | 通常 = 格子 x;少数消息复用作计数/类型/颜色索引(逐条注明) |
| tag | 通常 = 格子 y;SHOWEVENT 中低 16 位为 x |
| series | 低字节(Lobyte)= 方向 0-7;高字节(Hibyte)在 SM_MAGICFIRE 中=effectID;也常复用作伤害飘字/类型(逐条注明) |

方向编码(`mir2.scenes.main.role.def.lua :: def.dir`,与 constants.txt DR_UP..DR_UPLEFT 一致):0=上,1=右上,2=右,3=右下,4=下,5=左下,6=左,7=左上。

### 对象特征与状态记录

**TFeature**(packed,10 字节)— 对象外观五元组:

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | short | race | 种族:**0/1/150→玩家/英雄类(hero)**,50→NPC,**其余→怪物(mon)**(`map.lua :: newRole`);12=护卫、24=超级护卫、98/99/153 为特殊隐藏种族 |
| 2 | byte | sex | 性别 0 男/1 女 |
| 3 | byte | hair | 发型索引(def.role.hair 按 sex 选 hair/hair2 图库 0-7) |
| 4 | short | weapon | 武器外观号(def.weapon 配置键) |
| 6 | short | dress | 衣服/怪身外观号(appr);NPC 用 <256,dress 70-75 为龙形 |
| 8 | short | riding | 坐骑号(客户端解析存储;rebuilt-src 内未见消费逻辑,(未核实)) |

32 位紧凑 outlook(旧式,出现在 TCharDesc.feature / SM_DIGUP.param1 / SM_FEATURECHANGED 退化分支)按 `def.role.makeTFeature` 拆解:`race=Byte(w)`,`weapon=Hibyte(w)`,`dress=Hiword(w)`,`hair=Byte(Hiword(w))`,`sex=Hibyte(Hiword(w))%2`。

**TAllBodyState**(16 字节)— 身体状态位图:`array 4 × int32`;位 n 置于 `state[n÷32]` 的第 `n%32` 位。状态位定义(`role.def.state.lua`):stStone=0 石化、stOpenHealth=1 显示血条、stAlwaysShowName=2、stHeroLongHit=3、stHidden=23 隐身(半透明 128)、stPoisonGreen/Red/Fuchsia/Stone=31/30/27/26 中毒变色、stMagicShield=20 魔法盾、csZaiMaShang=51/csHorseRider=52 骑乘相关等(全表 82 项见该文件)。

**TCharDesc**(20 字节,非 packed):`int feature(紧凑 outlook)` + `TAllBodyState status`。

**TNewCharDesc**(32 字节,非 packed):`uint outlook` + `TAllBodyState status`(16B)+ `TFeature feature`(10B);feature 从偏移 20 起,尾部补齐到 32。

**TNewStateRec**(41 字节,**packed**,后可跟名字尾巴):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | short | len | 包长声明(服务端自填,客户端按 bufLen 解析) |
| 2 | uint | outlook | 紧凑外观 |
| 6 | TAllBodyState | status | 16B 状态位图 |
| 22 | uint | nameClr | 名字色(调色板索引) |

### 名字与颜色约定

- 名字多行用 `\`(反斜杠)分隔(SM_USERNAME、SM_TURN 的 TNewStateRec 名字尾);`/` 分隔用于 SM_CHANGEMAP 等单串多段。
- 名字颜色 param 为**客户端内置 256 色调色板索引**(`def.colors.get(id)` → RGB;`mir2.def.colors.lua :: colors.get`)。`def.role.namecolors` 表存在但未被引用。
- race==98/99/153 的对象不显示名字(`role.info.lua :: isShowName`),服务端无需为其下发 SM_USERNAME。

### map.msgs 二级队列(时序合并语义)

`ground.processMsg` 不直接改对象,而是把多数对象消息压入 `map.msgs`(`map.lua :: addMsg`),由每帧 `map.update → processMsgs` 消费,**每帧最多消耗 10ms**(`socket.gettime()` 切片),空帧不保证即时处理:

- `remove=true` 的消息(HIDE/GHOST/DISAPPEAR)会**立即删除对象,并把该 roleid 尚未消费的排队消息整体清空**——服务端在同一批包里先发动作再发消失时,动作会被丢弃;
- 带 `effect`/`magic` 的消息同样进队列延迟执行;
- 例外:SM_ACT_GOOD/SM_ACT_FAIL 在 `net.handler` 直通分发(不进 net 队列也不进 map 队列),SM_STRUCK/SM_HEALTHSPELLCHANGED 对自己/英雄的血量更新也是同步执行的。

服务端重写时不必模仿切片,但必须知道:客户端的对象动作顺序 = 收包顺序(队列 FIFO),乱序下发会造成走位回拉/动作错乱。
