## 模块边界

本模块覆盖"玩家选定要玩的服"到"点击进入游戏离开选人场景"之间的全部服务端交互。

**范围内文件**(均在 `client/src/mir2/` 下):

| 文件 | 角色 |
|---|---|
| `mir2.scenes.sfselect.scene.lua` | 私服列表场景(纯 HTTP,不建 TCP) |
| `mir2.scenes.sfselect.sflist.lua` / `mir2.scenes.sfselect.sflistitem.lua` | 列表 UI 与排序/搜索(数据来自场景) |
| `mir2.scenes.select.scene.lua` | 选人主场景,`processMsg` 承接本模块几乎全部 SM 分支 |
| `mir2.data.select.lua` | `g_data.select`:角色列表解析与当前选中角色(`receiveChrs`) |
| `mir2.scenes.select.role.lua` | 选人界面人物模型渲染,**纯本地,无协议交互** |
| `mir2.single.net.lua`(仅 `net.match` 白名单与 `net.send`) | 选人场景的消息发送门控 |
| `mir2.def.init.lua`(仅 `def.setSF` / `def.setLoginCenter`) | 私服列表 URL 与登录中心地址配置 |

**相邻模块交接**(消息详表收录,细节归邻模块):

- 上游 M1:`mir2.scenes.login.scene.lua` 完成 HTTP `/account` 登录拿到 ticket 后,由 `SM_SERVER_LIST(4001)` 触发 `CM_SELECT_SERVER(4002)`,`SM_SELECT_SERVER(4002)` 给出网关 ip/port/sessionID 并 `net.connect`(`login.scene.lua :: processMsg`)。
- 下游 M3:`SM_SELCHR(4017)` `param=1` 后切往 `notice` 场景(跨服返回 `areaChange` 时直连 `main`),notice/main 场景继续握手与进图流程(`select.scene.lua :: processMsg`)。
- 旁路:`mir2.scenes.reconnect.scene.lua` / `mir2.scenes.notice.scene.lua` 各自维护一份与本模块重叠的 `SM_LOGIN`/`SM_LOGIN_AUTH`/`SM_CHR_LIST`/`SM_LOGIN_ALREADY_ONLINE` 处理(见 S2 §重连相关)。

**时序概览**:

```text
玩家                    客户端                              服务端
 │ sfselect 场景          │                                   │
 │────GET /serverlist?password=xxx (HTTP)────────────────────►│  M2-S1
 │◄───JSON {serverlist:{...}}─────────────────────────────────│
 │ 点某服 → 仅记 def.loginCenter*,切 login 场景               │
 │ login 场景(已有 ticket)                                    │
 │◄───SM_SERVER_LIST(4001)                                    │
 │────CM_SELECT_SERVER(4002) 区组名──────────────────────────►│
 │◄───SM_SELECT_SERVER(4002) ip/port/sessionID ───────────────│
 │ net.connect(ip,port,…,sessionID) 新 TCP + 握手             │
 │◄───SM_LOGIN(4003) ──► CM_LOGIN_AUTH(4004,ticket…)          │
 │◄───SM_LOGIN_AUTH(4004,param=1) TLoginIdResult(2)           │
 │◄───SM_CHR_LIST(4010) 角色数组(缓存)                        │
 │◄───SM_LOGIN_ALREADY_ONLINE(4041,recog≠1) 进选人信号        │
 │ 开门动画 → select 场景                                      │
 │ select 场景(match 门控开启)                                │
 │◄───SM_REQUIRE_MIBAO(4020)?→ CM_SUBMIT_MIBAO(4020)         │
 │────CM_NEWCHR/CM_DELCHR/CM_QUERYDELCHR/CM_RECOVERCHR ──────►│  M2-S2
 │◄───SM_NEWCHR/SM_DELCHR/SM_QUERYDELCHR/SM_RECOVERCHR        │
 │◄───SM_CHR_LIST(4010,recog=1) 每次 变动后刷新               │
 │────CM_SELCHR(4017,角色名)────────────────────────────────►│
 │◄───SM_SELCHR(4017,param=1)                                 │
 │ 切 notice/main 场景(M3)                                    │
```

## 子模块一览表

| 子模块 | 场景/载体 | 协议形态 | 核心交互 |
|---|---|---|---|
| M2-S1 私服列表 | `sfselect` 场景 | HTTP GET + JSON | 拉取区服列表,选择后写入 `def.loginCenter*`,无 TCP |

## 共享点

### 1. `net.match` 发送白名单(选人场景门控)

`mir2.single.net.lua :: net.match / net.setMatchMode / net.send`:

- select 场景 `ctor()` 调 `net.setMatchMode(true)`,`onExit()` 调 `net.setMatchMode(false)`(`select.scene.lua :: ctor/onExit`)。
- 门控开启期间,`net.send` 对不在白名单内的消息**本地直接丢弃**并打日志 `"The message being sent is not matched with the current scene"`,不出网(`net.lua :: net.send`,行 271-276)。
- 白名单恰好 9 条(`net.lua :: net.match`,行 267-269),数值已核实:

| 消息 | 值 |
|---|---|
| CM_SELCHR | 4017 |
| CM_DELCHR | 4013 |
| CM_QUERYDELCHR | 4014 |
| CM_SELCHR_EXIT | 4039 |
| CM_NEWCHR | 4012 |
| CM_RECOVERCHR | 4015 |
| CM_SUBMIT_MIBAO | 4020 |
| CM_RECONNECT | 4031 |
| CM_LOGIN_ALREADY_ONLINE | 4041 |

服务端实现要点:**在选人阶段只能期待这 9 种上行**;任何其他 CM 都不可能从 select 场景发出(即使客户端逻辑想发也会被丢弃)。

### 2. `g_data.select`(`mir2.data.select.lua`)

- `roles[]`:每次 `receiveChrs` 重建,元素 `{name, job(0战士/1法师/2道士), hair, level(合成后显示等级), sex(0男/1女)}`。
- `selectIndex`:由 `SM_CHR_LIST.tag + 1` 恢复(`receiveChrs` 行 42)。
- `getCurName()`:当前选中角色名,是 `CM_SELCHR` 的上行内容。
- 同时 `cache.saveLastPlayerName` 落盘最近角色名。

### 3. `g_data.login.roleInfo` 原始报文缓存

login/notice/select(reconnectState 分支)/reconnect 四处场景都会把最近一次 `SM_CHR_LIST` 的 `{msg,buf,bufLen}` 原样缓存进 `g_data.login.roleInfo`(如 `login.scene.lua:335`、`select.scene.lua:888`),供"强登/顶号"分支重新解析。服务端不必关心,但意味着 `SM_CHR_LIST` 可能被同一连接上先后到达的多场景消费。

### 4. `SM_RECONNECT` 常量覆盖陷阱

`mir2.def.globa1.lua` 中 `SM_RECONNECT` 被赋值两次:第 584 行 `= 4031`,第 991 行 `= 802`。Lua 全局变量顺序执行,**运行时 `SM_RECONNECT == 802`**。因此 select 场景 `processMsg` 里 `elseif SM_RECONNECT == ident`(`select.scene.lua:1011`)只拦截 ident=802 的下行;若服务端在选人阶段发 ident=4031,会落进 `else return false`(无人处理)。服务端请勿依赖 4031 作为下行"重连确认"。

### 5. 编码与 body 约定(继承 BRIEF §4/§7)

- 上行 `strs` 经 `u2a` 转 **GBK**,单条字符串 body = `0x00 前导 + GBK 字节串`(无长度前缀/结尾符,长度=dataLength-1);多条之间以 1 字节 `0x00` 分隔。
- 上行 record 型 body(CM_NEWCHR)= `0x00 前导 + 记录定长字节`;无 strs/data 的消息(CM_QUERYDELCHR/CM_SELCHR_EXIT)无 body(dataLen=0)。
- 下行记录型 body(SM_CHR_LIST/SM_SELECT_SERVER/SM_LOGIN_AUTH)从 buf 第 0 字节开始连续解码,**无前导填充**;唯一例外 SM_ACK_TRANSFER_AREA 明确校验 `bufLen - 1 == getRecordSize(...)`(见 S2)。
- HTTP(`/serverlist`)侧为 JSON,列表文案按 UTF-8 处理(见 S1),与 TCP 的 GBK 不同。

### 6. 断线与重连入口(select 场景)

`select.scene.lua :: socketEvent/onLoseConnect/reconectFuc`:

- 连接失败(status=2)/断开(status=3,且非主动返回 `returnBtn`)→ 弹窗"确定重连?":确定 → `net.connect(g_data.login.recIP, recPort, self, recSession)`(recIP/recPort/recSession 来自 login 阶段 `SM_SELECT_SERVER`);取消 → `common.gotoLogin{logout=true}`(= `net.close()` + 回 login,`common.lua:1346`)。
- 网络切换(WiFi/蜂窝)检测后同样走 `reconectFuc`。
- `SM_OUTOFCONNECTION(4018)` / `SM_OUTOFCONNECTION_KICKOUT(4040)` 也汇入 `reconectFuc`;`SM_SELCHR_ERR(4042)` 则强制回登录。

### 7. 等待语义

本模块所有场景代码均**未使用 `net.setWaitMsg`**(对 select/sfselect 相关文件 grep 零命中),消息分发全部经 `net.processLoop` 队列异步完成。因此服务端不回包不会阻塞客户端消息泵,但对应功能将停在当前状态(典型:不发 `SM_SELCHR` 玩家就永远留在选人界面;不发 `SM_CHR_LIST` 列表永不刷新)。
