## 模块边界

本模块覆盖"客户端启动 → HTTP 登录中心换取 ticket → 两段 TCP 连接完成选区与账号鉴权 → 公告确认"以及"任意阶段断线后的重连"的全部服务端交互。

**范围内文件**(均在 `client/src/` 下):

| 文件 | 角色 |
|---|---|
| `upt/main.lua` | 启动插桩层:**非游戏协议**。LUAMODE 分支(`mod` 加载 `mir2_modpatch.zip`,否则 `mir2.zip`)与 DEBUG 下 `cc.Director:getConsole():listenOnTCP(8844)` 调试控制台(`l` 执行 Lua / `say` 代发 CM_SAY)均为本地调试设施,不属于游戏协议;其中还对本机栈强制 `def.setSF("127.0.0.1", 8089, "mir2666")` 并在 `def.loginCenterIP/Port` 为 nil 时兜底 `127.0.0.1:8088`(见 M1-S1) |
| `mir2/mir2.def.init.lua` | `setLoginCenter`(HTTP 登录中心 URL/IP/端口)、`setSF`(`/serverlist?password=` URL,归 M2)、`setGameServer`(zoneid/ip/**areaID**/configName 等,areaID 是首连握手 dataIndex 的来源) |
| `mir2/mir2.scenes.login.areas.lua` | 区服列表层:`POST /account` 请求构造与 JSON 解析、`GET /downloadconfig/<configName>` 补丁下载、`parseJson("config/serverlist.json")` 本地兜底 |
| `mir2/mir2.scenes.login.loginer.lua` | 账号操作 HTTP 客户端(cc.XMLHttpRequest + network.createHTTPRequest):`/account?id=&psw=`、`/reg`、`/bind`、`/modifypsw`、`/paycb` |
| `mir2/mir2.scenes.login.login.lua` | 登录输入层:调 loginer 发请求,消费 `{code,des,…}` JSON,`code==0` 回调 `scene:loginEnd` |
| `mir2/mir2.scenes.login.door.lua` | 进入选人前的开门动画,纯本地,结束时 `net.remove(scene)` 切 select 场景,无协议 |
| `mir2/mir2.scenes.login.scene.lua` | **登录主场景**:TCP 连接入口 `connectServer`(`net.connect(IpResult, PortResult, self, nil, def.areaID)`,行 63)与 `processMsg` 全部分支 |
| `mir2/mir2.scenes.notice.scene.lua` | 公告场景:展示 `SM_SENDNOTICE`,断线时用 `recSession` 重拨(行 105) |
| `mir2/mir2.scenes.reconnect.scene.lua` | 断线重连场景:`CM_RECONNECT` 重连鉴权链(行 78 起重连参数) |

| `mir2/mir2.single.sdnaPassport.lua` | 盛大通行证 SDK 桥(appid="4"):仅经 luaoc/luaj 调原生 `sndaPassportSDK`,Lua 层无直连;本树中 `sdnaPassport.login/getTicket` 无调用点(休眠代码),涉网性只在原生 SDK 内部 |

**相邻模块交接**:

- 下游 M2:`mir2.scenes.sfselect.*`(私服列表 `GET /serverlist?password=`,响应结构与选择行为)**归 M2-S1**,此处仅列接口存在;`select` 场景的角色管理消息族归 M2-S2。交接点:login 场景收到 `SM_SELECT_SERVER(4002)` 完成第二次 `net.connect` 后,`SM_CHR_LIST/SM_LOGIN_ALREADY_ONLINE` 把玩家送进 select 场景。
- 下游 M3:notice 场景确认后进 main 场景,main 场景 ctor 发 `CM_LOGINNOTICEOK(1018)`(M1-S4 详述),之后的进图初始数据归 M3-S1。
- 旁路:main/select 场景各自持有一份与 M1-S4 重叠的 `SM_LOGIN/CM_RECONNECT/SM_LOGIN_ALREADY_ONLINE` 分支(重连复用),在 S4 汇总。

## 连接对象与 dataIndex 语义(专节)

整个登录接入期会出现**多条先后建立的 TCP 连接**,它们共用同一个 `net` 单例,差别只在握手帧(cmd=24)的 `dataIndex` 字段(`mir2.single.net.lua :: net.connect`,行 22-32:`areaid` 有值取 `areaid`,否则取 `sessionid`):

| 连接 | 发起位置 | 第 4/5 参 | dataIndex 语义 | 目标来源 |
|---|---|---|---|---|
| ① 首连(登录/选区网关) | `login.scene :: connectServer`(行 63) | `sessionid=nil, areaid=def.areaID` | **areaID**(大区编号) | `/account` 区服列表条目的 `zoneip`(可含 `:port` 后缀,默认 7000,行 51-61)+ 条目 `area` 字段(`def.setGameServer` 做 `tonumber(area) or 0`,`def.init.lua:74`) |
| ② 二连(选人/游戏网关) | `login.scene :: processMsg` SM_SELECT_SERVER 分支(行 246-248) | `sessionid=msg.recog` | **sessionID**(会话票据) | SM_SELECT_SERVER 的 `MakeLong(tag,series)` 拼出的 ip + `param` 端口 |
| ③ 断线重连(notice/reconnect/main/select 四处 reconectFuc) | 如 `reconnect.scene :: reconectFuc`(行 77-79)、`main.scene :: reconectFuc`(行 187-189) | `sessionid=g_data.login.recSession` | **sessionID** | `g_data.login.recIP/recPort`(②的产物) |
| ④ 跨服转移(select 场景,归 M2) | `select.scene :: processMsg` SM_ACK_TRANSFER_AREA 分支(行 973-975) | `sessionid=transferArea.param` | sessionID | TRetTransferAreaInfo 内嵌 ip/port |

关键结论(服务端必须实现的行为):

1. `dataIndex` **只**在握手帧(cmd=24)里承载 areaID/sessionID;此后每条业务帧(cmd=23)的 `dataIndex` 都是被 `net.newClientMsg` 覆盖的自增序号 `net.code`(初值 `random(65535)+1000`,每发一条 +1,`net.lua:120,394-404`);心跳帧(cmd=25)两者都不填(record 默认 0)。
2. 首连握手 dataIndex=areaID、二连/重连握手 dataIndex=sessionID——服务端要按连接序号/来源区分这两种语义:①上 areaID 用于定位大区,②③上 sessionID 用于找回 `SM_SELECT_SERVER.recog` 签发的会话。
3. notice 场景**不新建连接**(沿用②的连接),只有其断线重拨才落入③的语义(M1-S4)。
4. `net.connect` 开头先 `net.close()`(旧连接关闭、`net.code=1`、队列清空),所以每次重拨都是全新握手。
