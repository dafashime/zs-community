# M9-S2 英雄背包与装备

> 所属主模块:[M9-英雄系统](../主模块/M9-英雄系统.md)

## 功能概述

英雄拥有**两条与主角完全独立的容器**:英雄背包(`g_data.heroBag`)与英雄装备栏(`g_data.heroEquip`)。二者是主角容器的克隆镜像:

- `mir2.data.heroBag.lua` = `clone(bag)` 后置 `isHero=true`,仅重写 `getFreeCount`(容量上限改用 `g_data.hero.bagSize`,即服务端控制的英雄背包格数);
- `mir2.data.heroEquip.lua` = `clone(equip)` 后置 `isHero=true`,逻辑全继承自 `mir2.data.equip.lua`。

服务端交互分四组:

1. **初始下发**(召唤后):SM_HERO_BAGITEMS(背包全量)、SM_HERO_SENDUSEITEMS(装备栏全量)、SM_HERO_SENDMYMAGIC(技能全量);
2. **转移**:主角背包↔英雄背包双向移动(CM_HERO_TOHEROBAG/TOHUMBAG + SM_TO* 应答四件套);
3. **操作**:英雄穿戴/脱下/用药/丢弃(CM_HERO_TAKEON/TAKEOFF/EAT/DROPITEM)+ 对应 OK/FAIL 应答;英雄背包内堆叠(CM_PILEUPITEM series=1);
4. **增量维护**:增删物品、技能增删、技能经验、装备与背包物品耐久变更。

客户端采用**暂存-确认(pending-confirm)**模型:每个上行操作先把物品从容器中摘除放入临时槽,收到 OK 才落位、FAIL 才放回——因此每条 CM 必须有对应 SM 应答,详见各条目与"服务端实现要点"。

### CM_HERO_TOHEROBAG(1100)主角背包 → 英雄背包

- **时机**:①主角背包物品拖入英雄背包面板空格(panel.heroBag::putItem → putInItem);②拖到英雄头像上(panel.heroHead::putItem)。前置:`g_data.client.heroPutInItem` 为空(无未确认转移),否则忽略。
- **发送前本地动作**:立即从主角背包(`g_data.bag`)与 bag 面板删除该物品,存入 `g_data.client:setHeroPutInItem(data)` 暂存。
- **TDefaultMessage 用法**:`recog = makeIndex`(uint32)。
- **body(strs)**:1 个字节物品名 GBK(`net.send` strs 布局:前导 0x00 + 名字字节)。
- **应答**:
  - **SM_TOHEROBAG_OK(817)**:`MakeLong(msg.param, msg.tag)` = 服务端分配的**新 makeIndex**(uint32 拆双字)。客户端把暂存物品的 makeIndex 改为新值,从主角背包按新 makeIndex 兜底再删一次,加入 `g_data.heroBag` 并刷新 heroBag 面板,最后触发 `PileUpItem(true)` 自动整理(ui.lua 行 1868-1885)。
  - **SM_TOHEROBAG_FAIL(818)**:暂存物品放回主角背包与 bag 面板,清暂存(行 1886-1895)。

### CM_HERO_TOHUMBAG(1101)英雄背包 → 主角背包

- **时机**:英雄背包物品拖出/拖回主角背包(panel.heroBag::getBackItem)。暂存槽为 `g_data.client.heroGetBackItem`。
- **字段与 body**:与 CM_HERO_TOHEROBAG 完全一致(recog=makeIndex,strs=物品名)。
- **应答**:**SM_TOHUMBAG_OK(819)**(param/tag=新 makeIndex;从英雄背包删除、加入主角背包、`PileUpItem()` 整理主角背包)/**SM_TOHUMBAG_FAIL(820)**(放回英雄背包)(ui.lua 行 1896-1923)。

### CM_PILEUPITEM(1115,series=1)英雄背包内堆叠

- **时机**:①把可叠加物品拖到英雄背包同类物品上(panel.heroBag::putItem 行 258-264);②收到 SM_TOHEROBAG_OK 或 SM_HERO_ADDITEM 后的 `PileUpItem(true)` 自动整理(ui.lua 行 230-247,寻找第一对可堆叠物品发起)。
- **TDefaultMessage 用法**:`series = 1`(英雄;主角/仓库为 0,见主模块专节模式 B);`recog = 目标物品 makeIndex`;`param = Loword(源物品 makeIndex)`;`tag = Hiword(源物品 makeIndex)`。
- **body**:无。
- **客户端节流**:`g_data.player:setIsinPileUping(true)` 后,`bag:PileUpNext()` 直接返回 false(mir2.data.bag.lua 行 596-599),直到主角侧某处复位 inPileUping——即同一时刻只允许一个在途堆叠请求(该标志由主角背包流程复位,英雄链路的复位点未核实,建议服务端尽快应答以免整理停滞)。
- **应答**:本树没有监听专门的 PILEUPITEM 应答分支;结果通过 SM_HERO_DELITEM(906)/SM_HERO_ADDITEM(905)/SM_HERO_BAGITEMDURACHG(922)(叠加后数量=dura 变化)体现。**服务端必须用这些增量包反映堆叠结果**,否则客户端两侧物品显示不一致。

### CM_HERO_TAKEON(1102)英雄穿戴

- **时机**:①英雄背包物品拖到 heroEquip 面板指定格(panel.heroEquip::putItem → `item:use(putIdx)`);②双击英雄背包中的可穿戴物品(item::use);③快捷按钮(btnCallbacks::handle_custom,source=="heroBag")。
- **发送前本地动作**:`bagData:use("take", makeIndex, {where=where})` 把物品摘入 take 临时槽(带 5 秒重复限制,mir2.data.bag.lua 行 507-543);戒指/手镯左右位自动选择逻辑同主角(U_RINGL/U_RINGR 等,item.lua 行 418-449)。穿戴条件校验(等级/攻魔道需求/职业书)在 `canUseEquip` 内用 `g_data.hero` 数据完成,不满足则不发包。
- **TDefaultMessage 用法**:`recog = makeIndex`,`param = where`(装备位序号);strs=物品名。
- **应答**:
  - **SM_HERO_TAKEON_OK(907)**:`heroBag:useEnd("take", true)` 把物品写入 `g_data.heroEquip.items[param]`(注意 useEnd 写入的是发送时保存的 where,不是应答里的值——本条应答不携带 where),刷新 heroEquip 面板(ui.lua 行 1962-1967)。**与主角 SM_TAKEON_OK(615)不同:英雄版不解析 TFeature、不变更任何外观**。
  - **SM_HERO_TAKEON_FAIL(908)**:`useEnd("take", false)` 把物品放回 heroBag 面板(行 1968-1973)。
- **超时行为**:take 槽无超时回滚定时器;若服务端不应答,物品将滞留在暂存槽(面板不可见)。见实现要点第 1 条。

### CM_HERO_TAKEOFF(1103)英雄脱下

- **时机**:英雄装备栏物品拖出(item::takeOff,行 560-571)。
- **发送前本地动作**:`g_data.heroEquip:takeOff(makeIndex, {where=params.idx})` 摘入 takeOffing 临时槽(5 秒防重,mir2.data.equip.lua 行 122-137)。
- **TDefaultMessage 用法**:`recog = makeIndex`,`param = where`(原装备位);strs=物品名。
- **应答**:**SM_HERO_TAKEOFF_OK(909)** 清空 takeOffing(成功脱下,物品去向由后续 SM_HERO_ADDITEM/SM_HERO_BAGITEMS 表达)/**SM_HERO_TAKEOFF_FAIL(910)** 把物品放回原 where 位并刷新面板(ui.lua 行 1974-1981)。

### CM_HERO_EAT(1104)英雄使用消耗品

- **时机**:①双击英雄背包中的药/书等(item::use else 分支);②保护策略自动喝药(settingLogic.update 的 useItem(isHero=true) 与 missHp 的 isHero 分支,行 138-197、497-550);③快捷按钮 handle_custom。技能书(stdMode==4)会先弹确认框再发。
- **发送前本地动作**:`heroBag:use("eat", makeIndex)` 摘入 eat 临时槽。
- **TDefaultMessage 用法**:`recog = makeIndex`;param/tag/series 不设;strs=物品名。
- **应答**:**SM_HERO_EAT_OK(911)** 清 eat 槽(消耗完成)/**SM_HERO_EAT_FAIL(912)** 取回 makeIndex 放回英雄背包面板(ui.lua 行 1954-1961)。
- 学习技能成功的技能本体经 **SM_HERO_ADDMAGIC(913)** 下发(与主角同构)。

### CM_HERO_DROPITEM(1106)丢弃英雄物品

- **时机**:把英雄背包物品拖到地面(item::throw else 分支,行 646-661);"贵重物品"(def.items.filt 标记 isGood)先弹确认框。金币丢弃(isGold)仅存在于主角背包分支,英雄侧无此入口。
- **发送前本地动作**:`dropItem(cmd, g_data.heroBag)` → `heroBag:throw(makeIndex)` 摘入 throwing 槽。
- **TDefaultMessage 用法**:`recog = makeIndex`;strs=物品名。
- **应答**:**SM_HERO_DROPITEM_SUCCESS(920)** 清 throwing 槽 /**SM_HERO_DROPITEM_FAIL(921)** 物品放回英雄背包(ui.lua 行 1946-1953)。

### CM_HERO_SKILL_HOTKEY(1109)英雄技能开关

- **时机**:heroEquip 技能页点击技能行右侧开关按钮(panel.equip.lua 行 826-859;仅 `magicConfig.heroCannotClose` 为假的可关技能显示开关)。
- **TDefaultMessage 用法**:`recog = magicId`,`param = 新键值`。本树两态:255=停用(按钮选中态,key 显示灰色),0=启用。
- **body**:无。
- **应答**:无专门应答;本地直接更新 magicList 中该技能的 key。其他取值语义未核实。

### SM_HERO_BAGITEMS(902)英雄背包全量

- **时机**:召唤后初始化、背包结构变化时由服务端推送。
- **处理位置**:ui.lua 行 1804-1810。
- **TDefaultMessage 用法**:`series = 英雄背包格数(bagSize)`(`hero:setBagSize`)。
- **body**:连续的 TClientItem 直到 bufLen 耗尽(`heroBag:set`,mir2.data.bag.lua 行 15-35;数组顺序即格子顺序 1..N)。
- **body 记录:TClientItem**(packed=true,**无对齐填充**,固定部分 16B):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | uint | makeIndex | 实例唯一索引(服务端分配) |
| 4 | short | Index | 物品库 id |
| 6 | short | dura | 当前耐久;可叠加物=数量 |
| 8 | short | duraMax | 最大耐久/单叠上限 |
| 10 | short | KeyValueSize | 扩展键值对个数 |
| 12 | uint | _Reserved | 保留 |
| 16 | dynArray | extendFields | KeyValueSize × TClientKeyValue(short ValueType + short ValueNumber,每对 4B) |

  注:物品名/stdMode/need 等展示属性不在包内——客户端解码后以 `Index` 查本地物品库(`TClientItem.getStd/getVar`,globa2.lua 行 1821-1836)合并,extendField 可覆盖同名属性。TClientItem 完整语义见 [M5-S1](../子模块/M5-S1-背包与物品操作.md)。
- **错误分支**:无;bufLen 不是记录整数倍时的行为未核实(解码层按剩余长度截断)。

## 服务端实现要点

1. **暂存-确认模型要求每请求必答**:TOHEROBAG/TOHUMBAG/TAKEON/TAKEOFF/EAT/DROPITEM 六类操作都先把物品从可见容器摘进临时槽,只有收到 OK/FAIL 才落位或回滚。**任何一条不回包,对应物品就在客户端永久"消失"(直到重登或英雄收回)**。FAIL 必须原样带回能定位物品的字段(DROP 用 recog=makeIndex,其余依赖客户端暂存槽,但同样必须到达)。
2. **makeIndex 重映射约定**:TOHEROBAG_OK/TOHUMBAG_OK 用 `param`(低 16 位)+`tag`(高 16 位)= MakeLong 返回**新 makeIndex**——服务端在跨容器转移时重新编号物品实例是协议允许且被期待的路径;客户端此后一律使用新号。
3. **普通移动/换位不发报文**:英雄背包内的非堆叠拖拽只做本地换位(heroBag::putItem else 分支 + `changePos`),没有任何上行包;服务端的背包是"列表+数量"模型时无须关心客户端格子顺序。唯一需要处理的上行是堆叠(CM_PILEUPITEM series=1),其结果必须用 SM_HERO_DELITEM/SM_HERO_ADDITEM/SM_HERO_BAGITEMDURACHG 组合表达。
4. **背包格数由服务端控制**:初始格数走 SM_HERO_BAGITEMS.series,扩容走 SM_HERO_LEVELUP.tag;`heroBag:getFreeCount`、面板格子渲染都以 `g_data.hero.bagSize` 为准。转入判断(CM_HERO_TOHEROBAG 是否成功)在服务端做,客户端不做容量预检。
5. **英雄穿戴不变外观**:SM_HERO_TAKEON_OK 不携带 TFeature(主角版 615 携带),英雄武器/衣服外观变化只能通过重新下发含该英雄的呈现类报文(SM_HERO_LOGON/TNewCharDesc 族)表达;基础版树未见英雄外观增量更新通道(未核实服务端实际做法)。
6. **装备位 where 是稳定契约**:CM_HERO_TAKEON.param 与 SM_HERO_DURACHANGE.param 都用装备位序号(与主角 U_* 常量体系一致,见 M5-S2);TAKEON_OK 不回显 where,服务端若改写落位需另发 SM_HERO_SENDUSEITEMS 全量纠正,否则客户端显示错位。
7. **技能三包配套**:全量(904)、新增(913)、经验/升级(916 双形态)。停用/启用自动施放的持久化在服务端(CM_HERO_SKILL_HOTKEY,param=0/255),下次下发 904 时 key 字段应反映持久化结果。
8. **耐久包参数顺序**:919(param=位)与 922(recog=makeIndex)字段安排不同,duraMax 的 int32 拆法也不同(919 拆 tag/series,922 不拆)——编码时严格对照上表。
9. **自动整理联动**:SM_TOHEROBAG_OK 与 SM_HERO_ADDITEM 处理完都会触发一次 series=1 的 CM_PILEUPITEM;服务端应保证堆叠幂等并在完成后回推正确的数量(dura),否则自动整理循环可能停在中间状态(inPileUping 标志的复位点在主角侧流程,英雄链路依赖服务端快速应答,未核实长时间不应答的全部表现)。
10. **未核实项汇总**:CM_HERO_POWERUP 应答(M9-S1 已列);SM_HERO_SUBABILITY(901)/SM_HERO_DELITEMS(917)布局(本树无代码);CM_PILEUPITEM 是否存在专用 ACK;inPileUping 标志在英雄链路的确切复位时机;TAKEOFF_OK 之后服务端是否必然跟随 ADDITEM(客户端两种表现都兼容:OK 即清槽,物品出现依赖 ADDITEM 或下次 BAGITEMS)。
