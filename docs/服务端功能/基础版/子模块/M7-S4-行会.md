# M7-S4 行会

> 所属主模块:[M7-社交系统](../主模块/M7-社交系统.md)

## 功能概述

行会系统为**两级组织**:行会(GILD/guild,会长-副会长)下属若干战队(CORPS/clan,队长-副队长)。客户端 `panel.guild.lua`(约 4740 行)提供两大页面:

- **行会页(tguild)**:行会列表/查找、申请入会、我的行会(guildmain:公告/信息/退出)、成员列表(mem:职位任命/转让会长)、下属战队(claninfo)、入会审批(clanrecruit)、外交(diplomatic:联盟/宣战/关注/联盟申请四子页)、行会日志(log);
- **战队页(clan)**:战队列表/查找、申请入队、我的战队(clanmain:公告/退出)、成员管理(clanmem:称号/踢人/队长转让)、审批(clanjobs)、招募条件设置、战队日志(clanlog)。

所有操作均为"CM 请求 → 同号 SM 应答(param=0 成功 / 非 0 错误码)"模式;错误码统一经 `guild:showError` 映射文案(panel.guild.lua L4688–4738),这是服务端错误码的权威对照表。

## 详细报文说明

### 归属信息:TGuildDesc / TCorpsDesc

**TGuildDesc**(非 packed,对齐后 **56 字节**,globa2.lua L2557):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | ID(double) | guildID | 行会唯一 id,8B 小端 IEEE754 承载 |
| 8 | string[15] | gildName | 行会名,16B GBK |
| 24 | string[15] | presidentName | 会长名,16B |
| 40 | byte | corpsCount | 下属战队数 |
| 41 | byte | enableUnion | 允许联盟开关(1/0) |
| 42→44 | int(4 对齐填充) | playerCount | 总成员数(偏移 42 填充至 44) |
| 48 | int | onlineCount | 在线成员数 |
| — | 尾部补齐 | | 52→56(ID 的 8 字节对齐) |

`data.guild :: initGuildInfo`(L74):bufLen 必须恰等于 getRecordSize("TGuildDesc")(56);`msg.tag = allMemCount` 另存总人数;**bufLen==0 → 无行会**(guildInfo=nil)。注意 bufLen 既不是 0 也不是 56 时整包丢弃——服务端不要发中间状态。

**TCorpsDesc**(非 packed,**64 字节**,L2589):corpsID(ID,8)+corpsName16+gildName16+captainName16+memberCount(byte)+onlineCount(byte)=58 → 补齐 64。`initClanInfo`(L124)同构校验。

**SM_PLAYER_POSITION(4628)**:`g_data.guild.posInfo = msg.tag`;职位语义由 data.guild 判定函数定义(isPresident L92 等):

| tag | 职位 |
|---|---|
| 0 | 普通/无(ui.lua info 表首项为空串) |
| 1 | 副队长(战队)isViceLeader |
| 2 | 队长(战队)isLeader 含义之一 |
| 3 | 副会长 isVicePresident |
| 4 | 会长 isPresident |

UI 按职位显隐管理按钮(会长/副会长可审批、任命、宣战等)。

### 列表分页:CM_GILD_LIST(4562)/ CM_CORPS_LIST(4520)

上行(panel.guild.lua L148/473/499/519 等):

| 字段 | 值 |
|---|---|
| param | 页码(g_data.guild.page,翻页 ±1,首页重置为 0) |

### 公告:CM_GILD_NOTICE(4563)/ CM_CORPS_NOTICE(4539)

- 查询:`net.send({CM_GILD_NOTICE, tag=0})`(guildmain 子页 sendcmd 时,L1257)。应答:`param==0` 且 body=公告全文(GBK,net.str 读取;bufLen 可为 0 表示空公告,ui.lua L1224)。
- 保存:`tag=1`,strs={公告文本}(多行以 `\r\n` 连接,L1507–1518)。**ui.lua 中没有 SM_GILD_NOTICE 的 tag/param 其他分支**——保存成功的反馈机制未观察到(建议服务端保存后重新下发查询应答,(未核实))。
- 战队公告 CM_CORPS_NOTICE(4539)完全同构(ui.lua L1217,clanmain 子页)。

### 入会/入队申请流

**玩家侧**(panel.guild.lua L841–853、L628–636):

1. `CM_GILD_REQUEST_JOIN(4560)` body=TGuildID(**TGuildID=单 ID 记录,8B**);应答 param=0 成功(param≠0 showError)。
2. 已有挂起申请时按钮变为取消:`CM_GILD_CANCEL_JOIN(4627)` 无参(注意:战队版取消是 CM_CORPS_CANCEL_JOIN(4523) 带 corpsID,两者不对称)。
3. 服务端随后(或登录时)下发 `SM_SEND_APPLYGILD_ID(4615)`/`SM_SEND_APPLYCORPS_ID(4613)`,body=TGuildID:ID≠0 表示当前申请挂在哪个组织,客户端据此渲染按钮态(data.guild :: refushCurGuild/refushCurClan L229–267)。触发时机未观察到显式请求,**应为服务端在申请/取消后及登录时主动推送((未核实))**。

**会长侧审批**(clanrecruit 页):

1. `CM_GILD_QUERY_REQUEST_JOIN_LIST(4570)`(tag=30,series=0)拉取申请列表;
2. 应答 param=0,**tag=条数**,body=n 条 **TGuildRequestJoinDesc**(非 packed,**56 字节**,globa2.lua L2815):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | ID | corpsID | 申请者所在战队 id(散人申请时服务端语义(未核实)) |
| 8 | ID | ID | 申请者角色 id |
| 16 | string[15] | corpsName | 战队名,16B |
| 32 | string[15] | captainName | 队长名,16B |
| 48 | byte | memberCount | 人数 |
| — | 补齐 | | 49→56 |

3. 批准:`CM_GILD_ACCEPT_REQUEST(4611) recog=1`,body=TGuildID(申请者 ID);拒绝:`CM_GILD_REFUSE_REQUEST(4572) recog=1` 同构。
4. 应答 param=0 后客户端按 recog 自动重查:recog=1 → 重发 CM_GILD_QUERY_REQUEST_JOIN_LIST;recog=2 → 重发 CM_GILD_QUERY_REQUEST_UNION_LIST(ui.lua L1559/L1579)——**同一对报文复用为联盟申请审批**(见外交节)。

**被拒通知 SM_SEND_REFUSE_REQUEST(4612)**(ui.lua L1734):body=**TRefuseRequestType**(17 字节:byte type + string[15] name)。type 语义(ui.lua L1742):3="「名字」拒绝了您的联盟请求!";1="您加入战队 名字 的请求已经被拒绝!";其他值(2)="您加入行会 名字 的请求已经被拒绝!"。提示 tip 会连打三次(客户端 quirk)。

## def.guild.lua 常量与报文字段的对应

`mir2/mir2.def.guild.lua` 返回一张纯常量表:

- **RANK_***(`RANK_LEADER=1`、`RANK_NORMEM=99`、`RANK_MAX_NUM=20`、`RANK_NAME_LEN=15`)与 `GUILD_NAME_LEN=31`、`CHAR_NAME_LEN=15`、`GTEAM_NAME_LEN=31`、`GUSER_REMARK_LEN=15`:长度/容量约束。其中 GUILD_NAME_LEN=31 与 TGuildMember/TGuildDesc 内 15(+1=16B)的名字字段不一致——前者是白猪扩展体系的配置,基础版报文以 record 定义为准。
- **职位与报文 position/rank 字段**:运行时真正使用的职位值来自 `SM_PLAYER_POSITION.tag` 与 `TGuildMember.position`(0无/1副队长/2队长/3副会长/4会长,ui.lua L1264 info 表);def.guild.RANK_LEADER=1 只与"队长=1"巧合一致,**并非同一套表的完整映射**。
- **guildPrivilege/guildActiveRight/guildFlag**(`gpOwner=1…gpFirstOwner=5`、`garChgNotice=0…garUseWeapon=11`、`tfAllowAlly=1`):被 `data.player.lua :: setGuildRight/setGuildInfo` 用于解析 `conferRight` 位域权限。但基础版 `TGuildDesc` 并无 conferRight/guildFlag 字段,且 setGuildInfo 在本树无调用点——**该组常量属白猪系残留死代码,基础版服务端无需实现**。
- **cmSubProto/smSubProto**(cmGuild_* 0–63/smGuild_* 0–43:ApplyJoin、AgreeJoin、SetRank、GetWeaponList、BuildWeaponFactory 等白猪扩展行会子协议):全树仅此一处定义,**无任何引用**。若未来移植白猪行会功能(武器工厂/职位编辑器/捐献等),这套子协议号是唯一的现成线索;基础版文档不将其视为现行协议。

> 结论:任务清单中提到的"行会捐献(DonateItem=49)、行会仓库、行会地图、武器工厂"等功能只存在于 def.guild 的预留子协议表内,**基础版客户端没有对应的现行报文实现**,服务端无需在本阶段支持。

## 服务端实现要点

1. **同号应答 + param 错误码**是铁律;唯一例外:宣战(CM 4585 → SM 4579)、关注添加(CM 4586 → SM 4576)、入会失败通知(SM 4434 类似物为 SM_SEND_REFUSE_REQUEST 4612)。实现 dispatcher 时按方向区分同号消息。
2. 条数字段不统一,极易写错:**GILD/CORPS_LIST 用 series,GILDMEMBER/CORPSMEMBER/申请列表/联盟/关注列表用 tag,附近队伍与好友列表用 param,SM_GROUPMEMBERS 用 recog**。逐条对照本文表格。
3. record 尺寸全部按 BRIEF §6 对齐规则计算并已在文中给出精确值(56/64/54/36/48/32/56(TGuildRequestJoinDesc)/24/32/64/8/17/60/31(packed));packed 的 TGuildMember 是唯一不填充的成员记录。
4. 审批类操作成功后客户端会**自动重查**相关列表(ui.lua 各成功分支),服务端只需保证查询接口幂等;不必额外推送。
5. 职位权限校验(谁能审批/任命/宣战/解散)完全在服务端:客户端仅按 SM_PLAYER_POSITION.tag 显隐按钮,越权直接回 555(无操作权限)即可。
6. 会长/队长退出的级联(带整队退会)、行会战/攻城区禁退(28/29)、安全区禁退(37/38)是状态机关键分支。
7. 所有名字/公告/称号/日志文本线上 GBK;string[N] 类型首字节为长度(N+1 占位)。
