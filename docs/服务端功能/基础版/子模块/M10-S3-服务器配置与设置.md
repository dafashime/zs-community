# M10-S3 服务器配置与设置

> 所属主模块:[M10-辅助系统](../主模块/M10-辅助系统.md)

## 功能概述

回答两个关键问题:

1. **`g_data.serverConfig` 从哪来?** —— 结论(已核实):在本基础版源码树中,它**没有任何网络写入点**。`mir2.data.serverConfig.lua` 定义了 `set(msg, body)`(从 `Lobyte(msg.param)` 取 deathColor),但全树 grep `serverConfig:set`/`SM_GSCONFIG` 均无调用点;`allowMaxLevel` 恒为构造默认值 **999**,仅被 `ui.lua` L265 在升级时用来判断"等级已达上限,不再获取经验"。`SM_GSCONFIG(2843)` 常量存在却无任何处理分支。也不存在 HTTP downloadconfig 路径(M1-S1 的 HTTP 仅覆盖账号/区服)。因此服务端若想下发该配置,需要自行启用 SM_GSCONFIG 或等价推送——但当前客户端不会消费(见要点)。
2. **setting 面板哪些项会触发服务器保存?** —— 结论:本地设置(`g_data.setting`,含基础/保护/药品/职业/显示/CPU/聊天/拾取过滤等)全部经 `cache.saveSetting(角色名, 分组)` 存本地,唯一例外是英雄"躲闪血量"输入框会即时上报 `CM_COMMON_INFORMATION(1099)`。不存在 CM_SETSERVERCONFIG 类报文。

另外,设置驱动的自动化逻辑(自动吃药/自动 unpack/自动施法/英雄保命)触发的是**既有玩法报文**(CM_EAT/CM_HERO_EAT/CM_SPELL/CM_HERO_LOGOUT),本文只登记入口,字段细节归对应模块。

## 详细报文说明

### CM_COMMON_INFORMATION(1099) —— 英雄躲闪血量上报

发出(`panel.setting.lua` L1039-1050,`addHeroProtected` 输入框 stop_call):

```lua
net.send({ CM_COMMON_INFORMATION, param = 2, recog = data.value })
```

| TDefaultMessage 字段 | 用法 |
|---|---|
| recog | 阈值数值(输入框数字,钳制在 [40, 英雄当前 maxHP]) |
| param | 固定 2(本面板内唯一取值) |
| tag / series | 未用 |
| body | 无(dataLen=0) |

期望应答:本树对 SM_COMMON_INFORMATION 只实现了 `param==6`(安全区进出通知:`tag=1` 进入/"离开安全区!"提示,`tag=0` 离开,`ground.lua` L638)。param=2 的回执无处理分支——成功即沉默,失败行为未核实。1099 号下其他 param 取值本树未使用(未核实服务端是否定义了更多子命令)。

### serverConfig 的字段与更新时机(现状核实)

| 字段 | 当前值 | 来源 | 更新时机 |
|---|---|---|---|
| deathColor | 0 | 构造默认 | 无(死代码:`set()` 读 `Lobyte(msg.param)` 并 clamp 到 ≤8,但无人调用) |
| allowMaxLevel | 999 | 构造默认 | 无网络更新;升级流程只读 |

若服务端按旧版行为下发 SM_GSCONFIG(2843),本树客户端不解析、不生效;要激活此通道需补 UI/数据层处理(超出本文档范围)。

### 设置自动化触发的既有玩法报文(登记入口)

以下均由 `settingLogic.update(dt)`(每帧)或 `settingLogic.missHp`(HP 变动回调)在满足阈值/间隔后发出,消息本身归物品/战斗模块:

| 触发设置项 | 发送 | 位置 |
|---|---|---|
| protected.role/hero .hp/.mp、drugs 各药线 | CM_EAT(1006)/CM_HERO_EAT(1104):`recog=makeIndex`,body=物品名 | settingLogic L182/L331/L533 |
| base.autoUnpack 各包线 | 同上(L331) | 包裹余量 ≥5 格且对应散药 ≤min 时吃包 |
| job.autoFire / autoSword / autoWide(战士) | CM_SPELL(3017):recog=target,param=player.x,tag=player.y,series=magicId | L409/L424/L473 |
| protected.hero.hp/mp 的 uses=="小退" 等价路径 | (本地 smallExit,不发) | — |
| hero miss/hp/mp 保命(heroExit) | CM_HERO_LOGOUT(1051):recog=英雄 roleid | L581 |

注意:这些发送不受 select 场景 match 门控影响(均在 main 场景);限速由各设置项的 `space`(ms)+`lastTime` 本地控制。

## 服务端实现要点

1. **不要指望客户端上报整套设置**:除 CM_COMMON_INFORMATION(1099,param=2)外没有"保存设置"协议;玩家设置只存在于客户端本地缓存,换设备即丢。
2. 服务端需要持久化的只有英雄躲闪血量阈值(1099/param=2),应按角色存储并在登录后恢复生效(英雄 AI 判定在服务端侧的场合)。
3. SM_COMMON_INFORMATION(2821) 是服务端→客户端的单向信息通道,param 子命令化:param=6 必须实现(安全区进出直接影响客户端提示与部分 UI);其余子命令按需扩展。
4. allowMaxLevel 封顶提示完全依赖客户端本地常量 999:若服务端实际等级上限不是 999,升级经验截断逻辑必须在服务端实现,不能依赖客户端提示。
5. deathColor(死亡名颜色?)在本树无生效路径,可忽略。
