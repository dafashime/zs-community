# M7-S3 组队

> 所属主模块:[M7-社交系统](../主模块/M7-社交系统.md)

## 功能概述

组队为无行会依赖的临时小队:队长邀请建组(CM_CREATEGROUP)、追加成员(CM_ADDGROUPMEMBER)、踢人/退队(CM_DELGROUPMEMBER)、玩家主动申请入队(CM_JOINGROUP)。成员列表以 **SM_GROUPMEMBERS 全量下推**为唯一权威数据源(客户端不做增量合并,每次整表替换);另有附近队伍查询、允许组队开关、组队频道聊天(聊天格式见 M7-S1)。

## 详细报文说明

### CM_GROUPMODE(1019) — 允许组队开关

来源:`panel.group.lua :: ctor` 开关回调(L59–69)。发送 `param = 当前选中 ? 0 : 1`(即点成"勾选"=1 允许,"取消"=0 拒绝),无 body。已有队伍(#groupMembers>1)时客户端拒绝切换。

应答 **SM_GROUPMODECHANGED(659)**:`g_data.player:setAllowGroup(msg.param > 0)`——param>0 即处于允许状态。建议服务端在登录时也下发一次当前状态。

### 邀请建组:CM_CREATEGROUP(1020)

来源:`panel.group.lua` L305(输入框添加)、L349(好友页邀请)、L620(右键菜单)、panel.relation.lua L1429、panel.guild.lua L4613。**客户端按 `#g_data.player.groupMembers == 0` 二选一**:空表发 CM_CREATEGROUP,否则发 CM_ADDGROUPMEMBER。

body:strs={目标名}(单条 GBK 名字)。

应答:

- **SM_CREATEGROUP_OK(660)**:无字段消费;客户端置 allowGroup=true。随后服务端应向全体队员下发 SM_GROUPMEMBERS 全量列表。
- **SM_CREATEGROUP_FAIL(661)**:`recog` 分支(ui.lua L1088):

| recog | 客户端文案(即服务端语义) |
|---|---|
| -1 | 发起人已经创建队伍 |
| -2 | 玩家名错误或不在线 |
| -6 | 发起人不允许创建队伍 |
| -3 | 该玩家已有队伍 |
| -4 | 接受人不允许组队 |
| -10 | 不可邀请自己组队 |
| 其他 | "未知错误" |

### 添加成员:CM_ADDGROUPMEMBER(1021)

同上触发点;body=strs={目标名}。应答:

- **SM_GROUPADDMEM_OK(662)**:仅打印 bufLen,不读内容(ui.lua L1108);成员变化靠后续 SM_GROUPMEMBERS。
- **SM_GROUPADDMEM_FAIL(664)**:recog 分支(ui.lua L1111):-1 发起人不是队长,-2 玩家名错误或不在线,-3 该玩家已有队伍,-4 接受人不允许组队,-5 队伍已满,-10 不可邀请自己组队。

### 踢人/退队:CM_DELGROUPMEMBER(1022)

来源:`panel.group.lua` L269(**退队**:确认框后发送 strs={自己名字})与 L403(踢出选中成员 strs={对方名});仅队长可踢(本地校验 isTeamLeader)。

应答:

- **SM_GROUPDELMEM_OK(663)**:body=被删的名字(net.str);客户端从本地表中移除并刷新。若被删的是自己,等价于离队。
- **SM_GROUPDELMEM_FAIL(665)**:recog=-1 队员不能删除其他成员,-2 输入的人物名称不正确,-3 删除目标不是队伍成员。

### 申请入队:CM_JOINGROUP(4413) ⇄ SM_JOINGROUP_FAIL(4413)

来源:"附近队伍"页"申请入队"(panel.group.lua L370)与右键菜单(L632)、panel.relation.lua L1437。body=strs={队长名}。

失败应答**与请求同号**(4413,S→C 方向):recog=-1 玩家名错误或不在线,-2 玩家队伍不存在,-3 不在允许组队状态,-4 队伍人数已满,-10 不可邀请自己组队(ui.lua L1070)。成功无专用应答——服务端把申请者入队后直接对全队下发 SM_GROUPMEMBERS 即可(客户端 UI 提示"申请加入 XX 的队伍"是本地即时打的)。

### 成员列表:CM_QUERY_GROUP_MEMBERS(4416) → SM_GROUPMEMBERS(667)

上行无参("我的队伍"页切换时发送,panel.group.lua L201)。

下行 **SM_GROUPMEMBERS(667)** 为本系统核心报文(`ui.lua` L1159):

- **recog = 成员人数 n**(注意不是 param!校验式 `msg.recog * getRecordSize("TClientGroupMemInfo") == bufLen`,data.player.lua L351);
- body = n 条连续 **TClientGroupMemInfo**(非 packed,单条对齐后 **54 字节**,globa2.lua 定义见 records.txt):

TClientGroupMemInfo 字段展开(尺寸计算:16+2+1+1+32+1=53,尾部补齐至 short 对齐 → **54**):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | string[15] | name | 名字,16B(N+1,GBK) |
| 16 | short | level | 等级 |
| 18 | byte | job | 职业 |
| 19 | byte | isonline | 1 在线 / 0 离线 |
| 20 | string[31] | guildName | 行会名,**32B**(N+1) |
| 52 | byte | isCaptain | 1=队长 |
| — | (填充 1B) | | 总长 53→54 |

客户端行为:整表替换 `groupMembers`;遍历找 `name==自己 && isCaptain==1` 则置 isTeamLeader=true(ui.lua L1164–1170)。**任何队伍变动(建组/加人/踢人/退队/解散/上线离线刷新)都应重发此报文给全队**。

**SM_GROUPCANCEL(666)** 解散通知:无字段消费,清空成员表并置非队长(ui.lua L1151)。建议服务端在队伍只剩 1 人或队长解散时下发。

### 附近队伍:CM_QUERY_NEARBYGROUP(4415) ⇄ 同号下行

上行无参(panel.group.lua L208,"附近队伍"页切换时)。

下行:`param`=条数 n,body=n 条 **TClientNearbyGroupInfo**(非 packed,单条 **36 字节**):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | string[15] | name | 队长名字,16B |
| 16 | short | level | 队长等级 |
| 18 | byte | job | (见下方 quirk) |
| 19 | string[15] | guildName | 队长行会名,16B |
| — | (填充) | | 35→36,补齐 short 对齐 |

⚠️ **客户端显示 quirk**:附近队伍页的列头是"队长名/等级/**人数**/队长行会",但取值代码为 `label = page=="group" and v:get("job") or ...`(panel.group.lua L464)——**人数列直接渲染 job 字段**。服务端若想让该页显示正确的队伍人数,必须在 TClientNearbyGroupInfo.job 中填队伍人数(职业信息在此页面不可见);若填职业,页面会显示数字职业码。此处按代码事实记录。

### 节流

`panel.group.lua :: allowRequest`(L529–531):距上次 `g_data.client:setLastTime("group")` 超过 **5 秒**才放行(基于 socket.gettime)。每个组队操作发送前都会 `setLastTime("group", true)` 打点,每类 SM 应答到达也打点(ui.lua 各分支 L1087/1109/1132/1150 等)。注:该 5 秒闸门函数在本树中已定义但未接入发送路径(防御性保留),实际生效的是各按钮的 lastTime 打点与 UI 校验;服务端仍应对 CREATEGROUP/ADDGROUPMEMBER/JOINGROUP 做自身频率限制。

## 服务端实现要点

1. **SM_GROUPMEMBERS 是唯一事实源**:recog 放人数(易错点:不是 param),body 严格 54B×n 对齐布局;任何变动全量重发,不要发明增量协议。
2. 邀请制与申请制并存:CREATEGROUP/ADDGROUPMEMBER 是队长侧动作,JOINGROUP 是玩家侧动作;两者最终都收敛为"入队 + 全量列表广播"。接受方"不允许组队"(开关关闭)返回 -4/-3。
3. 队伍上限的经典 Mir2 值为 4 人(对应 -5/-4 满员分支),具体由服务端配置;客户端无上限常量。
4. 退队 = DELGROUPMEMBER(自己名);服务端需区分"队长退出"(可解散或转让,经典实现要求先转让,见 M7-S4 showError 39 的同类语义)并在解散时下发 SM_GROUPCANCEL。
5. 附近队伍查询应以服务端 AOI 视野为准(客户端不发参数,直接按地图范围扫描周围队长)。
