# M4-S2 技能魔法

> 所属主模块:[M4-战斗属性与技能](../主模块/M4-战斗属性与技能.md)

## 功能概述

玩家施放魔法:客户端经本地节流后发送 CM_SPELL;服务端校验 MP/冷却/状态后,向全图广播 SM_SPELL(起手)与 SM_MAGICFIRE(命中/生效),并向施法者回执以解除其下一次施法的本地节流。技能数据(列表、等级、练度、快捷键)由 SM_SENDMYMAGIC / SM_ADDMAGIC / SM_MAGIC_LVEXP / CM_MAGICKEYCHANGE 维护。

## 详细报文说明

### CM_SPELL(3017)——施法上行

- **TDefaultMessage 字段**(无 body):

| 字段 | 含义 | 来源 |
|---|---|---|
| recog | 目标 roleid;可省略(=0) | 锁定类技能取 `controller.lock.target.skill`;magicId==2 时取点击处角色的 id(`findRoelWithPos`) |
| param | 目标点 x(地图格坐标) | |
| tag | 目标点 y | |
| series | magicId(技能 id) | `data:get("magicId")` |

- **主要发送点与字段差异**:
  - `controller:useMagic(x, y, dir, data)`(`controller.lua` 行 590):完整四字段,recog=锁定目标或点击处角色。
  - `btnCallbacks:handle_skill` effectType==0 分支(行 1031):只填 param/tag/series,**recog 不发(=0)**;magicId==27(野蛮冲撞类)时特殊编码 `x=player.dir, y=0`。另有本地限速:magicId==26 需过 `checkLastTime("fire",10)`、27 过 `checkLastTime("rush",3.1)`、其余过 `checkLastTime("spell",0.5)`。
  - `settingLogic.update` 自动技能分支(行 409/424/473):战士 job==0 且开启自动烈火(26)/自动剑气(58)/自动半月(25)时,以 `recog=锁定攻击目标id, param/tag=玩家当前坐标` 发送。
- **发送前的本地门禁(影响时序,服务端应预期这些节奏)**:
  1. `player:canNextSpell(magicId)`(`role.hero.lua` 行 168):距上次施法须超过 `def.role.speed.spell(0.4s) + delayTime/1000`,其中 delayTime 来自该技能 TNewClientMagic.delayTime(**服务端下发的数值直接决定客户端二次施法间隔**)。
  2. `checkLastTime("spell",2)`(controller 路径,约 2 秒硬节流);MP < needMp 时直接拦截并提示"没有足够的魔法点数!!"(**不发包**)。
  3. magicId∈{13,14,15,16,17,18,19,28,30,48} 需通过 `common.checkAmulet`(护身符/毒药检查,不足时自动尝试装备)。
  4. magicId==36(无极真气?按 helperScript 名表推断,未核实)走独立的 `checkLastTime("wuji",20)` 节流。
  5. **重要**:上述 "spell" 节流计时器要等收到**自己的 SM_MAGICFIRE**(ground.lua 行 470:`setLastTime("spell", true)`)才被确认重置——服务端若不回 SM_MAGICFIRE,客户端会持续处于节流状态。

### CM_MAGICKEYCHANGE(1008)——技能快捷键上报

- 发送点:`mir2.data.hotKey.lua :: setMagicHotKey`(行 211-248)。面板(magicKeySetting)本身纯 UI;真正发包在此:
  1. 清除旧绑定:对所有原先绑定了同一 magicId 的键发 `{recog=magicId, param=0}`;
  2. 设置新键:`{recog=magicId, param=keyCode}`。
- **keyCode 编码**:键位 id 6..13 → `'1'..'9'`(49..57);id 18..25 → `'A'..'H'`(65..72)(行 233-237)。param 直接存 ASCII 码。
- 反向证据:TNewClientMagic.key 字段(见下)在 WIN32 下会被 `hotKey:loadMagicHotKey` 用同样映射还原——即 **key 字段与 CM_MAGICKEYCHANGE.param 使用同一套 ASCII 键码**,服务端应持久化该值并在下次 SM_SENDMYMAGIC 中回填。

### SM_SENDMYMAGIC(211)——全量技能列表

- 分发:`ui.lua :: processMsg` 行 316 → `mir2.data.player.lua :: setMagicList`(行 239)。
- **body**:循环 `while getRecordSize("TNewClientMagic") <= bufLen` 连续解包 N 条 `TNewClientMagic`(**packed=true,每条 46 字节**,无对齐填充):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | char*14 | magicName | 技能名,GBK,15 字节区(14+长度字节由 readChars 消化) |
| 15 | byte | magicType | 技能类型 |
| 16 | byte | effectType | 0=直接施放类(handle_skill 直发 CM_SPELL),非 0=需选目标/区域 |
| 17 | byte | effect | 特效 id(effect-1 用于动画) |
| 18 | short | magicId | 技能 id(全局唯一键) |
| 20 | short | level | 当前等级 |
| 22 | short | key | 快捷键 ASCII('1'..'9'=49..57,'A'..'H'=65..72,0=未绑) |
| 24 | short | needMp | 每次消耗 MP |
| 26 | short | spellTick | (施法间隔相关,客户端未直接使用,未核实) |
| 28 | short | nextNeedLv | 升下一级所需人物等级 |
| 30 | int | coldTick | 冷却 tick |
| 34 | int | curTrain | 当前练度 |
| 38 | int | maxTrain | 本级练度上限 |
| 42 | int | delayTime | 二次施法延迟(ms),参与 canNextSpell 计算 |

- 客户端行为:整表覆盖 `g_data.player.magicList`;WIN32 下用 key 字段恢复快捷键绑定。
- 应答:无错误分支;bufLen 不是 46 的整数倍时尾部余数被忽略。

### SM_ADDMAGIC(210)——学会新技能

- 分发:行 323 → `player:addMagic`(行 260):`getRecordSize("TNewClientMagic") <= bufLen` 时解出**单条** TNewClientMagic 追加入列表。
- 无 FAIL 变体(未核实服务端学习失败时的通知方式,可能走 SM_SYSMESSAGE)。

### SM_DELMAGIC(212)——删除技能(客户端无处理)

- 常量存在(globa1.lua 行 817),但 usage.json 核实除定义外无任何引用。服务端如需收回技能,本树客户端不会响应(未核实服务端是否实际使用)。

### SM_MAGIC_LVEXP(640)——技能练度/升级

- 分发:行 335 → `mir2.data.player.lua :: setMagicExp(msg, buf, bufLen)`(行 269)。先按 `msg.recog=magicId` 在 magicList 中定位技能,找不到则丢弃。
- **双格式(按 bufLen 区分)**:
  - **短格式**(`bufLen < 16`,即不足一条 TClientSkillExp):
    | 字段 | 含义 |
    |---|---|
    | msg.recog | magicId |
    | msg.param | 新等级 level |
    | MakeLong(tag, series) | curTrain(当前练度,param=低16位) |
    | body 前 4 字节(仅当 bufLen==4) | maxTrain(net.int) |
  - **记录格式**(`bufLen >= 16`):body=`TClientSkillExp`(16B,自然对齐):
    | 偏移 | 类型 | 字段 | 落点 |
    |---|---|---|---|
    | 0 | short | skillID | (不校验与 recog 一致) |
    | 2 | byte | isSuper | 未使用 |
    | 3 | byte | _reserved | 未使用 |
    | 4 | uint | curExp | → curTrain |
    | 8 | uint | nextExp | → maxTrain |
    | 12 | int | skillLv | → level |
- 应答:无错误分支。

### SM_SPELL(17)——他人施法广播(下行)

- 分发:`mir2.scenes.main.ground.lua :: processMsg` 行 424。
- **TDefaultMessage**:recog=施法者 roleid;param=targetX;tag=targetY;series=effectID+1(客户端 `Byte(series-1)` 还原)。
- **body(可选,逐字段顺序读)**:`bufLen>4` 读 int magicId;再 `bufLen>4` 读 int magicLevel。即 0/4/8 字节三种形态均合法。
- 呈现(飞行特效)归 M3;此处注意:**没有"自己施法起手"的独立回执**——自己的起手由客户端本地预测播放,成功与否以下条 SM_MAGICFIRE 为准。

### SM_MAGICFIRE(638)——施法生效回执/广播

- 分发:`ground.lua` 行 448。组装 `{recog, Lobyte(series), Hibyte(series), param, tag, target}` 交给地图层(M3 呈现)。
- **TDefaultMessage**:recog=施法者 id;Lobyte(series)/Hibyte(series)=效果参数对(具体语义未核实,param/tag 为目标坐标类数值);**body(≥4 才读)**:int target(目标 roleid),再 ≥4:int magicLevel。
- **关键时序**:当 `msg.recog == g_data.player.roleid` 时执行 `setLastTime("spell", true)`(行 470-472),解除 CM_SPELL 的 2 秒节流——**服务端必须对每次合法施法回发一条 recog=施法者的 SM_MAGICFIRE,否则玩家将无法连续施法**。

### SM_MAGICFIRE_FAIL(639)——施法失败

- 分发:`ground.lua` 行 473,仅 `print`,**无任何状态回滚**(MP 不返还、节流不重置)。服务端若拒绝施法,建议同时考虑是否补发 SM_MAGICFIRE 以免卡死玩家节流(取舍未核实)。

### 英雄三件套:SM_HERO_SENDMYMAGIC(904)/SM_HERO_ADDMAGIC(913)/SM_HERO_MAGIC_LVEXP(916)

- 分发:`ui.lua` 行 1823/1829/1845 → `mir2.data.hero.lua :: setMagicList/addMagic/setMagicExp`,布局与本体的 SM_SENDMYMAGIC/SM_ADDMAGIC/SM_MAGIC_LVEXP 完全同构(操作 g_data.hero.magicList),不再重复展开。

## 服务端实现要点

1. **TNewClientMagic 是唯一技能载体**(本树不存在 TClientMagic 记录;BRIEF 附录中的 TClientAbility/TClientMagic 名称在本域实际代码中分别对应 TAllAbility 与 TNewClientMagic)。
2. **delayTime/needMp/coldTick 由服务端下发并被客户端强制执行**:调小 delayTime 会放大施法频率,须谨慎配置。
3. **SM_MAGICFIRE 是施法循环的心跳**:漏发会导致玩家约 2 秒一发甚至完全卡住;SM_MAGICFIRE_FAIL 客户端不恢复任何状态。
4. 快捷键是服务器态:key 字段 ↔ CM_MAGICKEYCHANGE.param 同一套 ASCII 编码,改键后服务端应更新并在此后的 SM_SENDMYMAGIC.key 中回填。
5. SM_SPELL.series 是 effectID+1(偏移 1),与其他消息的"原值直传"不同,构造广播时注意 +1/-1。
