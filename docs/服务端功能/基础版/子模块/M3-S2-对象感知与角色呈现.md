# M3-S2 对象感知与角色呈现

> 所属主模块:[M3-游戏世界与场景](../主模块/M3-游戏世界与场景.md)

## 功能概述

服务端视野广播(AOI)的全部下行报文都汇入 `mir2.scenes.main.ground.lua :: processMsg`(main 场景 ctor 中 `net.add(self.ground)` 注册)。该函数逐 ident 分支解析,把结果打包成 `{roleid, ident, x, y, dir, feature, state, …}` 压入 `map.msgs` 二级队列,由 `map.lua :: processMsgs` 每帧消费:`findRole` 找到或按 feature 新建角色对象(race 0/1/150→hero、50→npc、其他→mon),再调用 `role.lua :: processMsg(ident, x, y, dir, feature, state, params)` 映射为动作。本子模块按"出现→移动→死亡→消失→外观/名字→空间移动→英雄/召唤兽→地面物品/事件→血条"逐一记录每个分支的字段布局与语义。

## 涉及源文件

## 详细报文说明

以下所有分支的宿主函数均为 `mir2.scenes.main.ground.lua :: processMsg`,不再重复标注;动作落点标注 `role.lua :: processMsg` 对应分支。

### 对象描述的三种载体(SM_TURN 及移动族共用)

移动/转身族消息按 **bufLen 匹配记录尺寸** 选择解析方式:

| bufLen | 记录 | 内容 |
|---|---|---|
| 20B | TCharDesc | int feature(32 位紧凑 outlook)+ TAllBodyState(16B) |
| 32B | TNewCharDesc | uint outlook + status(16B)+ TFeature(10B)(布局见主模块共享报文) |
| ≥41B | TNewStateRec(**仅 SM_TURN**) | len/outlook/status/nameClr/specState/feature/job(41B packed)+ 尾部字符串 |

TNewStateRec 的**尾部字符串**(剩余 body 按 `/` split):

- 第 1 段再按 `\` split → 多行名字(`info:setName`);
- 第 2 段若以 `+` 开头 → 英雄队长标记(cWilIdxHeroTeamLord=295 图签);以 `-` 开头 → 队员标记(cWilIdxHeroTeamMember=296);否则整段为用户名。注意:该分支解析出的 `heroTeam/username` 是局部变量,**解析后被丢弃**,只有 name/nameColor 生效(代码事实,疑似未完成的英雄队伍功能,(未核实))。

### SM_TURN(10)— 转身 / 站立刷新

| 字段 | 含义 |
|---|---|
| recog | roleid |
| param/tag | 格子 x/y |
| series | 低字节=dir |

body 三格式见上表;解析出 desc 后统一 `map:addMsg{ident=SM_TURN,x,y,dir,feature,status,job,name,nameColor}`。
`role.lua :: SM_TURN`:置站立状态,addAct(type="stand");若状态含 stStone 则石化表现;mon 类播 born 音效。**服务端常用于对象首次可见时的补帧或打断动作复位**。

### 移动族:SM_WALK(11)/SM_RUN(13)/SM_BACKSTEP(9)/SM_RUSH(6)/SM_RUSHKUNG(7)/SM_HERO_RUSH(4)/SM_HERO_RUSHKUNG(5)/SM_MONRUSH(36)

- 字段:recog=roleid,param=x(目标格),tag=y,Lobyte(series)=dir;body=TCharDesc/TNewCharDesc。
- **自身豁免**:当 `msg.recog == self.player.roleid` 且 ident 为 SM_WALK/SM_RUN 时跳过(自己的走跑由 CM_ 请求 + SM_ACT_GOOD/FAIL 驱动,见 S3);其余 ident 即使是自己也照常处理(如自己被撞飞 SM_RUSH)。
- `role.lua` 映射:WALK/NPCWALK→walk 动作(SM_NPCWALK 未在 globa1 定义,恒 nil)、RUN→run、BACKSTEP→walk、RUSH→rushLeft/rushRight 交替、RUSHKUNG→rushKung(去程回程各半)、DEATH 族见下。目标格与当前格曼哈顿距离>2 或非直线时客户端直接"闪现"(act 降级为 stand,`role.lua :: executeAct`)——服务端必须保证位移合法(一步/两步直线)。

### 死亡与复活:SM_DEATH(32)/SM_NOWDEATH(34)/SM_SKELETON(33)/SM_ALIVE(27)

| 消息 | 客户端表现 | 服务端注意 |
|---|---|---|
| SM_DEATH | die+corpse=true(留尸体,可被 hideCorpse 设置隐藏) | 尸体期间对象仍在 map 表中,可继续收到动作包 |
| SM_NOWDEATH | die 但不留尸 | |
| SM_SKELETON | dir 强制 0,gutou 白骨贴图 | |
| SM_ALIVE | die=false,播 death(起身)动作 | 与 SM_ALIVE 配对使用 |

死亡后 `minimap:removePoint`、锁定目标清理(role.clearLock)。这些消息同样带 param/tag/x/y/dir 与可选描述 body(与移动族同格式)。

### 消失:SM_HIDE(29)/SM_GHOST(30)/SM_DISAPPEAR(803)

- 仅带 recog。`msg.recog ~= g_data.player.roleid` 时执行 `map:addMsg{remove=true, roleid}`:**立即从 heros/npcs/mons 表删除对象,并把该 roleid 在 msgs 队列中的未消费消息全部清洗**(`map.lua :: addMsg remove 分支`)。
- 服务端含义:对象离开视野/隐身/幽灵化,一律用这三者之一;同一批包中先发动作再发消失是安全的(动作会被丢弃),反之"先消失后动作"会创建不出对象而静默丢弃(findRole 无 feature 不建档)。

### 外观与状态变更

**SM_FEATURECHANGED(41)**:

- bufLen==TFeature 尺寸(10B)时 body=TFeature;否则退化格式:`feature = MakeLong(msg.param, msg.tag)`(32 位紧凑 outlook,series=新状态位图低 32 位)。
- `role.lua :: changeFeature` 按新外观差量重建部件(dress/weapon/hair/humEffect);数字自动经 makeTFeature 展开。

**SM_CHARSTATUSCHANGED(657)**:body=TAllBodyState(16B)完整状态位图。本人走同步分支更新 `self.player:processMsg`;他人入队。`role.lua`:替换 self.state 并插一个 type="state" 动作即时刷新中毒变色/隐身透明度/魔法盾贴图。

### 名字

**SM_USERNAME(42)**:

| 字段 | 含义 |
|---|---|
| recog | roleid |
| param | 名字色调色板索引(0-255,def.colors.get) |

body=`\` 分行的多行名字(GBK)。入队后在 `map.processMsg` 中 setName;race 98/153 不设名(见主模块约定)。

**SM_CHANGENAMECOLOR(656)**:recog=roleid,param=调色板索引,无 body。
**SM_CHANGELIGHT(654)**:仅 `print("SM_CHANGELIGHT, 人物的照明程度?")`——客户端未实现,服务端发不发无效果。

### 空间移动:SM_SPACEMOVE_SHOW(801)/SHOW2(807)/HIDE(800)/HIDE2(806)

- SHOW/SHOW2:recog=roleid,param/tag=出现坐标,Lobyte(series)=dir;body 必须是 TCharDesc(20B)或 TNewCharDesc(32B),取其 feature;**其他长度直接 return(忽略整包)**。
- 客户端:findRole 建档/复用 + spacemove 动作(瞬移到坐标)+ spaceMoveShow(2) 特效。
- HIDE/HIDE2:仅 recog,播放 spaceMoveHide(2) 特效(不删除对象,通常紧跟 SM_HIDE 或由后续坐标消息接力)。
- 典型用途:随机传送卷、传送阵把对象"吸进去/送出来"。传送阵门点数据本身来自本地 `config/doorPoint.txt`(`map.def.lua`),网络侧无对应推送(未发现 SM_OPENTRAP 类消息)。

### 地面物品(显示/隐藏;拾取协议归 M5)

**SM_ITEMSHOW(610)**:

| 字段 | 含义 |
|---|---|
| recog | 物品 id(itemid,服务端分配的地面物品标识) |
| param/tag | 格子 x/y |
| series | 外观图号 looks(dnitems 图库索引) |

body=**TFloorItem**(24B):string15 name(GBK)+int owner(归属者 id)+byte state。state>0 时物品名按紫色高亮显示(配合本地好物设置判断红名/显名)。owner 的精确语义(谁可拾取/归属时长)(未核实)。

**SM_ITEMHIDE(611)**:仅 recog=itemid。
注意:ground 里另有一个只 print("地上物品消失")的 `SM_DISAPPEAR` 分支,但它位于移动族 checkExist(SM_HIDE/SM_GHOST/SM_DISAPPEAR)之后,**是不可达的死代码**——SM_DISAPPEAR 实际永远走"删除对象"路径。地上物品的消失必须用 SM_ITEMHIDE 表达。

### 场景事件与摆摊

**SM_SHOWEVENT(804)**:

| 字段 | 含义 |
|---|---|
| recog | 事件服务端 id(serverID,增删键) |
| tag 低 16 位(Loword) | x |
| series | y |
| param | 事件类型 type(ET_*) |

body 按 bufLen 匹配:TEventMessage(12B)或 TEventMessage2(64B)。type 分发(`map.lua :: showEvent`):ET_FIRE=5 火墙、ET_HOLYCURTAIN=4 圣言结界、ET_PILESTONES=3 石头堆、ET_DIGOUTZOMBI=1 尸王钻地、ET_CAKEFIRE=8 蛋糕火、ET_YanHuaTextEvent=23 文字烟花(用 eventMsg.desc 显示大字)、ET_STALL_EVENT=41 **摆摊摊位**(用 TEventMessage2:id/msg/desc/name 建 stall 节点并登记 `map.stalls`,占 3×3 格阻挡)、ET_INTENTLY(78)..ET_SUCHASFOGDREAM(84) 一组庆典特效等(全表见 `map.def.lua`)。

**SM_HIDEEVENT(805)**:recog=serverID,移除事件/摊位。
**SM_USEITEMMAGIC(554)**:字段同 SHOWEVENT 但无 body(x=tag,y=series,type=param),用于物品触发的临时事件特效。

### 门(发送侧在 S3)

SM_OPENDOOR_OK(612)/SM_CLOSEDOOR(614):param/tag=门所在格子坐标,客户端按 tile.doorIndex 低 7 位找到同组门格并切换开/关图(`maptile.setDoorState`,开门帧=objidx+doorOffset);同时解除/恢复该格阻挡。SM_OPENDOOR_LOCK(613):提示"此门被锁定."。

### 挖肉与怪物特殊动作

- **SM_BUTCH(637)**:recog≠自己时入队;`role.lua`→sitdown 动作。对应玩家侧挖肉指令 CM_BUTCH(1007,M4/M5 边界)。
- **SM_DIGUP(20)**:body=TMessageBodyWL(16B),`param1` 被**当作 feature 数值**传入(数字→makeTFeature 展开,供钻出换装类怪使用);param/tag=x/y,Lobyte(series)=dir。`role.lua`→digup 动作+钻出音效;特定 race 有替代动画(def.mon.getMonDigupAct)。
- **SM_DIGDOWN(21)**:param/tag/x/y+dir;mon 执行 digdown 动画后**自行标记 readyRemove 并从场景移除**(`role.lua :: executeAct digdown 分支`)——服务端钻地即等于移除,不必再发 SM_HIDE。

### 攻击动作族(呈现;伤害数值归 M4)

- 单动作组 SM_HIT(14)/SM_HEAVYHIT(15)/SM_BIGHIT(16)/SM_POWERHIT(18)/SM_LONGHIT(19)/SM_WIDEHIT(24)/SM_HERO_LASTHIT(26)/SM_HERO_LONGHIT(25)/SM_SQUARE_HIT(3):recog≠自己时入队;字段 param/tag=攻击者坐标,Lobyte(series)=dir,无 body。`role.lua` 分别映射 attack/heavyHit/bigHit/hit(+对应剑法特效 magicId 7/12/25/26/34/58 等)。
- **SM_PHYSICAL_ATT(1230)**:body=TClientPhyAttRec(12B:short hitMode/skillLv/specEffect/dir/x/y),按 hitMode 重映射 ident:1000→SM_HIT、1001→SM_HEAVYHIT、1002→SM_BIGHIT、1003→SM_POWERHIT、1004→SM_LONGHIT、1005→SM_WIDEHIT、1007→SM_FIREHIT、1011→SM_HERO_LONGHIT、1012→SM_HERO_LASTHIT、1013→SM_SQUARE_HIT、1015→SM_SWORD_HIT、1017→SM_HundredHit、1018→SM_HORIZONHIT;x/y/dir 取自记录。这是"新版"统一物理攻击广播,旧单动作消息与之并存。
- SM_UNITEHIT0/1/2(60/61/62):合击动作,特效类型 zz/zf/zd(magicId 50/52/51)。
- SM_FLYAXE(22):param/tag=出手坐标,Lobyte(series)=dir,body=TMessageBodyW(8B):target=MakeLong(tag1,tag2)(目标 roleid 拼合),x=param1,y=param2(落点)。
- SM_BIGMONMAGIC(716):param/tag=坐标,series=特效编号(拼 "effectNum"..series 播放)。

### 施法呈现(技能语义归 M4)

- **SM_SPELL(17)**:recog=施法者,param/tag=目标点 x/y;series-1 的低字节=effectType(`Byte(msg.series - 1)`);body 可选:int magicId(剩≥4B 时读)、int magicLevel(再剩≥4B 时读)。
- **SM_MAGICFIRE(638)**:Lobyte(series)=effectType,Hibyte(series)=effectID,param/tag=目标点,body int target(目标 roleid,int32;若再剩≥4B 会读 magicLevel 但未使用)。本人施法时顺带 setLastTime("spell")(节流键,S3)。飞行物由 `magic.showMagic(roleid, effectType, effectID, x, y, target)` 渲染。
- **SM_MAGICFIRE_FAIL(639)**:仅 print,无处理。

### 受击与血量(数值面板归 M4)

- **SM_STRUCK(31)**:双格式——bufLen==TMessageBodyWL(16B)时 hp=msg.param,maxHp=msg.tag;bufLen==TStruckInfo(32B)时 hp/maxHp/mp/maxMp 取自记录。series=飘出的伤害数字(outhp)。本人与英雄同步 g_data.player/g_data.hero 的 ability HP/MP,其他人经队列 setHP。
- **SM_HEALTHSPELLCHANGED(53)**:双格式——TMessageBodyWL:param1=hp,param2=maxHp,tag1=mp,tag2=maxMp;否则 hp=msg.param,mp=msg.tag,maxHp=msg.series(maxMp 缺省)。
- **SM_OPENHEALTH(1100)**:本构建存在**移植缺陷**:分支引用了未赋值的局部 `hp/maxHp`(nil),实际不会显示任何血量;服务端发它当前无效果(如实记录)。要展示他人血条,直接持续发 SM_HEALTHSPELLCHANGED 即可(首包即建血条)。
- **SM_CLOSEHEALTH(1101)**:仅 print。
- **SM_SHOWBODY_EFFECT(1107)**:param=11 → protectionStruck(护盾抵消)特效;param=20 → bloodlust(嗜血)特效;recog=作用对象。

### 英雄召唤呈现(背包装备归 M9)

- **SM_HERO_LOGON(899)**:recog=英雄 roleid,param/tag=x/y,Lobyte(series)=dir;body 必须是 **TNewHeroLook(40B)**(outlook/status/state/resv/feature)。建档(hero 类)、`g_data.hero:setRoleID/setSex(feature.sex)`、挂为 player.hero、显示 heroHead 面板。
- **SM_HERO_LOGOUT(918)**:清除 player.hero、重置 g_data.hero/heroBag/heroEquip,收起面板。
- **SM_HERO_LOGMAGIC(897)/SM_HERO_QUITMAGIC(896)**:param/tag=坐标,播 heroBorn/heroHide 特效(召唤/收回光效)。
- **SM_HERO_NAME(898)**:body=名字串,param=heroType,tag=heroRank → `g_data.hero:setName(name, type, rank)`。
- **SM_HERO_SPLITSHADOW(924)**:param/tag=坐标的 heroSplistShadow 分身特效(recog 附带)。
- **SM_HERO_HELPOP_OK(925)**:recog=1 → 同步合击锁开关;recog=2 → 同步守护开关(UI 回执)。

### 召唤兽名单

- **SM_SLAVE_BORN(4469)**:body=名字串 → `g_data.player:addSlave(name)`。
- **SM_SLAVE_VANISH(4470)**:body=名字串 → removeSlave。名单用于自动打怪/面板展示,不影响地图对象(怪物本体仍走 AOI 消息)。

### 其他

- **SM_LEVELUP(45)**:ground 分支只在**本人脚下**播 levelup 特效;升级属性/提示由 ui.lua 的同名分支处理(等级值 msg.param → runner.onLevelUp,归 M4)。
- **SM_SHOWHELPER(4407)**:recog=2 时 body=被杀怪名 → helper.runner.onKilledMonster(新手引导事件;存在 bossId 形参 bug,见 S1 要点 7)。recog=1 空实现。

### mon/npc/hero/stall 变体的区分字段(建档规则)

`map.lua :: newRole` 只依据 **TFeature.race**:0/1/150→hero(race==0 且 params.isPlayer 时设为 self.player)、50→npc、其余→mon。变体差异:

| 变体 | 判定/字段 | 说明 |
|---|---|---|
| hero(玩家) | race 0/1/150 | dress/weapon/hair 经 def.role 配置(dress.txt/weapon.txt 本地 JSON)拆部件;sex 来自 TFeature.sex |
| npc | race==50 | dress=NPC 外观号(<256 支持,70-75 为龙形 cannotMove);名字默认色 250 |
| mon | 其余 race | monsterId=getRoleId(race,dress) 查 def.role 怪物表选图库(monImgs 特例映射,race 99 沙巴克城门按血量换破损贴图);race 12/24 为护卫(guard,有回归原点逻辑),50/12 或名为弓箭护卫/守卫视为 police(不参与最近怪搜索) |
| stall(摆摊) | 不是 role;由 SM_SHOWEVENT type=41 创建 | 占 3×3 阻挡(isObjblock),安全区内不阻挡 |
| race 98/99/153 | 特殊 | 不显示名字(info.isShowName);99 兼有 blend 半透明 |

def.frame.lua(4728 行)全部是各动作的帧号/帧数/时长表(start/frame/ftime/skip),**不含任何影响报文字段的定义**,服务端无需关心。

## 服务端实现要点

1. **AOI 广播字段纪律**:所有对象消息 recog=roleid(int32)、param=x、tag=y、series 低字节=dir;描述 body 三格式按**总长**区分(20/32/≥41),长度错了会被当成别的记录解析,务必精确。
2. **先描述后动作**:对象首次进入视野时,任何动作消息(SM_WALK 等)都能凭 body 里的 feature 建档,因此**每条移动/转身包都必须携带完整描述 body**——这正是老 mir2 协议的做法;省略 body 将导致 findRole 建不了档、整包被静默丢弃。
3. **移除时机**:SM_HIDE/GHOST/DISAPPEAR 会连带清空该对象的排队动作;死亡(SM_DEATH)不移除对象,尸体消失用 SM_HIDE;钻地怪用 SM_DIGDOWN 自移除。
4. **队列时延**:客户端每帧只花 ≤10ms 消化 map.msgs(net 层还有 ≤30ms 切片),大量对象同帧进场时动作会平滑排队;但顺序绝不重排——服务端按序广播即可,不要依赖客户端"立即"呈现。
5. **直通例外**:SM_ACT_GOOD/SM_ACT_FAIL 不排队(见 S3);对自己/英雄的 SM_STRUCK/SM_HEALTHSPELLCHANGED 血量更新是同步的,可用于即时校准。
6. 名字颜色用调色板索引而非 RGB;多行名用 `\` 分隔;GBK 编码。
7. SM_OPENHEALTH 当前无效(缺陷),他人血条靠 SM_HEALTHSPELLCHANGED 维护;需要"显示血条开关"语义的服务端可自行用状态位 stOpenHealth(=1,TAllBodyState 位图)表达。
