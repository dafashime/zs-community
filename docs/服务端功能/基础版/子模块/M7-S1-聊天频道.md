# M7-S1 聊天频道

> 所属主模块:[M7-社交系统](../主模块/M7-社交系统.md)

## 功能概述

聊天是本客户端唯一的自由文本通道:所有频道(附近/私聊/喊话/组队/战队/行会/千里传音/系统/广播)共用一条 `CM_SAY` 上行报文,靠**频道前缀语法**区分;服务端按频道转发为对应的 SM 报文。聊天文本内可嵌入表情、语音、截图、坐标、物品五类富文本标记(纯文本协议,无独立报文)。频道接收开关由 `CM_SWITCH_LISTEN`/`SM_CLIENT_CONF` 位掩码管理。

屏幕聊天八件套的布局与控件见 [M4-S4-系统消息与提示](../子模块/M4-S4-系统消息与提示.md),本文不重复。

## 详细报文说明

### CM_SAY(3030) — 发言

来源:`mir2.scenes.main.common.common.lua :: common.say`(L457)+ `mir2.data.chat.lua :: chat.getSayText`(L222)。

发送前处理链:

1. 本地敏感词过滤 `def.wordfilter.run`;例外:**附近频道且以 `@` 开头的原文不做过滤**(供 `@` 口令直达,common.lua L464–470)。
2. 按当前频道拼装频道前缀(`chat:getSayText`,data.chat.lua L222):

| 频道 | 发送的 strs[0] 文本格式 |
|---|---|
| 附近 | `<原文>`(无前缀) |
| 喊话 | `!` + 原文 |
| 私聊 | `/` + 对方名 + 空格 + 原文 |
| 组队 | `!!` + 原文 |
| 战队 | `!#` + 原文 |
| 行会 | `!~` + 原文 |
| 千里传音 | `@传` + 空格 + 原文(`def.cmds.get("@千里传音")=="@传"`,def.cmds.lua L3–6) |

3. 表情编码:`common.encodeEmoji`(common.lua L31)把每个 ≥4 字节的 UTF-8 字符转为 `{@ej<base64>}`(base64 结果去掉尾部 `=` 并把 `/` 替换为 `!`)。
4. `net.send({CM_SAY, param = hasRich and 1}, {str})`:**param 仅在文本含富文本片段时为 1**,纯文本时该字段缺省(TDefaultMessage.param=0)。
5. body 布局:单条字符串,经 net 层 u2a 转 GBK,前置 1 字节 0x00(BRIEF §4)。无 data record。

私聊发送成功后客户端本地立即回显一条 color=180/bgColor=255 的 `/目标 内容` 消息并写入本地聊天记录(cache),**不依赖服务器回包**(common.lua L502–507)。

`@` 口令(如 `@传 内容`、`@允许求婚` 等 def.cmds.all 表中的口令)同样走 CM_SAY 文本上行,服务端按口令解析,**没有专用报文**。

### 富文本内嵌标记(随 CM_SAY 文本携带)

来源:`common.encodeRich`(L48)/`common.decodeMsg`(L67)。发送方把标记拼进文本;**接收方原样收到后再解析**,因此服务端只需透明转发文本(注意 GBK 编码下的 `{}` `|` `@` 字符不会被转码破坏)。

| 标记格式 | 含义 | 字段 |
|---|---|---|
| `{@emNNN}` | 内置表情(NNN 三位十进制编号) | 本地素材 `pic/emoji/NNN.png`,不产生网络流量 |
| `{@ej<8字符base64>}` | 自定义字符表情(emojiConvert) | base64 中 `/` 已替换为 `!` |
| `{@vi<URL>\|<时长>\|<msgID>}<附文>` | 语音消息 | URL 中 `/` 替换为 `!`;语音文件本身经 yaya SDK HTTP 上传/下载(mir2.single.voice.lua),不走 TCP |
| `{@pi<URL>\|<大小KB>\|<msgID>}` | 截图消息 | 截图经 HTTP 上传(`pic.upload`,mir2.single.pic.lua);点击时 `pic.download` |
| `{@ps<mapID>\|<地图名>\|<x>\|<y>}` | 坐标分享 | 点击仅打开本地大地图,无网络请求 |
| `{@it<makeIndex>\|<lookID>\|<名称>\|<重量>}` | 物品链接 | 点击触发 CM_QUERY_FOCUS_ITEM |

含上述任一标记时 CM_SAY 的 param=1(`hasRich`)。

**结论:聊天图片/语音不存在"#编号"类特殊编码**,编号(msgID/URL)以明文嵌在 `{@pi...}/{@vi...}` 标记内。

### 聊天接收(SM_HEAR 40 / SM_CRY 102 / SM_GROUPMESSAGE 101 / SM_GUILDMESSAGE 104 / SM_CORPSMESSAGE 108 / SM_WHISPER 103 / SM_SYSMESSAGE 100 / SM_BROADCASTMESSAGE 106)

分发:`mir2.scenes.main.ui.lua :: processMsg` L283:

```lua
checkExist(ident, SM_HEAR, SM_CRY, SM_GROUPMESSAGE, SM_CORPSMESSAGE,
           SM_GUILDMESSAGE, SM_SYSMESSAGE, SM_WHISPER, SM_BROADCASTMESSAGE)
```

处理:`net.strs(buf)` 取第一段(`/` 分割),依次过 `settingLogic.filterChat` 与 `g_data.relation.filterChat`(黑名单过滤,relation.lua L466),然后 `common.addMsg(strs[1], Lobyte(param), Hibyte(param), nil, msg.recog, ...)` —— 即:

- **TDefaultMessage.param 低字节 = 文字颜色索引,高字节 = 背景颜色索引**(经 `def.colors.get` 映射)。
- **recog = 发言者 roleid**(用于附近频道头顶气泡定位与私聊记录 user 字段)。

各频道的 body 文本格式约定(服务端必须按此拼装,否则客户端解析不出说话人,data.chat.lua :: getUser L30 / getChannel L95 / relation.lua :: filterChat L466):

| 频道 | ident | body 文本格式 | 颜色约定 |
|---|---|---|---|
| 附近 | SM_HEAR(40) | `名字:内容` | 任意 |
| 喊话 | SM_CRY(102) | `(!)名字:内容`(前缀恰为 3 字符 `(!)`,名字到第一个 `:` 之前) | 黄色系(客户端文案"黄颜色字体") |
| 组队 | SM_GROUPMESSAGE(101) | `-名字:内容` | **必须** Lobyte(param)=196 且 Hibyte(param)=255,客户端以此识别组队频道(data.chat L114) |
| 行会 | SM_GUILDMESSAGE(104) | `名字:内容` | 任意 |
| 战队 | SM_CORPSMESSAGE(108) | (客户端未从文本解析名字,仅按 ident 归类) | 任意 |
| 私聊 | SM_WHISPER(103) | `名字=> 内容`(注意 `=>` 后有一个空格) | 任意 |
| 系统 | SM_SYSMESSAGE(100) | 任意 | 任意 |
| 广播 | SM_BROADCASTMESSAGE(106) | 任意 | 任意 |

SM_WHISPER 的附加字段(common.lua :: decodeMsg L68–82):

- `tag` = 对方的显示等级,客户端在 `=>` 前插入 `[N级]`;
- `series` = 0 时只显示 `[N级]`;非 0 显示 `[N级 series+]`(**推测 series 为转生等级,(未核实)**);
- `recog` = 对方 roleid,写入私聊记录的 user。

私聊过滤(settingLogic.lua L626):当本地设置 `whisperLimit` 生效且 `msg.tag < whisperLimit` 或 `whisperLimit == 0` 时,该条私聊被本地丢弃——服务端无需处理,但 tag 必须真实填写等级才能让该过滤正常工作。

黑名单过滤(relation.lua L483):说话人名出现在黑名单时整条丢弃(附近/喊话/行会/私聊等全部生效)——同样纯本地。

### CM_SWITCH_LISTEN(3032) — 频道开关

来源:`common.setChatChannelIsOpen`(common.lua L1283)。

玩家切换"私聊/附近公聊/喊话/行会"四个**服务器保存型**频道的接收开关时发送(组队/战队频道为本地保存 localSave,不发报文):

| 字段 | 值 |
|---|---|
| recog | 0=开启接收,1=关闭接收 |
| param | 通道位:1=私聊,2=公聊(附近),3=喊话,4=行会(common.allChatChannels,common.lua L1219) |
| body | 无 |

### SM_CLIENT_CONF(2953) — 屏蔽位掩码下推

分发:`ui.lua :: processMsg` L299(另见 reconnect.scene L194、notice.scene L184,同一语义)。

```lua
g_data.chat:setShieldMask(msg.recog)
```

| 字段 | 含义 |
|---|---|
| recog | 32 位屏蔽掩码;**bit 置 1 = 该玩家拒绝接收对应频道**。bit1=私聊,bit2=公聊(附近),bit3=喊话,bit4=行会(`ycFunction:band(shieldMask, 1<<n)==0` 判定开启,common.lua L1280) |

服务端职责:登录初始化与每次 CM_SWITCH_LISTEN 变更后,下发最新掩码;之后该玩家不再收到其拒绝频道的聊天转发(或发了也会被客户端本地屏蔽,建议服务端过滤以省带宽)。

### CM_QUERY_FOCUS_ITEM(1271) — 聊天物品链接查询

来源:`chatItem.lua :: ctor` 点击回调(L16–28):仅当本地无该物品完整数据时发送。

| 字段 | 值 |
|---|---|
| recog | 物品 makeIndex(uint) |
| body | 无 |

应答 **SM_QUERY_FOCUS_ITEM(3290)**:`ui.lua` L291 → `net.record("TClientItem", buf, bufLen)`,body = 单条 TClientItem(packed,定长头 16B = uint makeIndex + short Index + short dura + short duraMax + short KeyValueSize + uint _Reserved,后接 KeyValueSize×4B 的 TClientKeyValue dynamicArray)。客户端用它补全聊天物品浮层并缓存(`g_data.chat:uptItemMsgData`)。

## 服务端实现要点

1. **CM_SAY 是万能文本入口**:必须先解析频道前缀(`!`、`/名字 `、`!!`、`!#`、`!~`、`@传 `),再决定路由;`@` 开头的附近频道文本优先按 GM/系统口令处理。
2. 转发时**重写 body 为目标频道的标准格式**(如行会频道拼 `名字:内容`),并正确设置 param 的低/高字节颜色;组队频道固定色 196/255 + `-` 前缀是客户端识别依据,不可省略。
3. 富文本标记透明转发即可,但需保证 GBK 编码安全(标记 ASCII 字符不受 GBK 影响);语音/截图文件的 HTTP 存储服务与 TCP 服务解耦,URL 由上传方生成。
4. 屏蔽掩码以服务端为准下发(SM_CLIENT_CONF.recog),客户端开关只是发起变更;四个服务器保存型频道之外(组队/战队)客户端自管,服务端不必感知。
5. 私聊需校验目标存在/在线;失败时经典 Mir2 以系统频道文本提示(本树未见专用错误码分支,(未核实))。
6. 发言频率限制(刷屏禁言)客户端完全不做,由服务端自行实现;禁言提示可走 SM_SYSMESSAGE。
