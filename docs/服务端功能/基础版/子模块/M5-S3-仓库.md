# M5-S3 仓库

> 所属主模块:[M5-物品与装备](../主模块/M5-物品与装备.md)

## 功能概述

NPC 仓库(个人仓)的完整协议:仓库内容全量下发(SM_SAVEITEMLIST)、从背包寄存(CM_USERSTORAGEITEM)、取回(CM_USERTAKEBACKSTORAGEITEM)及全部应答;仓库内格间移动/堆叠复用背包通用消息(SM_DELITEM param=1、CM_PILEUPITEM);仓库内物品耐久变化。
面板为 `panel.storage`:4 页 × 每页 48 格(共 192 格,`gridMax=48`),`gridCnt` 控制前多少格已解锁(`storage:gridIsOpen`,idx≤gridCnt 可用)。任务所问的"面板打开拉取"在本客户端是**服务端推送 SM_SAVEITEMLIST 直接开面板**,不存在 CM_SAVEITEMLAST 之类的拉取命令(grep 无此常量)。

## 详细报文说明

### 1. SM_SAVEITEMLIST(704)——仓库全量 & 开面板

- 时机:客户端没有主动"请求仓库"的命令。入口是 NPC 脚本对话选择(M6 的 CM_MERCHANTDLGSELECT,@warehouse 类脚本),服务端处理后就发本消息。客户端收到即 `showPanel("storage", …)`(ui.lua 718-720 行),同时把背包面板挪到仓库旁(bag resetPanelPosition("storage"))。
- 字段:

  | 标头 | 含义 |
  |---|---|
  | recog | NPC 实例 id(后续所有存取原样回传) |
  | param | 本次 body 内物品件数 count |
  | tag | 已解锁格数 gridCnt(idx≤tag 的格子可用,>tag 显示锁图标) |

- body:`count` 条 TClientItem 连续排列(`panel.storage.lua :: ctor` 93-99 行按 param 计数解析)。单条尺寸 16+4n(主模块 §2.2)。
- 页签映射:全局格位 idx = 页号+页内位(1..192);`itemDatas[idx]` 线性存放,服务端无需发送页号——顺序即布局。
- 错误分支:无;不发则面板不开。

### 2. CM_USERSTORAGEITEM(1031)——寄存

- 时机:背包物品拖入仓库面板任意开放格,或开启"快捷"模式后双击背包物品(`storage:putInItem`;item.lua quick 分支)。
- 单飞保护:`g_data.client.storageItem` 非空时忽略新请求(上一件未结算)。
- 字段:

  | 标头 | 值 |
  |---|---|
  | recog | NPC id(来自 SM_SAVEITEMLIST.recog) |
  | param | Loword(MakeIndex) |
  | tag | Hiword(MakeIndex) |
  | series | 不填 |

- strs:{物品名}。body 无其余内容。
- 客户端乐观扣减:先从 bag 面板与 g_data.bag 移除,挂到 storageItem 暂存。

### 3. 寄存应答 SM_STORAGE_OK(701)/ FULL(702)/ FAIL(703)

- 三条共用一个处理块(ui.lua 867-911 行):
  - 公共:清 npc sell-frame、清 lastSellItem/storageItem 暂存标志。
  - **OK**:物品正式入仓库面板(storage:addItem 自动找第一个空格,必要时自动切页签);若此前 lastSellItem 存在(NPC 投放框路径)也同步删背包条目。**注意 OK 不携带 TClientItem**,面板显示用的是客户端暂存数据——服务端若在寄存时修改了物品属性(如改持久),需随后补 SM_STORAGEITEMDURACHG 或让客户端下次全量刷新。(未核实旧服务端是否保证属性一致)
  - **FULL**:弹窗"你的个人仓库已满…",物品回背包。
  - **FAIL**:tip"寄存失败。",物品回背包。
- 四标头在这三条里都不读(body 无)。
- 并行通道:NPC sell-frame 的 storage 模式(SM_SENDUSERSTORAGEITEM(700) 打开,recog=NPC)确认时同样发 CM_USERSTORAGEITEM(clickSellOk 906 行分支,series=sp or 0)。两条路径报文相同,服务端无感知差异。

### 4. CM_USERTAKEBACKSTORAGEITEM(1032)——取回

- 时机:仓库物品拖回背包(或双击,quick 模式),`storage:getBackItem`(327-347 行);以及 NPC 列表模式选中仓库条目点购买键(npc.lua clickBuy type=="storage")。
- 单飞保护:g_data.client.storageGetBackItem。
- 字段:与 1031 完全一致(recog=NPC,param/tag=MakeIndex 低/高,strs={名称})。
- 应答:
  - **SM_GETSTORAGEITEM_OK(705)**:`recog`=MakeIndex(ui.lua 912-918 行用于 npc:removeItem);物品本体由随后的 **SM_ADDITEM(200)** 入包(推断组合,客户端按通用增量消费;未核实旧服务端顺序)。客户端清 storageGetBackItem。
  - **SM_GETSTORAGEITEM_FAIL(706)**:错误码表(recog):

    | recog | 文案 |
    |---|---|
    | -1 | 您已无法携带这么重的物品了(超重) |
    | -2 | 在交易中无法使用仓库功能 |
    | -3 | 你的仓库已被盛大CD卡、或密宝绑定,如需取出物品请先开启仓库 |

    物品退回仓库面板(storage:addItem)。
  - **SM_GETSTORAGEITEM_FULLBAG(707)**:弹窗"您无法携带更多物品了.",物品退回仓库面板。
- 失败类均需客户端回滚 → 服务端必须显式回执,不能静默丢弃请求。

### 5. SM_STORAGE_ADDITEM(717)——仓库新增

- 时机:仓库内拆分产物、系统直投仓库(如配药"存入仓库"路径的产物,S5)。
- body:**一条 TClientItem**(ui.lua 955-958 → panel.storage:splitNemItem,bufLen>0 才处理)。
- 客户端 addItem 自动放入第一个空格(跨页自动切签显示)。
- 标头不读。

### 6. SM_STORAGEITEMDURACHG(790)

- `recog`=MakeIndex,`param`=dura,`tag`=duraMax,`series`=价格(透传不用);同步 itemDatas/itemDatasBak/UI 三处(storage:duraChange)。body 无。

### 7. 复用消息(职责边界声明)

| 复用 | 说明 |
|---|---|
| SM_DELITEM(202,param=1) | 服务端删仓库物品(如被系统收回):只清仓库视图,不碰背包/装备。param 必须为 1,误发 0 会误删同名背包/装备条目 |
| CM_PILEUPITEM(1115) | 仓库页内两堆合并:recog=目标,param/tag=源低/高,**series=0**(panel.storage putIn 388-393 行);同样要等 SM_ITEM_PILEUP_RESULT(3322) 才继续 |
| SM_ITEM_PILEUP_RESULT(3322) | 仓库发起的叠放 series 也是 0(仓库无英雄形态) |
| CM_SPLITITEM(1116) | 仓库物品拆分:series=0;产物走 SM_STORAGE_ADDITEM(见 S1 §10) |
| TClientItem 结构 | 引用主模块 §2.2,本文不重复字段表 |

### 8. 未使用/边界

- SM_STORAGE_SPACE_CHANGED(718):定义存在,客户端无分支。
- SM_SENDUSERSTORAGEITEM(700) 只是"保管投放框"开关(等价于 sell-frame 的 repair/sell 模式切换),不是仓库内容下发;内容仍以 704 为准。
- 英雄无独立仓库(M9 heroBag 与仓库无关)。

## 服务端实现要点

1. **param/tag = Loword/Hiword(MakeIndex)** 是本域所有 C→S 的编址惯例,还原函数 `MakeLong(param, tag)`;不要把整个 uint32 塞进 param(会截断)。
2. 704 的 param/tag 是仅有的两个"数量"型标头(件数/开格数),其余 STORAGE 族标头基本不读;保持发送顺序:先 704 后任何增量。
3. 取回三态(OK/FULLBAG/FAIL)必须恰好回其一,否则客户端暂存占用导致后续取回被单飞保护吞掉。
4. 寄存/取回都带物品名 strs(GBK),建议校验名字与 makeIndex 一致防伪造包(客户端不做本地验证)。
5. 仓库容量裁决完全服务端侧:gridCnt 由 704 下发后客户端只做显示锁格;扩容操作(如元宝开格)属 NPC 商店域(M6),完成后重发 704 即可刷新。
