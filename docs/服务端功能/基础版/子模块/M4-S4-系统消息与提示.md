# M4-S4 系统消息与提示

> 所属主模块:[M4-战斗属性与技能](../主模块/M4-战斗属性与技能.md)
> 本子模块的 body 布局是聊天模块(M7-S1)的直接引用来源:M7 只描述上行(CM_SAY 等),下行一律以本文为准。

## 功能概述

服务端向客户端推送的八种文本消息(系统提示、附近、喊话、私聊、组队、行会、战队、广播)在客户端走**同一条分发分支**,共用同一 body 布局(`/` 分割多段 GBK 字符串)与同一颜色编码(param 低/高字节双色调)。客户端按消息号映射聊天频道,并从文本前缀中二次解析说话人名字。SM_CLIENT_CONF 单独下发频道屏蔽位掩码。

## 详细报文说明

### 聊天八件套(SM_HEAR 40 / SM_GROUPMESSAGE 101 / SM_CRY 102 / SM_WHISPER 103 / SM_GUILDMESSAGE 104 / SM_BROADCASTMESSAGE 106 / SM_CORPSMESSAGE 108 / SM_SYSMESSAGE 100)

- **分发**:`mir2.scenes.main.ui.lua :: processMsg` 行 283:
  `checkExist(ident, SM_HEAR, SM_CRY, SM_GROUPMESSAGE, SM_CORPSMESSAGE, SM_GUILDMESSAGE, SM_SYSMESSAGE, SM_WHISPER, SM_BROADCASTMESSAGE)`。
- **TDefaultMessage 字段**:

| 字段 | 含义 | 证据 |
|---|---|---|
| recog | 说话者 roleid(number);传入 addMsg 后用于"附近"频道头顶气泡的角色定位(findRole);不用于显示名字 | common.updateAddMsg 行 272-275、316-327 |
| param 低字节 Lobyte(param) | **文字前景色**(色板索引 color) | addMsg 第 2 参 |
| param 高字节 Hibyte(param) | **文字背景色**(色板索引 bgColor) | addMsg 第 3 参 |
| tag | 仅 SM_WHISPER 使用:与本地设置 whisperLimit 比较,`whisperLimit==0 或 msg.tag < whisperLimit` 时整条拒收(语义疑似"发言者等级",未核实) | settingLogic.filterChat |
| series | 未使用 | |

  典型取值参考(本地调用侧):普通白字 `color=219,bg=256`;红字用 display.COLOR_RED;频道启发式依赖的组合为 `color=180,bg=255`(私聊)与 `color=196,bg=255`(组队)。
- **body**:`net.strs(buf)` —— 整个 body 按 `/` 分割的多段字符串,GBK→UTF8(`net.strs` 见简报 §5)。**strs[1]=正文文本**;后续段保留在原始 buf 中供聊天扩展(语音/图片指令)二次解码(`common.decodeMsg(text, netMsg)`)。
- **处理链**:`settingLogic.filterChat(strs[1], ident, msg)`(本地私聊等级过滤)→ `g_data.relation:filterChat(...)`(黑名单过滤,命中即丢弃;均为本地行为各一句,不展开)→ `common.addMsg(strs[1], Lobyte(msg.param), Hibyte(msg.param), nil, msg.recog, msg, buf, bufLen)` → `common.updateAddMsg` → `chat:addMsg` 入聊天记录(上限 50 条)。
- **频道映射**(`chat:getChannel`,chat.lua 行 95):

| 消息号 | 频道名 |
|---|---|
| SM_HEAR(40) | 附近 |
| SM_WHISPER(103) | 私聊 |
| SM_CRY(102) | 喊话 |
| SM_GUILDMESSAGE(104) | 行会 |
| SM_CORPSMESSAGE(108) | 战队 |
| 其余(SM_GROUPMESSAGE/SM_SYSMESSAGE/SM_BROADCASTMESSAGE 等) | 文本启发式:`color==180 && bg==255 && 正文以"/"开头`→私聊;`color==196 && bg==255 && 正文以"-"开头`→组队;否则→系统 |

- **说话人名字解析**(`chat:getUser`,chat.lua 行 30):显示名不是 recog,而是**从 strs[1] 文本前缀解析**:
  - 附近/行会/千里传音:`"名字:正文"`(第一个 `:` 之前);
  - 私聊:`"/名字 正文"` 或 `"名字[...]"`;
  - 喊话:`"(!)名字:正文"`;
  - 组队:第一个 `-` 在第一个 `:` 之前时取两者之间;
  - 系统:`"名字:..."` 取冒号前;战队:无专门解析(user 为空)。
  服务端拼装文本时应遵守上述前缀格式,否则聊天窗口显示不出说话人。
- **错误分支**:无应答概念;buf 为空时整条忽略。

### SM_CLIENT_CONF(2953)——频道屏蔽掩码

- 分发:`ui.lua` 行 299 → `g_data.chat:setShieldMask(msg.recog)` + `common.refershChatContent()`。notice/reconnect 场景有同构分支(仅 setShieldMask)。
- **字段**:recog=32 位掩码,**bit 置 1 表示该频道被屏蔽(拒绝接收)**;param/tag/series/body 未使用。
- **位定义**(`common.allChatChannels`,common.lua 行 1219;`getChatChannelIsOpen`: `band(shieldMask, lshift(1, bit)) == 0` 视为开启):

| 位(bit 索引) | 频道 | 掩码值 |
|---|---|---|
| 1 | 私聊 | 0x0002 |
| 2 | 附近/公聊 | 0x0004 |
| 3 | 喊话(黄字) | 0x0008 |
| 4 | 行会 | 0x0010 |

  组队/战队的开关存本地配置不入掩码;"系统"频道永远开启。
- **联动上行**:客户端在聊天设置里切换开关时,除改本地掩码外会发 `CM_SWITCH_LISTEN(3032){recog = 开?0:1, param = 位索引}`(common.lua 行 1310)。因此掩码的权威状态在服务端,SM_CLIENT_CONF 是服务端向客户端同步(含登录初始化与其他设备变更)的通道。

### SM_MENU_OK(767)/SM_DLGMSG(772)——文本提示框(共享分支)

- 分发:`ui.lua` 行 293:`SM_MENU_OK == ident or SM_DLGMSG == ident` → `net.str(buf)` 全文作为提示弹框文本(空串不弹)。
- **字段**:body=GBK 文本(整段,非 `/` 分割);recog/param/tag/series 未使用。
- 用途推断:SM_MENU_OK 对应 NPC 菜单动作成功回执(如改名/拜师成功提示),SM_DLGMSG 为通用对话框文本(NPC 脚本 `输入框/提示` 通道);两者客户端处理完全相同。服务端实现时二选一即可,客户端不区分。

### 本地过滤(各一句,不展开)

- `settingLogic.filterChat`(settingLogic.lua 行 626):仅针对 SM_WHISPER,当本地设置 whisperLimit==0 或 `msg.tag < whisperLimit` 时拒收。
- `g_data.relation:filterChat`(relation.lua 行 466):按文本前缀提取说话人查本地黑名单拒收,并对私聊做未读记录。

## 服务端实现要点

1. **一条 body 布局覆盖八个消息号**:GBK 文本以 `/` 分割,首段为正文;额外段(如语音消息 id/url)由聊天扩展解码器消费,格式详见 M7(此处只需保证首段正确)。
2. **颜色编码压缩在 param 一个 16 位里**:Lobyte=文字色板索引,Hibyte=背景色板索引;想让某条系统提示走"私聊/组队"启发式识别,必须精确使用 (180,255)/(196,255) 组合并配 "/" 或 "-" 前缀。
3. **recog 是 roleid 不是名字**:头顶气泡靠它找场景内角色;跨地图/离线广播(找不到角色)时只影响气泡,不影响聊天窗显示。
4. **SM_WHISPER.tag 有过滤语义**:被本地 whisperLimit 过滤的消息直接丢弃且无回执;tag 含义(疑似等级)未核实,保守做法是填发言者等级或 0 以外勿用。
5. **SM_CLIENT_CONF 是服务端权威的频道订阅状态**:登录后应主动下发一次;用户在其他端改设置时再次推送即可实时生效,无需客户端确认。
