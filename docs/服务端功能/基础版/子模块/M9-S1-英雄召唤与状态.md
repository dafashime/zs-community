# M9-S1 英雄召唤与状态

> 所属主模块:[M9-英雄系统](../主模块/M9-英雄系统.md)

## 功能概述

英雄是随主角作战的服务端托管实体。客户端职责仅限:

1. **请求召唤/收回**(`CM_HERO_LOGON` 1050 / `CM_HERO_LOGOUT` 1051);
2. **为英雄指定攻击目标或守卫点**(`CM_HERO_APPTARG` 1105)——英雄的移动、攻击、施法全部由服务端 AI 决策并以下行报文驱动,本树客户端没有任何"代替英雄施法"的上行报文(autoRat.lua 无英雄逻辑,grep 核实);
3. **切换英雄辅助状态**(自动魔法盾 `CM_HERO_CHGSTATE` 1107;休息模式经聊天命令 `@RestHero`);
4. **接收并展示服务端下发的英雄数据**:身份(SM_HERO_LOGON/NAME)、全量能力(SM_HERO_ABILITY)、成长(SM_HERO_LEVELUP/WINEXP/MAGIC_LVEXP)、忠诚与荣誉(SM_GLORYFEALTY)、合击进度(SM_HERO_UNIONSTATUS)、醉酒三态(共享 SM_DRINK_* 族)、以及英雄专属动作报文(SM_HERO_RUSH/LONGHIT/LASTHIT)。

英雄数据的本地容器是全局单例 `g_data.hero`(`mir2.data.hero.lua`):`roleid`、`name`、`heroType/heroRank`、`sex`、`job`、`bagSize`、`fealty/glory`、`unionState/unionProgress`、`ability(TAbility)`、`ability2(TSub2Ability)`、`ability3(TSub3Ability)`、`magicList`。所有字段都由本文档所列 SM 报文填充,客户端不自行推算。

## 详细报文说明

### CM_HERO_LOGON(1050)召唤英雄

- **时机**:控制台英雄面板点击"召唤"。前置条件:客户端检查 `g_data.hero.roleid == 0`(当前无英雄在场),否则改发 CM_HERO_LOGOUT(`mir2.scenes.main.console.btnCallbacks.lua :: handle_hero`,行 864-878)。
- **TDefaultMessage 用法**:`recog = main_scene.ground.player.roleid`(主角 roleid);param/tag/series 不设。
- **body**:无(strs/data 均不传,dataLen=0)。
- **应答与错误分支**:成功序列见 SM_HERO_LOGMAGIC(897)→ SM_HERO_LOGON(899)→ SM_HERO_NAME(898)→ SM_HERO_ABILITY(900)及背包/装备/技能下发(M9-S2)。召唤失败(如已达等级/金币条件)本树无专门失败分支代码——预期表现为收不到 SM_HERO_LOGON(未核实服务端是否有显式失败回执)。

### CM_HERO_LOGOUT(1051)收回英雄

- **时机**:①再次点击控制台"收回"按钮(btnCallbacks::handle_hero,行 870-875);②保护策略"英雄 HP/MP 低于阈值时收回":`settingLogic.missHp → heroExit`(`mir2.scenes.main.common.settingLogic.lua` 行 576-587,在 SM_STRUCK 等扣血报文处理后触发)。
- **TDefaultMessage 用法**:`recog = 英雄 roleid`(两处分别取 `g_data.hero.roleid` 与 `main_scene.ground.player.hero.roleid`)。
- **body**:无。
- **应答**:SM_HERO_LOGOUT(918)。客户端收到后无条件清空 `g_data.hero/heroBag/heroEquip`(`_data_reset` 克隆重置)并隐藏英雄头像面板——服务端必须保证收回流程最终必发此包,否则客户端英雄数据残留。

### CM_HERO_APPTARG(1105)英雄锁定目标/守卫点

三种触发入口,两种字段形态:

| 形态 | 触发点 | recog | param | tag | series |
|---|---|---|---|---|---|
| 锁定目标(带坐标) | controller.lua 行 200-212(heroLock 模式点击地面);pc.operate.lua Ctrl+W(795-800) | 目标 roleid | 目标格子 x | 目标格子 y | 0 |
| 锁定目标(仅 id) | btnCallbacks.lua 行 900-946("锁定"按钮,依次取 lock.target.skill/select/attack) | 目标 roleid | 未设 | 未设 | 0 |
| 守卫模式(无目标) | controller.lua 行 213-225(heroGuard 模式点击地面);pc.operate.lua Ctrl+Q(815-820) | 未设 | 守卫点 x | 守卫点 y | 1 |

- **时机细节**:每种形态都有 1 秒节流(`g_data.client:checkLastTime("heroLock"/"heroGuard", 1)`);锁定形态发送前会把 `g_data.hero.bNoTarget` 置 false;"锁定"按钮在无任何目标时改为 `g_data.hero:setNoTarget(true)` 且**不发任何包**。
- **body**:无。
- **应答**:无专用应答;英雄行为变化通过通用动作报文(SM_WALK/SM_HIT/SM_SPELL 等,见 M4)与 SM_HERO_HELPOP_OK(925)体现。

### CM_HERO_CHGSTATE(1107)英雄状态开关

- **时机**:控制台设置页切换"英雄自动魔法盾"开关(`btnCallbacks.lua` 行 376-385,settingKey=`autoDunHero`)。
- **TDefaultMessage 用法**:`param = 1`,`recog = enable and 1 or 0`(1=开启,0=关闭);tag/series 不设。
- **body**:无。
- **应答**:本树无对应处理分支;param 是否承载其他子状态码未核实(本树唯一取值 param=1)。

### CM_HERO_POWERUP(1108)请求英雄技能信息

- **时机**:控制台"技能"按钮(`btnCallbacks.lua :: handle_hero`,行 890-893);发送前校验 `g_data.hero.roleid ~= 0`,否则提示"您还未召唤出英雄!"并不发包。
- **TDefaultMessage 用法**:全部字段不设(全零)。
- **body**:无。
- **应答**:未核实。推测服务端以 SM_HERO_SENDMYMAGIC(904)/SM_HERO_ABILITY(900)重发响应(客户端技能页打开本身也会因这些推送而刷新,无法从代码区分)。

### CM_SAY(3030)`@RestHero` 英雄休息切换

- **时机**:控制台"模式"按钮(`btnCallbacks.lua :: handle_hero`,行 894-899):`net.send({CM_SAY}, {"@RestHero"})`——经聊天通道发送字符串 `@RestHero`(GBK)。
- **body**:`net.send` strs 布局:1 个前导 0x00 字节 + "@RestHero" 的 GBK 字节串(见 BRIEF §4)。
- **应答**:未核实(预期为某种状态回执或英雄动作变化;本树没有监听特定应答)。

### SM_HERO_LOGON(899)英雄登场

- **时机**:服务端接受召唤后下发。这是英雄一切后续交互的前提——客户端由此记录 `g_data.hero.roleid`,共享报文(模式 C)靠它归户。
- **处理位置**:`mir2.scenes.main.ground.lua :: processMsg`,行 742-765。
- **严格校验**:`getRecordSize("TNewHeroLook") == bufLen` 必须精确相等,否则整条报文被丢弃(英雄永不绑定,头像面板不显示)。TNewHeroLook 为非 packed 记录,按 BRIEF §6 对齐规则推算线上尺寸为 **40 字节**(推算值):
- **TDefaultMessage 用法**:`recog`=英雄 roleid;`param`=x,`tag`=y;`series` 低字节(Lobyte)=朝向 dir。
- **body 布局(TNewHeroLook)**:

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | int | outlook | 外观原始值 |
| 4 | record[16B] | status | TAllBodyState = 4×int 定长数组 |
| 20 | int | state | 身体状态位 |
| 24 | int | resv | 保留 |
| 28 | record[10B] | feature | TFeature,展开见下 |

TFeature(globa2.lua 行 335):

| 相对偏移 | 类型 | 字段 |
|---|---|---|
| 0 | short | race(种族;英雄为人形种族值) |
| 2 | byte | sex(客户端 `setSex(feature.sex)` 用于头像图选择) |
| 3 | byte | hair |
| 4 | short | weapon |
| 6 | short | dress |
| 8 | short | riding |

- **客户端动作**:播放 `sound.hero_login`;`map:addMsg` 创建角色实体;`g_data.hero:setRoleID(msg.recog)`、`setSex(feature.sex)`;把实体绑定为 `map.player.hero`;显示 heroHead 面板。
- **关联报文**:SM_HERO_LOGMAGIC(897)通常先于此包做出场特效(param/tag=x,y,无 body 解析);SM_HERO_NAME(898)补名字。顺序未核实为强制。

### SM_HERO_NAME(898)英雄名字

- **时机**:登场后下发(顺序未核实)。
- **处理位置**:ground.lua 行 796-801。
- **TDefaultMessage 用法**:`param`=heroType(英雄类型),`tag`=heroRank(称号等级);recog/series 未用。
- **body**:GBK 名字串(`net.str` 整体读取,a2u 转 UTF-8)。
- **消费方**:heroHead 标题、heroEquip 面板标题(panel.equip.lua ctor 直接读 `baseData.name`)。

### SM_HERO_ABILITY(900)英雄全量能力值 —— 服务端编码重点

- **时机**:召唤后初始下发;装备/升级等引起属性变化时重发(本树未见增量能力包被使用的证据,SM_HERO_SUBABILITY 901 未实现)。
- **处理位置**:`mir2.scenes.main.ui.lua :: processMsg` 行 1792-1801 → `mir2.data.hero.lua :: setAbility`。
- **与主角 SM_ABILITY(52)的关系(结论性描述)**:**不是同一消息用 series 区分**,而是两个独立 ident 承载同一结构的 body:

| 对比项 | SM_ABILITY(52)主角 | SM_HERO_ABILITY(900)英雄 |

| recog | 金币数(player:setAbility 行 166) | 忽略 |

| 解析函数 | mir2.data.player.lua :: setAbility | mir2.data.hero.lua :: setAbility |

### SM_GLORYFEALTY(960)荣誉与忠诚度

- **时机**:服务端在数值变化时推送(时机未核实)。
- **处理位置**:ui.lua 行 1802-1803 → `hero:setGloryFealty(msg.param, msg.tag)`。
- **字段语义**(由代码赋值方向确定):`param`=glory(荣誉),`tag`=fealty(忠诚度)。heroHead 显示"忠诚度: fealty/100 %",即 **fealty 为千分数**(10000=100%)。
- **body**:无。注意该消息号无 HERO 前缀但只写英雄数据,归入英雄协议。

### SM_HERO_UNIONSTATUS(923)英雄合击状态

- **时机**:合击能量/状态变化时推送。
- **处理位置**:ui.lua 行 1851-1853;随后 `console:call("btnHeroSkill","hero_upt_union")` 刷新合击按钮(widget.btnMove.lua 行 315-326)。
- **字段语义**:`recog`=unionProgress(合击进度),`param`=unionState(>0 表示可合击,按钮播放循环特效)。进度条换算:`value = 200 - unionProgress;p = clamp(value/2, 0..100)%`,推断 progress 取值范围 0~200(未核实边界)。
- **body**:无。

### SM_HERO_LEVELUP(914)英雄升级

- **处理位置**:ui.lua 行 1856-1867。
- **字段语义**:`param`=新等级(写入 ability.level);**`tag`=新背包格数**(`hero:setBagSize(msg.tag)`,并触发 heroBag 面板 reloadAll 重排格子数)。
- **body**:无。

### SM_HERO_WINEXP(915)英雄获得经验

- **处理位置**:ui.lua 行 1835-1844。
- **字段语义**:`recog`=当前累计 Exp(uint32 写入 ability.Exp);`MakeLong(msg.param, msg.tag)`=本次获得经验量(int32 拆 param 低 16 位/tag 高 16 位)。

### SM_HERO_HELPOP_OK(925)服务端强制取消英雄辅助

- **处理位置**:ground.lua 行 821-830。
- **分支**:
  - `recog == 1`:若客户端处于 heroLock 状态则强制 `toggleHeroLock()` 取消锁定,并把控制台按钮置为未选中;
  - `recog == 2`:若处于 heroGuard 状态则强制取消守卫。
- **body**:无。这是服务端否决客户端辅助模式的唯一通道(如目标已失效、区域禁止等,具体策略未核实)。

### 共享醉酒三态:SM_DRINK_STATUS(2816)/SM_DRINK_DRUG_STATUS(2817)/SM_DRINKEXP_STATUS(2818)

- **区分方式(模式 C)**:同一消息服务主角与英雄,`msg.recog == g_data.player.roleid` 走主角,`msg.recog == g_data.hero.roleid` 走英雄(ground.lua 行 692-741)。

- **body**:无。英雄侧更新后同时刷新 heroEquip "state" 页与 heroHead(醉酒度进度条)。

### 英雄专属战斗动作:SM_HERO_RUSH(4)/SM_HERO_RUSHKUNG(5)/SM_HERO_LONGHIT(25)/SM_HERO_LASTHIT(26)

- **处理位置**:ground.lua 行 325-347(RUSH 族)与行 349-358(近战族);动作播放 role.role.lua 行 1007-1028。
- **布局**:与主角同名族完全一致——RUSH 族 body 为 TCharDesc(16B:int feature + TAllBodyState)或 TNewCharDesc(uint outlook + TAllBodyState + TFeature),按 bufLen 二选一;`recog`=英雄 roleid,`param/tag`=x/y,`Lobyte(series)`=朝向。近战族无 body,`recog/param/tag/series` 同义。
- **复合形式**:SM_PHYSICAL_ATT(hitMode 复用包,详见 M4-S3)中 `hitMode==1011` 映射为 SM_HERO_LONGHIT、`hitMode==1012` 映射为 SM_HERO_LASTHIT(ground.lua 行 379-381)——服务端二选一即可。
- **归户**:这些报文按 recog 寻找地图上的英雄实体;`msg.recog ~= self.player.roleid` 恒成立(是英雄不是主角)。
- 动作效果差异仅是表现(HitEffect twn1/twn2,magicId=34),协议层无额外字段。

## 服务端实现要点

1. **召唤是状态机起点**:必须按"特效(897)→ 登场(899)→ 名字(898)→ 能力(900)→ 背包/装备/技能(902/903/904,M9-S2)"补齐数据流;其中 **SM_HERO_LOGON 的 bufLen 必须恰好等于 TNewHeroLook 尺寸**,否则客户端静默丢弃、英雄永不绑定,之后所有按 recog 归户的共享报文全部失效。
2. **roleid 一致性**:CM_HERO_LOGOUT、APPTARG 应答后的动作报文、SM_STRUCK 等共享包的 recog 都必须使用 SM_HERO_LOGON 下发的同一个英雄 roleid;客户端用它匹配 `map.player.hero`。
3. **收回必达**:无论主动收回还是保护触发,只要英雄离场就发 SM_HERO_LOGOUT(918),否则客户端 `g_data.hero.roleid` 残留,后续"召唤"按钮会走 LOGOUT 分支形成死锁。
4. **英雄 AI 全在服务端**:客户端不会替英雄走路/攻击/施法;英雄行为完全由服务端下发通用动作报文表达。CM_HERO_APPTARG 只是意图输入(锁定的目标 id + 参考坐标;守卫模式 series=1 且无 recog)。
5. **升级双载荷**:SM_HERO_LEVELUP 同时携带新等级(param)与新背包格数(tag)——扩容英雄背包的唯一途径就是这条包(M9-S2 的 SM_HERO_BAGITEMS.series 也会带一份当前格数)。
6. **无阻塞等待**:本树没有对任何英雄报文调用 `net.setWaitMsg`,英雄链路不存在"扣包卡死"风险;但仍建议按序推送,面板刷新依赖到达顺序的表现(未核实乱序下的全部表现)。
7. **未核实项汇总**:CM_HERO_POWERUP 的应答;`@RestHero` 的服务端回执;SM_HERO_SUBABILITY(901)布局;SM_GLORYFEALTY 推送时机;unionProgress 边界;召唤失败是否有显式失败包。
