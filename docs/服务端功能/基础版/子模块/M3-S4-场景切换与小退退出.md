# M3-S4 场景切换与小退退出

> 所属主模块:[M3-游戏世界与场景](../主模块/M3-游戏世界与场景.md)

## 功能概述

覆盖游戏内四种"离开当前画面"的路径与场景级控制消息:

1. **切图**:走传送点后服务端发 SM_CHANGEMAP,客户端原地换图(不回选人);
2. **小退**:`scene:smallExit()` 发 CM_SOFTCLOSE,服务端回 SM_CHR_LIST 把玩家送回角色选择;
3. **大退**:`scene:bigExit()` 清理本地数据并 `common.gotoLogin` → `net.close()` 主动断线(无退出报文);
4. **异常断开/顶号/排队/维护/重连失败**等控制消息(scene.processMsg 场景级分支)。

## 详细报文说明

### SM_CHANGEMAP(634)— 游戏内切图

- **时机**:玩家踩中服务端判定的传送点(客户端本地 doorPoint.txt 只做表现辅助,判定权在服务端);也用于 GM 移送等。
- **字段**:`msg.param = 新 x`,`msg.tag = 新 y`;recog 未使用。
- **body**:GBK 字符串;`net.strs(buf)` 按 `/` split,**strs[1] 为新地图 ID**(`ground.lua :: SM_CHANGEMAP 分支`)。注意代码随后把整段原始串(含 `/` 后内容)传给了 `helper:enterMap(net.str(buf))`,引导脚本拿到的是未分段原串——服务端应保证 `/` 后不带额外段,或接受引导脚本收到脏串的现状。
- **客户端行为**(与 SM_NEWMAP 的差异):销毁旧 map → 用 strs[1] 新建 map → **保留自己的 roleid/feature/state/名字/hitSpeed 重建 player 对象**(不从服务器取描述)→ 恢复 HP 显示 → 关闭 npc/bigmapOther/stall 面板 → 小地图 reload、寻路重算。**不再等待 SM_LOGON**,也不重设 setWaitMsg。
- **应答链**:切图后服务端通常需要补发:SM_MAPDESCRIPTION(54)、SM_AREASTATE(708)(若状态变化)、SM_SAFE_ZONE_INFO(4230)(若目标图安全区不同——注意该包是全量表,重发即可)、以及新图的 AOI 对象流。这些都不再有等待阻塞(SM_NEWMAP 路径才有),顺序自由。

### CM_SOFTCLOSE(1009)— 小退请求

- **时机**:
  - 设置菜单调用 `scene:smallExit()`(`smallExitState=true` 后发送);
  - Android 返回键确认退出(`scene.ctor` 内,发送后直接 os.exit);
  - 反外挂检测失败 `plugCheck.kill`(弹窗后 os.exit)。
- **字段/body**:全部为空。
- **期望应答**:**SM_CHR_LIST(4010)**,且 `recog==1` 才被接受(`scene.enterSelectScene`)。收到后:

```
enterSelectScene(msg,buf,bufLen):
  recog==1 →
    net.remove(ui) net.remove(ground)          # 摘除分发器
    g_data.select:receiveChrs(...)             # 解析角色列表
    clearGameData()                            # net.clearMsgs + g_data cleanup + 音频/资源清理
    reconnect 流程: 等 5s → isLoginQueue ? 进选人界面
                    : 发 CM_SELCHR(4017)+当前角色名 → 进 notice 公告场景(自动重回游戏)
    普通 smallExit:net.remove(self) → 切到 select 选人场景
```

- **SM_CHR_LIST 字段**(小退与选人共用解析,`data.select.receiveChrs`):

| 字段 | 含义 |
|---|---|
| recog | 成功标志,**必须为 1** |
| param | 角色数量 n |
| tag | 当前选中角色索引(**0 基**,客户端 selectIndex=tag+1) |

- **body**:n × TMirCharinfoEx(22B:string15 name,hair/job/sex 各 1B,short level)或旧格式 TMirCharinfo(20B,level 为 byte);按 `bufLen >= 22*n` 自动二选一。level 展示时 hair≠1 会并入高位(`bor(level, (hair-1)<<8)`),服务端保持常规填法即可。
- **错误分支**:recog~=1 整包忽略;不发 SM_CHR_LIST 则客户端停留在"正在退出.."进度条画面(clearGameData 已执行,main_scene=nil)。

### 大退 bigExit — 无协议

`scene:bigExit()` = `clearGameData()` + `common.gotoLogin({logout=true})`;后者执行 **`net.close()`**(主动关闭 TCP)再切登录场景。**没有任何"退出告知"报文**;服务端靠连接断开感知。clearGameData 中 `g_data.login.reconnectState` 为真时显示"正在重连中.."(配合重连流程,不回登录)。

### 断线与重连(scene.socketEvent / reconectFuc)

- socket 事件 status==3(连接关闭/超时中断)或 ==2(连接失败)→ 弹"确定重连?"框:确定 → `reconnect=true; g_data.login.reconnectState=true` → `net.connect(g_data.login.recIP, recPort, self, recSession)`(**复用会话 id 重连**,三值由登录流程存于 login.scene.lua,归 M1);取消 → bigExit。
- `onLoseConnect`(网络切换为不可达,baseScene 监听 CONNECTIVITY_ACTION)同样弹重连框。
- 重连成功后服务端发 **SM_LOGIN(4003)**,main/notice 场景分支回 **CM_RECONNECT(4031)**+`g_data.reconnctID` 票据串(body 为该字符串,GBK);随后服务端校验票据恢复会话,重新走进图序列(SM_NEWMAP…)。票据来源:TLoginIdResult2.reconnectID(SM_LOGIN_AUTH param=1 时下发,M1/M2)。
- **11706**(裸数值分支,globa1 无符号名):弹"重连失败,请重新登陆"→ bigExit。服务端在票据失效时应使用此 ident。

### 顶号与在线冲突

- **SM_OUTOFCONNECTION_KICKOUT(4040)**:弹"已经被其他用户踢下线",用户可选重连(同上流程)。服务端语义:同账号 elsewhere 登录成功后向旧会话推此包并断开。
- **SM_OUTOFCONNECTION(4018)**:main 场景分支为空——**发了没有可见效果**;要踢人请用 KICKOUT 或直接断线(如实记录)。
- **SM_LOGIN_ALREADY_ONLINE(4041)**(recog==1):弹"此账号目前在线,是否强行登录?";选择后无论强弱登都先回 **CM_LOGIN_ALREADY_ONLINE(4041,param=1 强登/0 取消)**;param=1 时用先前缓存的 roleInfo(见下)直接 enterSelectScene 进游戏。recog~=1:不询问,直接用缓存 roleInfo 进入。缓存的 roleInfo 来自本场景此前收到的 SM_CHR_LIST(`smallExitState=false` 路径只缓存不跳转)——即该机制假设服务端在通知冲突**之前已下发过一次 SM_CHR_LIST**;服务端必须遵守这个先后,否则强登时无列表可用。

### 排队与其他

- **SM_LOGIN_QUEUE(4332)**:param=队列位次,tag=队列人数,series=预计秒 → `login:setQueueData`;置 `isLoginQueue=true`(影响小退重连路径改走选人界面而非自动 CM_SELCHR)。UI 展示归 M1/M2,此处存档字段。
- **SM_SELCHR_ERR(4042)**:"服务器维护中,请稍后再试"→ bigExit。服务端在选角不可用时下发。
- **SM_New_Version(889)**:分支体为空(忽略)。
- **SM_JPUSH_SETALIAS(4498)**:body=别名串 → jpush.setAlias(移动端推送别名绑定;Win32 无 jpush 全局时此分支不会被触达)。

### 回城请求:CM_CLICK_BACKHOME(4633)

- **时机**:点击回城按钮(`common.backHome`,`common.lua` 行 1351):**5 秒节流**(`checkLastTime("common.checkAmulet", 5)`,过快提示"操作太快.");发出后停止挂机与寻路。
- **字段/body**:全部为空(无参无 body)。
- **应答**:无专用回执——回城成功以 SM_CHANGEMAP(634) 送达为准(服务端把玩家移回绑定地图并走切图流程);失败反馈未见专用报文(未核实,可复用 SM_MENU_OK 类提示或直接不下发)。

### 反外挂联动(plugCheck)

`plugCheck.kill` 发 **CM_SOFTCLOSE** 后强制退出(错误码 speed=-1/timeOut=1/initErr=2/sendTimeLong=3)。但其探测循环依赖的 `CM_SPEEDHACKUSER(1042)` 走的是废弃桩 `net.send_old`(只打日志不出网)、`plugCheck.verify(serverTime)` 全工程无调用点——**整条反加速链路在 rebuilt-src 中是死代码**,服务端无需实现对应探测报文(如实记录)。另外 **SM_TIMECHECK_MSG(810)** 常量存在但无任何处理代码。

## 服务端实现要点

1. **切图最小集**:SM_CHANGEMAP(param/tag=落点,body=地图 ID 串)之后,按需补 SM_MAPDESCRIPTION/SM_AREASTATE/SM_SAFE_ZONE_INFO 与新视野 AOI;不要重发 SM_LOGON(会因无等待而立即处理,重复创建自己)。
2. **小退闭环**:CM_SOFTCLOSE → 必须回 SM_CHR_LIST(recog=1,param=n,tag=选中索引,body=Ex 格式列表);客户端随后要么停选人界面,要么(重连态)5 秒后自动 CM_SELCHR+角色名回到公告场景。若服务端不支持小退回列表,也应至少断开连接让客户端走大退 UI,否则卡进度条。
3. **强登协商顺序**:SM_CHR_LIST 先行缓存 → SM_LOGIN_ALREADY_ONLINE(recog=1)询问 → 收 CM_LOGIN_ALREADY_ONLINE(param) 决定踢谁/放行;param=0 表示放弃强登(旧会话保留)。
4. **踢下线**用 SM_OUTOFCONNECTION_KICKOUT(4040)+断开;SM_OUTOFCONNECTION(4018) 在本客户端是 no-op。
5. **重连**:支持 reconnectID 票据(SM_LOGIN→收 CM_RECONNECT→校验→重走进图序列);失败回 11706。重连 TCP 连接的 dataIndex=sessionID(M1 约定)。
6. 大退/杀进程无任何报文,一切以 TCP 断开为准;心跳缺失超时(LM_PING 仅 DEBUG 构建)不能作为唯一存活判据,(未核实生产构建是否启用 DEBUG 心跳)。
