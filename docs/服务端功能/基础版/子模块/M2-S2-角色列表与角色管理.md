# M2-S2 角色列表与角色管理

> 所属主模块: [M2-选区与角色管理](../主模块/M2-选区与角色管理.md)

## 功能概述

覆盖正式服 TCP 连接建立后的两段流程:

1. **进选人前的握手**(由 `login` 场景代为处理):`CM_SELECT_SERVER(4002)` 选区组 → 按 `SM_SELECT_SERVER(4002)` 给出的 ip/port/sessionID 建立游戏 TCP 并完成动态加密握手 → ticket 鉴权(`SM_LOGIN`/`CM_LOGIN_AUTH`/`SM_LOGIN_AUTH`)→ 服务端推角色列表并下发"进入选人"信号。
2. **选人场景**(`select`):角色列表刷新、创建/删除/查询删除/恢复角色、进入游戏、密保验证、排队提示、被顶号/断线重连、跨服转移。此场景内客户端开启 `net.match` 白名单门控,**只可能发出 9 种上行消息**(见主模块共享点 §1)。

重要事实:本客户端 **从不发送 `CM_QUERYCHR(100)`**(常量已定义但全工程零引用)。角色列表完全依赖服务端在鉴权后**主动推送** `SM_CHR_LIST(4010)`。

## 详细报文说明

以下"body 偏移"均从 TDefaultMessage 之后的载荷第 0 字节起算;记录尺寸按 BRIEF §6 对齐规则核算(char*/string 声明长 N 占 N+1 字节,首字节=内容长度 L)。

### 0. 进入选人前的握手(login 场景代办)

来源:`mir2.scenes.login.scene.lua :: processMsg`(行 200-249、250-299、335-340、394-417)、`mir2.scenes.login.door.lua`、`mir2.single.net.lua :: net.connect/net.handler`。

#### CM_SELECT_SERVER(4002)

- **时机**:login 场景收到 `SM_SERVER_LIST(4001)` 并让玩家选定区组后自动发送。
- **TDefaultMessage 用法**:`recog=-1, param=1, series=0, tag=def.useIGW(=1)`(`login.scene.lua:207-215`)。
- **body**:`0x00 前导 + GBK 区组名`(strs 单条)。
- **应答** SM_SELECT_SERVER(4002):
  - **失败** `recog == 0`:`series=2` 你选择的服务器满员 / `series=3` 维护中 / `series=4` 配置的区组ID或服务器名字不一致(行 216-228)。
  - **成功** `recog ~= 0`:全部连接参数来自 TDefaultMessage 字段——
    - `ip = int2ip(MakeLong(msg.tag, msg.series))`(tag=低 16 位,series=高 16 位,拼成 uint32 小端语义的点分 IP);
    - `port = msg.param`;`sessionID = msg.recog`;
    - body 再按记录解码:`TSelectServerMsg`(20B);若剩余 ≥ `TSelectServerMsg2` 尺寸(36B)则整段按 Msg2 重解一次(行 230-244)。
  - 随后 `net.connect(ip, port, loginScene, sessionID)`:新连接握手帧(cmd=24)的 `dataIndex=sessionID`(`net.lua :: net.connect` 行 22-32;BRIEF §3)。

**TSelectServerMsg body 布局**(20 字节,非 packed;客户端仅透传保存到 `g_data.login.serverMsg`,连接参数不取自此记录):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | int32 | areaID | 区 ID |
| 4 | int32 | groupID | 区组 ID |
| 8 | byte | sdoa | 未使用 |
| 9 | byte | other1 | 未使用 |
| 10 | byte | other2 | 未使用 |
| 11 | byte | other3 | 未使用 |
| 12 | char*7(8B) | suffix | 定长 GBK 区(长度字节+≤7 字节) |

TSelectServerMsg2(36B)= 上述 20B + `serverName char*15`(偏移 20,16B)。注意:此分支直接从 buf 第 0 字节解记录,**服务端不要加前导填充字节**(代码未跳过任何字节;(线上样本未核实))。

#### SM_LOGIN(4003) → CM_LOGIN_AUTH(4004)(login 场景版)

- 服务端在新连接上发 `SM_LOGIN`,login 场景回 `CM_LOGIN_AUTH`:`recog=def.MIR_VERSION_NUMBER(131532307), param=net.platformCode()=2`,strs=`{ticket, "", def.gameType("gametea"), "mobile-mac-address"}`(行 267-277)。细节归 M1,列出仅为时序完整。

#### SM_LOGIN_AUTH(4004,param=1)

- **body 二选一**,客户端按长度判定:`ret1:size()(42) < bufLen` 时解析为 `TLoginIdResult2`,否则 `TLoginIdResult`(行 286-299;select/notice/reconnect 场景同款逻辑)。

TLoginIdResult(packed,42B):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | char*20(21B) | ptID | 通行证 |
| 21 | char*20(21B) | digitID | 数字 ID |

TLoginIdResult2(packed,87B):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | char*20(21B) | oldMsg | 兼容旧结构 |
| 21 | char*20(21B) | serverName | 服务器名 |
| 42 | int32 | areaID | |
| 46 | int32 | groupID | |
| 50 | string36(37B) | reconnectID | **重连凭证**:取出后存 `g_data.reconnctID`,后续 CM_RECONNECT 上行原样带回 |

- `param == 2`:客户端不做任何事(含义未核实)。
- 鉴权成功后 login 场景只隐藏登录层,**不主动切场景**——切场景由下一条 `SM_LOGIN_ALREADY_ONLINE(recog≠1)` 驱动。

#### SM_CHR_LIST(4010)(login 阶段的第一次)

- login/notice/reconnect 场景收到后仅缓存原始报文到 `g_data.login.roleInfo = {msg,buf,bufLen}`(`login.scene.lua:335-340`),供顶号分支复播。

#### SM_LOGIN_ALREADY_ONLINE(4041,recog≠1)——进入选人的信号

- `recog != 1` 时:显示开门动画层并立即用缓存的 roleInfo 解析角色(`showLayer("door")` + `g_data.select:receiveChrs(...)`),动画播完 `net.remove(loginScene)` 后 `game.gotoscene("select")`(`login.scene.lua:414-417`、`door.lua`)。
- 即:**正常进入选人的最后一步是服务端发一条 `SM_LOGIN_ALREADY_ONLINE` 且 `recog ≠ 1`(如 0)**,此前必须已有 `SM_CHR_LIST` 到达(否则 `roleInfo.msg` 取值为空会报错)。
- `recog == 1` 则是"账号在线"询问,见下文 §重连与顶号。

### 1. 角色列表:SM_CHR_LIST(4010) 与 g_data.select:receiveChrs

来源:`mir2.scenes.select.scene.lua :: processMsg`(行 884-901)、`mir2.data.select.lua :: receiveChrs`(行 18-45)。

- **触发时机**:select 场景内每次收到都走本分支;这是角色变动(建/删/恢复)后唯一的列表数据更新途径。
- **TDefaultMessage 用法**:
  - `param` = 角色数量 N;
  - `tag` = 服务端指定的"上次选中下标",客户端执行 `selectIndex = tag + 1`;
  - `recog` 必须 **== 1**,否则 select 场景直接忽略该包(行 893);reconnectState 下例外:无论 recog 都收进缓存(行 885-892)。
- **body**:N 条连续记录,**无前导填充**。记录版本自适应:

```lua
local temp = bufLen >= infoEx:size() * count and infoEx or info   -- data.select.lua:23
```

即 `bufLen >= N×22` 用 `TMirCharinfoEx`(22B),否则用 `TMirCharInfo`(20B)。

TMirCharInfo(20 字节,非 packed):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | string15(16B) | name | 首字节=L,后 L 字节 GBK 角色名 |
| 16 | byte | hair | 发型;兼作等级高位载体(见下) |
| 17 | byte | job | 0=战士 1=法师 2=道士 |
| 18 | byte | sex | 0=男 1=女 |
| 19 | byte | level | 等级低字节 |

TMirCharinfoEx(22 字节,非 packed;level 升为 short,19 字节处为对齐填充):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | string15(16B) | name | 同上 |
| 16 | byte | hair | 同上 |
| 17 | byte | job | 同上 |
| 18 | byte | sex | 同上 |
| 19 | byte | (填充) | 对齐填充,建议填 0 |
| 20 | int16 | level | 小端 |

- **等级合成规则**(`receiveChrs` 行 27-31):`hair ~= 1` 时显示等级 `= level | ((hair-1) << 8)`;`hair == 1` 直接用 level。服务端若想让旧短记录支持 >255 等级,可把高 8 位放 hair(此用法系从代码反推,是否符合作者意图未核实);常规实现保持 `hair=1`、level 即真实等级即可。
- **UI 刷新条件**:`recog==1` 分支里才调用 `getRoleListSuccess()` 重建模型(行 900-901)。
- **等待语义**:无 setWaitMsg;不推送则列表维持上次数据。

### 2. 创建角色:CM_NEWCHR(4012) / SM_NEWCHR(4012)

来源:`mir2.scenes.select.scene.lua :: showCreate`(行 307-437,发送在 420-427)、`:: processMsg` SM_NEWCHR 分支(行 868-883)。

- **触发时机**:「创建角色」按钮(上限校验:普通 ≤4 个 `roleUpperLimit`,IS_PLAYER_DEBUG ≤20)→ 填名、选职业(1~3)、选性别(1~2)→「确定」;名字为空本地拦截。发送后面板立即关闭。
- **TDefaultMessage 用法**:recog/param/tag/series 全部缺省(=0)。
- **body**:无 strs,`data = getRecord("TMirCharInfo", {hair=1, name=输入名, job=workIndex-1, sex=sexIndex-1})`,即 `0x00 前导 + TMirCharInfo(20B)`,dataLength=21。字段布局见 §1 表;其中 `hair 固定写 1`,`job=职业-1`(0战士/1法师/2道士),`sex=性别-1`(0男/1女),`level=0`。
- **应答** SM_NEWCHR(4012),按 `param` 分支(行 868-881):

| param | 客户端文案/行为 |
|---|---|
| 2 | 「这个名字已存在」 |
| 3 | 「你最多只能为一个帐号设置2个角色」 |
| 4 | 「角色创建失败\n角色名中不能包含特殊字符…最少两个汉字或4个英文/数字」 |
| 5 | 「你所创建的角色总数已达上限」 |
| 6 | 「跨服申请中，无法新建、删除、恢复角色」 |
| 7 | 「跨服不允许新建、删除、恢复角色」 |

来源:`clickBtn(5)`(行 163-166,先置 `self.returnBtn=true`)、排队取消按钮(行 819-823)、SM_SELCHR_EXIT 分支(行 979-982)、`common.lua :: gotoLogin`(行 1346)。

### 8. 密保验证:SM_REQUIRE_MIBAO(4020) → CM_SUBMIT_MIBAO(4020) → SM_VAILDATE_PPWD(4011)

来源:`mir2.data.security.lua :: setLoginBit`(行 3-9)、`login.scene.lua:345-346`、`select.scene.lua :: showSecurity`(行 573-657,发送在 615-631)、SM_VAILDATE_PPWD 分支(行 958-959)。

- **弹出时机**:login 阶段服务端下发 `SM_REQUIRE_MIBAO(4020)`,body=4 字节,每字节一个"要求输入的密保位序号"(经 `net.strSplitWithLen(buf,1,4)` 拆成 `g_data.security.loginBit`);进入 select 场景后 `onEnterTransitionFinish` 检测到 loginBit 即弹全屏密保面板(输入指定 4 位数字)。

### 11. 跨服转移:SM_ACK_TRANSFER_AREA(4028)

来源:行 960-976;记录 `mir2.def.globa2.lua:3577-3611`(packed)。

- **触发时机**:服务端主动下发(客户端在本模块内没有对应的请求消息;(何种 CM 触发未核实,推测为跨服排队/申请链路,M8 类模块))。

## 服务端实现要点

1. **必须主动推列表**:鉴权完成后依次 `SM_CHR_LIST(4010, recog 必须置 1, param=数量, tag=选中下标)` → `SM_LOGIN_ALREADY_ONLINE(4041, recog≠1)`。顺序不能颠倒(后者触发时要用前者缓存),漏掉任何一个玩家永远停在 login 开门之前。
2. **每次角色变动后再推一条 SM_CHR_LIST**:SM_NEWCHR/SM_DELCHR/SM_RECOVERCHR 本身不携带角色数据,客户端也不因它们重建数据;没有后续 SM_CHR_LIST(recog=1),界面数据不变。
3. **record 型下行不加前导填充**(SM_CHR_LIST/SM_SELECT_SERVER/SM_LOGIN_AUTH 从第 0 字节解码);唯一例外 SM_ACK_TRANSFER_AREA 要求 body 比 81 字节记录恰好多 1 字节。
4. **GBK**:角色名、reconnectID 等线上文本一律 GBK;name 字段是"长度字节+内容"的变长串,超长截断由服务端负责(声明容量 15 字节)。
5. **param 错误码表必须按 §2/§3/§5/§6 数值实现**,客户端按数值匹配文案;未定义的 param 一律当"成功/无提示"处理,所以**失败码绝不能用表外值**。
6. **必须回包否则卡住的点**:SM_SELECT_SERVER(不回则停在选区遮罩)、SM_LOGIN_AUTH(不回则不开门)、SM_LOGIN_ALREADY_ONLINE(recog≠1,不回则不切选人)、SM_CHR_LIST(不回则空列表且顶号分支崩溃风险)、SM_SELCHR(不回则进不了游戏)、SM_SELCHR_EXIT(不回客户端也会自行 net.close 回登录,属宽松项)。
7. **选人阶段上行只有白名单 9 条**(主模块共享点 §1);其余 CM 在此场景会被客户端本地丢弃,服务端不必防御性处理未知流量。
8. **SM_RECONNECT 下行别用 4031**(运行时常量=802,4031 无人处理);CM_RECONNECT 上行的 strs 就是 TLoginIdResult2 里发出去的 reconnectID,服务端需能凭它恢复会话。
9. 密保链路(SM_REQUIRE_MIBAO→CM_SUBMIT_MIBAO→SM_VAILDATE_PPWD)的"通过后推进"在本客户端无可见路径(SM_VAILDATE_PPWD 空处理、面板无关闭调用),实现时以实测为准(未核实)。
