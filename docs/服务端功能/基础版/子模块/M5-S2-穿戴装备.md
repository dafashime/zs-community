# M5-S2 穿戴装备

> 所属主模块:[M5-物品与装备](../主模块/M5-物品与装备.md)

## 功能概述

玩家把背包物品穿到装备位(CM_TAKEONITEM)、从装备位脱回背包(CM_TAKEOFFITEM)的完整握手;穿戴结果引发的外观特征变更(SM_FEATURECHANGED / TFeature);进图时已装备列表下发(SM_SENDUSEITEMS);查看他人装备(CM_QUERYUSERSTATE → SM_SENDUSERSTATE);密保/锁定装备(CM_LOCK_UNLOCK_EQUIP 族);以及装备耐久变化与 NPC 修理报文(CM_MERCHANTQUERYREPAIRCOST / CM_USERREPAIRITEM 族)。
英雄镜像(CM_HERO_TAKEON/CM_HERO_TAKEOFF 及对应 SM_HERO_*)布局完全同构,归 [M9](../主模块/M9-英雄系统.md);本文件在相应条目标注差异。

## 详细报文说明

### 1. CM_TAKEONITEM(1003)——穿戴

- 时机:双击背包中"可穿戴"物品(stdMode 能被 `getTakeOnPosition` 映射),或拖到装备面板某格(`panel.equip.putItem` → `item:use(putIdx)` 可指定目标位)。
- 发送前本地预检(`item.lua :: canUseEquip`,失败**不发**):need=0 等级 /1 maxDC /2 maxMC /3 maxSC /5 声望;stdMode=4 书按 shape 校验职业且学习等级=Word(duraMax)。服务端必须重复全部校验(客户端检查可被绕过)。
- 字段:

  | 标头 | 值 | 说明 |
  |---|---|---|
  | recog | 物品 MakeIndex | |
  | param | 目标装备位 U_* | 缺省由 getTakeOnPosition(stdMode) 决定;戒指(7/8)与手镯(5/6)"先空位、再左右交替";玩家指定格则用指定值 |
  | tag / series | 不填 | |

- strs:body = {物品名}(GBK;net.send 组装:名称 + 结尾占位字节)。服务端应以 makeIndex 为准,名字仅作对账。
- 客户端乐观扣减:`bag:use("take", …)` 把物品移入暂存(同类操作 5s 防抖,bag.lua:507-543),并从背包面板移除。
- 英雄差异:来源为 heroBag 时改发 **CM_HERO_TAKEON**,其余一致(M9)。

### 2. SM_TAKEON_OK(615)

- 时机:服务端完成穿戴校验并落库后。
- 字段/body 双形态(ui.lua 582-595 行):
  - 若 `bufLen == getRecordSize("TFeature")`(=10):body = TFeature,**packed,恰 10 字节**,无 padding:

    | 偏移 | 类型 | 字段 | 说明 |
    |---|---|---|---|
    | 0 | short | race | 外观种族/基础体型号 |
    | 2 | byte | sex | 性别(0 男/1 女) |
    | 3 | byte | hair | 发型(客户端显示时 +438 偏移取资源) |
    | 4 | short | weapon | 武器外观 looks |
    | 6 | short | dress | 衣服外观 looks |
    | 8 | short | riding | 坐骑外观 looks |

  - 否则:`recog` 视为旧式 int32 打包外观(MakeLong 型 feature),直接喂 changeFeature。**推荐服务端始终带 10 字节 TFeature**(旧式 int 无法表达 weapon/dress/riding 全量)。
- 后续数据一致性:物品本体移动由通用增量表达——通常服务端随后应发 SM_DELITEM(recog=MakeIndex,param=0)(若此前未随 TAKEON 流程隐式删除)与装备侧刷新。注意:**客户端已在收到 OK 时自行把物品放入 g_data.equip[param 位]**(`bag:useEnd("take",true)` → equipData:setItem(where,item)),此时不再需要对该物品补发 SM_UPDATEITEM;但其它观察者的外观同步走广播 SM_FEATURECHANGED(§4)。(旧服务端是否还追加 SM_UPDATEITEM 未核实;多发一条亦无害,匹配规则见 S1 §5。)
- 负重变化可随后发 SM_WEIGHTCHANGED(622)。

### 3. SM_TAKEON_FAIL(616)——错误码表

recog 为负数错误码(ui.lua 603-631 行,完整表):

| recog | 文案 | 服务端语义 |
|---|---|---|
| -1 | 该物品获得后自动锁定,锁定期过后才可正常使用 | 锁定期装备 |
| -2 | 穿戴位置不正确 | param 与 stdMode 不符 |
| -3 | 二级密码锁定状态不能更换装备 | 二级密码 |
| -4 | 密保锁定 | 密宝绑定 |
| -6 / -9 | 装备基础条件不满足 | need/needLevel 类 |
| -7 | 超重 | wearWeight/handWeight 超限 |
| -8 | 声望不足 | need=5 |
| -10 / -11 | 职业不满足 | 职业/书 shape |
| -12 | 不能穿戴 | 兜底 |
| 其他 | 未知错误 | — |

(-5 无映射。)客户端收到后把物品放回背包(useEnd false 回滚)。body 无。

### 4. SM_FEATURECHANGED(41)——外观变更广播

- 时机:任何角色(含自己)外观变化:穿戴/脱下武器衣服、换发型、骑乘上下等。服务端发给可见范围内玩家。
- 字段:`recog` = roleid;`series` 参与状态拼装(state = MakeLong(series,0),高位含义归 M3 对象状态)。
- body 双形态(ground.lua 146-160 行):
  - `bufLen == 10`:TFeature(packed,字段表同 §2);
  - 否则:feature = MakeLong(param, tag)(旧式 int 外观)。
- 与 SM_TAKEON_OK 的关系:OK 只修正本人视角;其他玩家的画面更新靠这条广播。**同一事件两包都发是常态**。

### 5. CM_TAKEOFFITEM(1004)/ SM_TAKEOFF_OK(619)/ SM_TAKEOFF_FAIL(620)——脱下

- CM_TAKEOFFITEM 字段:`recog`=MakeIndex,`param`=当前装备位(params.idx),strs={物品名}。
- **5 秒防抖**(任务点名项):`g_data.equip:takeOff` 中,若上一件仍在脱下暂存且距上次 <5 秒,直接忽略本次点击**不发消息**(`mir2.data.equip.lua:122-137`)。即客户端天然限制脱衣频率 ≤1 次/5s;英雄侧 g_data.heroEquip 同构。
- SM_TAKEOFF_OK:body 口径与 SM_TAKEON_OK 相同(bufLen==10 时解析 TFeature 刷新外观,否则用 recog 旧式 int)。客户端 `equip:takeOffEnd(true)` 清空暂存(物品视为进入背包——背包侧新实例由服务端以 SM_ADDITEM 下发;未核实旧服务端是否复用原 makeIndex,建议保留原 makeIndex 以便客户端 delItem 匹配)。
- SM_TAKEOFF_FAIL:四标头不读;客户端把暂存物品放回**原装备位**(setItem(takeOffing.params.where,…))并刷新面板。

### 6. SM_SENDUSEITEMS(621)——已装备全量

- 时机:进图初始化(与 SM_BAGITEMS 平行);也可在任何时刻做权威重同步。
- body:TClientEquip 连续数组(`mir2.data.equip.lua :: set`,`while bufLen>0` 循环,**无数量前缀**)。单条 = int nPos + TClientItem。
- nPos 取值 U_DRESS(0)…U_XueYu(16)(主模块 §2.7)。空槽位不要发(客户端 items 表按出现的 nPos 填充)。
- 英雄版:SM_HERO_SENDUSEITEMS(M9)。

### 7. CM_QUERYUSERSTATE(82)/ SM_SENDUSERSTATE(751)——查看他人装备

- CM_QUERYUSERSTATE:点击其他玩家触发(pc.operate.lua 761-778 行;widget.lock.lua 同款):`recog`=对方 roleid,`param`=对方 x,`tag`=对方 y;节流 1s("你查看太快了!!!")。常伴随 CM_QUERY_TITLE(封号查询,归 M10 称号域)连发。
- SM_SENDUSERSTATE body = `TUserStateInfo`(**packed**,def.globa2:2914):

  | 偏移 | 类型 | 字段 | 尺寸 | 说明 |
  |---|---|---|---|---|
  | 0 | int | feature | 4 | 旧式打包外观(int) |
  | 4 | char*[15] | userName | 16 | 定长 GBK 区 |
  | 20 | byte | nameColorIndex | 1 | 名字颜色索引 |
  | 21 | byte | milrankSW | 1 | 军衔开关(未消费细节) |
  | 22 | byte | b2 | 1 | 保留 |
  | 23 | byte | vipFlag | 1 | VIP 标记 |
  | 24 | char*[15] | guildName | 16 | 行会名 |
  | 40 | char*[15] | clanName | 16 | 战队名(==" 的英雄" 特判英雄页签) |
  | 56 | array[16] of TClientItem | userItems | 16×(16+4n) | 按 U_* 位序;**空槽也要发**,客户端以 Index==0 跳过(equipOther.lua 134-158 行) |

  总尺寸 = 56 + Σ16 件物品尺寸。

### 8. 装备锁(CM_LOCK_UNLOCK_EQUIP 1084 / SM_LOCK_EQUIP_STATE 1201 / SM_LOCKEQUIP 689)

- CM_LOCK_UNLOCK_EQUIP:装备面板右上"密保"按钮,3s 点击节流 + 服务器解锁倒计时判断后发送,**无任何标头/body 字段**(panel.equip.lua 246-281 行)。
- SM_LOCK_EQUIP_STATE(common.setLockEquipState):`recog`=服务器解锁时间戳(epoch 秒,参与剩余时间计算),`param`=1 已锁定(按钮置灰提示)/2 已解除锁定。body 无。
- SM_LOCKEQUIP(common.setBindEquipState,param 分支文案):param<9 且 recog>0 时显示 lockTime(180000ms)-recog 的倒计时;param=0/1 绑定提示、2 解绑失败(中断)、3 解绑成功、4 时间偏差、5 忙、6 重登、8~18/PPW_SM_EQUIP_SPLIT 携带 series(>10000 时写入 security.equipBit)。细节属 [M10-S2 安全密保],此处只立索引。
- 相关但未接入:CM_TRY_UNLOCK_EQUIP/CM_LOCK_UNLOCK_EQUIP2 定义存在,grep 无调用点。

### 9. SM_DURACHANGE(642)——已穿装备耐久

- 字段(**按客户端解析口径**,ui.lua 535-536 行调用 `equip:duraChange(param, recog, MakeLong(tag,series))`):

  | 标头 | 客户端解释 |
  |---|---|
  | param | 装备位 nPos(items[tonumber(idx)]) |
  | recog | 新 dura |
  | tag+series | duraMax = MakeLong(tag, series)=tag \| series<<16 |

  (该口径与直觉相反——makeIndex 不在包内,而是按"位"定位;服务端照此编码即可。若担心歧义,可在实现注释中固化此表。)

- **SM_SENDREPAIRCOST(671)**:`recog`=修理价格(金币);recog<0 显示 "???? 金币"(ui.lua 766-769 行,与 SM_SENDBUYPRICE 共用分支)。

## 服务端实现要点

1. **双通道外观**:本人视角走 SM_TAKEON_OK/SM_TAKEOFF_OK 的 body=TFeature(10B packed),围观者走 SM_FEATURECHANGED 广播;两处都必须实现,缺一会出现"只有自己看得见换装"。
2. **位置协商以服务端为准**:客户端预选的戒指/手镯左右位可能被服务端拒绝(回 -2),客户端会整件回滚到背包;不会自动尝试另一只手。
3. **脱下 5s 防抖**意味着服务端收到的 CM_TAKEOFFITEM 天然稀疏;无需再做频率惩罚。
4. **TUserStateInfo 空槽必须存在**(16 件全量数组,Index=0 表示空),否则后续字段整体错位——这是该结构最常见的实现事故点。
5. SM_SENDUSEITEMS/TUserStateInfo 内的 TClientItem 都支持扩展键值:他人装备上的强化属性要一并编入,否则对方面板属性显示为模板默认值。
6. 修理报价/执行都以 MakeIndex 低/高拆分编址(Loword/Hiword),与仓库存取、宝箱钥匙同一惯例(主模块 §2.6)。
