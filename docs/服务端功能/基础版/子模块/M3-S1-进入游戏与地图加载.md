# M3-S1 进入游戏与地图加载

> 所属主模块:[M3-游戏世界与场景](../主模块/M3-游戏世界与场景.md)

## 功能概述

玩家在公告场景(notice)点击"确认"后进入 main 场景。main 场景构造的**第一件事**就是向服务端上报客户端环境(CM_LOGINNOTICEOK + TOsVersion3),随后设置消息等待(SM_NEWMAP/SM_MAPINFO_EX),进入"等图"状态。服务端依次下发地图相关初始包,客户端重建本地地图对象;收到 SM_LOGON 后创建自己的角色对象并打开 UI。本子模块覆盖:

- 进主场景的第一包与时序约束(`net.setWaitMsg` 阻塞语义);
- 地图数据四件套:地图替换表、安全区列表、地图状态、地图标题;
- 自己进场包 SM_LOGON 的两种 body 格式与字段;
- 客户端本地如何用这些数据加载地图文件(哪些是网络数据、哪些是本地资源)。

## 详细报文说明

### CM_LOGINNOTICEOK(1018)— 客户端环境上报

- **时机**:`mir2.scenes.main.scene.lua :: ctor`,即 main 场景一构建就发送(此时还没收到任何进图数据);同函数内紧随其后调用 `net.setWaitMsg(SM_NEWMAP, SM_MAPINFO_EX)`。
- **TDefaultMessage 字段**:recog/param/tag/series 全部缺省(=0)。
- **body**:`getRecord("TOsVersion3")` 直接编码,**packed 记录,80 字节**,字段未赋值 → 全零/空串(代码事实:`net.send({CM_LOGINNOTICEOK}, nil, getRecord("TOsVersion3"))`,无任何填充语句):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | int | major | OS 主版本(推测;客户端发 0) |
| 4 | int | minor | OS 次版本(推测) |
| 8 | int | build | OS build 号(推测) |
| 12 | int | memSize | 内存大小(推测,MB) |
| 16 | int | usingIGW | 是否使用 IGW 网关(推测) |
| 20 | int | oemID | OEM/渠道 ID(推测) |
| 24 | char*[47] | cpuName | CPU 名称,GBK 定长 47+1=48B(推测;客户端发全 0) |
| 72 | int | videoMemorySize | 显存大小(推测) |
| 76 | int | isVirtualMachine | 是否虚拟机(推测;服务端可作虚拟机封禁依据) |

- **应答**:无直接应答。它的真正作用是"敲门":服务端收到后才开始下发进图序列。

### net.setWaitMsg 阻塞语义(时序核心)

`mir2.single.net.lua :: setWaitMsg/processLoop`:设置后,分发循环只放行 ident==SM_NEWMAP 或白名单(SM_MAPINFO_EX)的消息,**其余全部滞留 net.msgs 队列**;SM_NEWMAP 到达时解除等待。因此:

1. 服务端在 CM_LOGINNOTICEOK 之后、SM_NEWMAP 之前发的任何其他包(包括 SM_CHR_LIST、SM_SENDNOTICE 等)都会被扣住,直到 SM_NEWMAP 之后才被处理——不会丢,但顺序上表现为"延后"。
2. SM_NEWMAP 处理分支里又调用 `net.setWaitMsg(SM_LOGON)`(`ground.lua :: SM_NEWMAP 分支`)开始第二段等待:**SM_NEWMAP 必须先于 SM_LOGON**(SM_LOGON 分支要用已建立的 `self.map`),且两段等待期间服务端必须持续发包推进,否则客户端表现为"卡在黑屏"。
3. 白名单消息(SM_MAPINFO_EX)可以在等待期间随时插入,到达即处理。

### SM_NEWMAP(51)— 建立新地图

- **时机**:进图/切图均走此包(切图通常走 SM_CHANGEMAP,见 S4;SM_NEWMAP 为首次进图与"再入"路径)。
- **TDefaultMessage 字段**:recog/param/tag/series 未使用(客户端不读)。
- **body**:整段 body 经 `net.str()` 按 GBK→UTF-8 解出**地图 ID/名字符串**(如 `"0"`),作为 `map.new(mapid)` 构参(`ground.lua :: SM_NEWMAP 分支`)。不是压缩数据——真正的地图文件是本地资源 `res.loadmap(replaceMapid or mapid)`(`map.lua :: ctor`),网络侧只需给 ID。
- **客户端行为**:销毁旧 map 对象 → 新建 map(读本地 `.map` 文件得到宽 w/高 h)→ `self.player = nil` → `net.setWaitMsg(SM_LOGON)`。
- **错误分支**:无应答分支;不发此包则永远等待。

### SM_MAPINFO_EX(1281)— 地图替换表

- **时机**:仅在**第一段等待期(SM_NEWMAP 到达之前)是白名单消息**——`setWaitMsg(SM_NEWMAP, SM_MAPINFO_EX)` 的 allowList 含它,随到随处理;SM_NEWMAP 之后等待链切换为 SM_LOGON(无白名单),再发会被扣到 SM_LOGON 后才处理。**建议放在 SM_NEWMAP 之前下发**(map 构造时即读取替换表决定 replaceMapid)。
- **字段/body**:无头字段;body 为 GBK 字符串,格式 `"旧地图ID,替换地图ID;旧2,替2;…"`(`mir2.data.map.lua :: setMapReplaceTable`:先按 `;` split,再按 `,` split,两端 trim)。含义:当某地图客户端缺少资源时,用替换地图的资源渲染(`map.lua :: ctor` 中 `replaceMapid` 决定 loadmap 与 hasRes 判定)。
- **空 body 合法**(清空表)。

### SM_SAFE_ZONE_INFO(4230)— 安全区列表

- **时机**:进图阶段一次性全量下发(客户端整体重建表)。
- **字段**:`msg.param = 条数 n`;recog/tag/series 未使用。
- **body**:n × **TStartPoint**(22B,非 packed):

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | string[14] | startMap | 生效地图 ID(GBK 变长串:首字节长度 L+L 字节,占 15B) |
| 16 | short | x | 中心 x |
| 18 | short | y | 中心 y |
| 20 | short | rang | 半径;**0 时客户端按 9 处理**(`data.map.lua :: setSafeZone`) |

- **消费**:`g_data.map.safezones[startMap] = {x,y,rang}…`,用于 `isInSafeZone`(影响无限移动判定与摆摊阻挡,S3/S2)与小地图安全区光圈绘制(`map.lua :: addSafeZoneEff`,坐标 `x±rang/y±rang`,地图 "0" 的 (320,260)-(337,276) 区域刻意跳过——比奇省特例)。

### SM_AREASTATE(708)— 地图状态

- **字段**:`msg.recog = 状态位图`;其余不用,无 body。
- **位定义**(`mir2.def.globa1.lua` cAreaState*):0 普通、1 战斗(cAreaStateFight)、2 安全(cAreaStateSafe)、4 攻城(GuildWar)、8 挑战(DareWar)、22 可复活(Reliveable,globa1 原值如此)。文案映射见 `mir2.def.globa3.lua :: getMapStateStr`(底部状态栏 uptMap 显示)。
- **消费**:`g_data.map:setMapState(recog)`;cAreaStateSafe 位参与 `isInSafeZone`(整图视为安全区)(`data.map.lua :: isInSafeZone`)。

### SM_MAPDESCRIPTION(54)— 地图标题

- **body**:GBK 字符串,按 `\r`(string.char(13))分割取第 1 段为标题(`ground.lua :: SM_MAPDESCRIPTION 分支`,`net.strs(buf, string.char(13))`)。
- **消费**:`g_data.map:setMapTitle`,大地图面板标题更新。

### SM_LOGON(50)— 自己进场

- **时机**:SM_NEWMAP 建立地图之后(受第二段 setWaitMsg 控制)。
- **字段**:

| 字段 | 含义 |
|---|---|
| recog | 自身 roleid(`g_data.player:setRoleID`) |
| param | 出生格 x |
| tag | 出生格 y |
| series | 低字节=朝向 dir(0-7) |

- **body 双格式**(按 bufLen 与记录尺寸匹配,`ground.lua :: SM_LOGON 分支`):

| 格式 | 尺寸 | 内容 |
|---|---|---|
| TPlayerStateEx(**必须**) | 40B | outs(4)+allBodyState(16)+state(4)+resv(4)+feature=TFeature(10,补齐至 40) |
| TPlayerState(旧) | 28B | 同上但**无 feature** —— 此格式下 `v:get("feature")` 返回 nil,后续 `setSex(v:get("feature"):get("sex"))` 直接报错、玩家对象也不会创建 |

- state(int)字段的低 16 位低字节被解读为"允许组队"标志(`setAllowGroup(Lobyte(Loword(v:get("state"))) == 1)`);allBodyState 作为身体状态位图传入角色对象。
- **客户端连带动作**(同一分支):向服务端补发 **CM_QUERYBAGITEMS(81)**(无参无 body,背包内容应答 SM_BAGITEMS 归 M5)、显示 UI/小地图、启动邮件轮询(g_data.mail:startSchedule,归 M10)、触发 helperScript `enterMap(mapid)`(纯本地引导脚本,不发网络包,见下节)。
- **错误分支**:无;不回此包则客户端停在等待态。

### SM_LOGON_64ID(4651)— IAP 支付角色标识

- **body**:buf 原样存入 `IAP.roleIdentify` 并触发 `IAP.init()`(`ground.lua :: SM_LOGON_64ID 分支`)。用途是 iOS 支付票据与角色的绑定校验(mir2.single.iap.lua),服务端只需保证该串与本角色订单一致;具体格式未核实。

## 服务端实现要点

1. **必达时序**:收到 CM_LOGINNOTICEOK(1018) 后按下发顺序回复:
   `SM_MAPINFO_EX(1281)`(可选,建议在 SM_NEWMAP 前)→ **`SM_NEWMAP(51)`** → `SM_SAFE_ZONE_INFO(4230)`/`SM_AREASTATE(708)`/`SM_MAPDESCRIPTION(54)`(任意顺序,会被队列暂存到等待结束后处理)→ **`SM_LOGON(50, TPlayerStateEx 40B)`**。少发 SM_NEWMAP 或 SM_LOGON 都会永久卡住客户端(setWaitMsg 扣留一切后续包)。
2. **SM_LOGON 只能用 40 字节 TPlayerStateEx**;28 字节旧格式会导致 nil 崩溃路径(feature 缺失)。
3. SM_NEWMAP 的 body 是**地图 ID 字符串(GBK)**,必须与客户端本地 `res/map` 资源名一致;若使用客户端没有资源的地图,需配合 SM_MAPINFO_EX 提供替换表,否则只显示占位灰块并提示"该地图的环境正在施工中."。
4. 安全区列表是全服性的(param=条数),每张要用的地图都要有 TStartPoint 条目,rang=0 会被放大成 9。
5. 收到 CM_QUERYBAGITEMS(81) 应回 SM_BAGITEMS(归 M5),否则界面背包为空但不阻塞。
6. TOsVersion3 当前客户端恒发全零,服务端可校验 bodyLen==80,不要依赖字段值做风控(除非确认目标版本原生层会填充,(未核实))。
7. helperScript 家族(enterMap/enterRegion/killedMonster/levelUp/globalEvent)**均无网络发送**:五个文件的 `main(...)` 全部为空实现或纯本地新手引导(mod.newbee 打印/流程),`scriptRunner` 只是本地协程调度器(`mir2.helperScript.*.lua`、`common.helper.scriptRunner.lua :: runner.execute`)。唯一沾边的上行是游戏助手按钮 `helper.clickedHelper()` 发 **CM_CLICK_HELPER(4417)**(无参无 body,`common.helper.helper.lua`),以及服务端可用 **SM_SHOWHELPER(4407,param=2,body=怪名)** 驱动 killedMonster 引导事件——注意 scriptRunner.onKilledMonster 存在形参 bug(传的是全局 bossId 而非入参),引导脚本实际收到 nil。
