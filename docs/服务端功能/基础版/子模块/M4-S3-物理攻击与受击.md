# M4-S3 物理攻击与受击

> 所属主模块:[M4-战斗属性与技能](../主模块/M4-战斗属性与技能.md)

## 功能概述

物理攻击链路:玩家操作(点击目标/Shift 强攻/挖矿/自动打怪)→ 客户端按攻击方式选择 CM_HIT 系列消息(全部**无 body**,坐标与方向编码在 TDefaultMessage 字段中)→ 服务端校验后回发 SM_ACT_GOOD/SM_ACT_FAIL 推进动作队列,并向周围广播他人攻击(SM_HIT 族或通用 SM_PHYSICAL_ATT)。特殊剑法(烈火/攻杀/半月/刺杀/剑气)由服务端通过开关消息授权,客户端一次性消费。受击侧:SM_STRUCK/SM_HEALTHSPELLCHANGED 承载血量数值,SM_OPENHEALTH/CLOSEHEALTH 控制他人血条显示;死亡/回生的呈现归 M3,本模块记录其数值与提示分支。

## 详细报文说明

### CM_HIT 系列(3014/3015/3016/3018/3019/3024/3025/3002)——物理攻击上行

- **body:无。所有信息在 TDefaultMessage 12 字节内**(已核对全部发送代码,不存在 TClientPhyAttRec 上行):

| 字段 | 含义 |
|---|---|
| recog | 攻击者当前 x(地图格坐标) |
| param | 攻击者当前 y |
| series | 方向 dir,0..7(DR_UP=0 顺时针至 DR_UPLEFT=7,globa1 DR_* 常量) |
| tag | 未使用(唯一例外见下) |

- **发送点与 ident 选择**(`controller:attackRole`,行 865):
  - 目标与自己切比雪夫距离 ≤1 时按优先级选 ident(命中即消费 `g_data.player.hitEnables.*` 标志并置 false):fire→CM_FIREHIT(magicId 26)> fire4→**CM_4FIREHIT**(magicId 26)>sword→CM_SWORD_HIT(magicId 58)>twn→**CM_TWINHIT**(magicId 95,MP≥10)>pow→CM_POWERHIT(magicId 7)>wide→CM_WIDEHIT(magicId 25,MP≥3)>long(autoAllSpace 设置)→CM_LONGHIT(magicId 12);全无标志则 CM_HIT。(controller.lua 行 875-913)
  - 距离为 2 的直线(行列对齐,`abs(dx)<=2 且 abs(dy)<=2 且 dx/dy 不同时为±1`)且 long 开启 → CM_LONGHIT。
  - 距离 >2 不发包,转为寻路移动(sendMove→CM_WALK/CM_RUN,归 M2/M3 移动域)。
  - `forceAttackTest(dir)`(行 1060,Win32 Shift 强攻/移动中朝向攻击):无目标时随机 CM_HIT/CM_HEAVYHIT/CM_BIGHIT(math.random(3));long 开启且前方 2 格有角色则改发 CM_LONGHIT。
  - **挖矿**:装备 shape==19(鹤嘴锄)时,`moveTo` 分支(行 812)发 `CM_HEAVYHIT{recog=x, param=y, tag=dir}`(**此处分方向用了 tag 而非 series,与其他攻击不一致,服务端需兼容**);`miningTest`(行 1234)则用标准 `series=player.dir`。
- **⚠️ 未定义常量**:`CM_4FIREHIT`、`CM_TWINHIT` 在 globa1.lua 中不存在(grep 已核实)。fire4/twn 标志分支会以 `msg[1]=nil` 调 net.send,TDefaultMessage.ident 的实际线上值未核实(ident 编码为 nil 的行为取决于字节流层)。服务端如收到 ident 异常包应丢弃而非断连。
- **本地节流(影响发包节奏)**:`player:canNextHit()`(`role.hero.lua` 行 158)要求距上次攻击动作超过 `max(0, def.role.speed.attack(0.9s) − min(300, hitSpeed*60)/1000)`;hitSpeed 来自角色数据。lastAttackTime 在 addAct(type∈hit/spell/heavyHit/bigHit)时更新。

### SM_ACT_GOOD(629)/SM_ACT_FAIL(630)——动作回执

- 分发:`ground.lua` 行 195/208 → `player:executeSuccess()/executeFail(x,y,dir)`。
- SM_ACT_FAIL 字段:`param>0 且 tag>0` 时 x=param、y=tag、dir=series,客户端把角色拉回该坐标并清空动作队列;否则仅终止当前动作。
- 这两条是 walk/run/hit/spell 共用的通用回执(BRIEF §2:内联处理,不走 processLoop 队列)。**服务端必须及时应答,否则客户端动作队列停摆、无法发起下一次攻击。**

### SM_STRUCK(31)——受击与血量推送

- 分发:`ground.lua` 行 494。recog=受击者 roleid;**msg.series=本次伤害量(outhp)**,客户端用于飘血(`settingLogic.missHp`)。
- **body 双布局(按 bufLen 区分)**:
  - `bufLen == 16`(TMessageBodyWL 尺寸):**body 内容被忽略**,取 `hp=msg.param`、`maxHp=msg.tag`(mp/maxMp 缺失);
  - `bufLen == 32`:解析 `TStruckInfo`:
    | 偏移 | 类型 | 字段 | 说明 |
    |---|---|---|---|
    | 0 | short | unUse1 | 未使用 |
    | 2 | short | unUse2 | 未使用 |

    | 8 | int | param | 未使用 |

    | 20 | int | maxHp | 最大生命 |

    | 28 | int | maxMp | 最大魔法 |
- 两种布局都不匹配时 hp/maxHp 为 nil,客户端 ability:set 收到 nil(边界情况,建议服务端始终二选一)。
- 自己/英雄受击:更新 ability.HP/maxHP(及 MP/maxMP)+ 血条 setHP(hp,maxHp,series);其他角色:交地图层刷新头顶血条(M3)。

## 服务端实现要点

1. **攻击上行无 body**:坐标(x=recog,y=param)与方向(series=dir,例外:moveTo 挖矿用 tag=dir)都在 TDefaultMessage 里;服务端做距离/朝向合法性校验时应以此为基准,不要期待 TClientPhyAttRec 上行。
2. **动作回执驱动一切**:每条 CM_*(含移动)都要配 SM_ACT_GOOD/SM_ACT_FAIL;FAIL 用 param/tag/series 提供纠错坐标可实现服务器权威回拉。
3. **特殊剑法 = 服务端授权 + 客户端单次消费**:SM_FIREON/POWER_OK/SWORDHIT_ON/LNGHITONOFF/WIDEHITONOFF 控制 hitEnables 标志;标志只在下一次 attackRole 时消耗一次。连续两次烈火必须发两次 SM_FIREON。
4. **广播两条通道可选**:逐个 SM_HIT 族消息,或统一 SM_PHYSICAL_ATT(hitMode 表见上);两者最终汇入同一呈现管线。
5. 受击推送建议带 32B TStruckInfo(同时覆盖 HP/MP 及上限);16B 形态仅更新血量且读的是 param/tag 而非 body。
6. 击杀流程:SM_DEATH(尸体)→ SM_NOWDEATH(recog=死者,触发回生 UI)→ SM_ALIVE(复活,重新带 body)。
