# M3-S3 自身移动与位置交互

> 所属主模块:[M3-游戏世界与场景](../主模块/M3-游戏世界与场景.md)

## 功能概述

记录玩家自己移动(走/跑/转身)、开门、以及动作回执的完整回路。客户端是**预测式**的:摇杆/点击先本地播放动画并入等待队列(waits),同时发 CM 包;服务端回 **SM_ACT_GOOD(629)** 确认或 **SM_ACT_FAIL(630)** 纠偏。这两个回执在 `net.handler` 中**直通分发**(不进 30ms 队列,`mir2.single.net.lua :: handler`),保证操作手感。

发送点不在 ground.lua,而集中在操作层:

| 发送函数 | 文件::函数 | 场景 |
|---|---|---|
| CM_WALK / CM_RUN / CM_OPENDOOR | `mir2.scenes.main.console.controller.lua :: sendMove` | 摇杆/点击移动的主路径 |
| CM_TURN | 同上 `moveTo`(走不动时转身)、`handleTouch` autoWa 分支 | 点击转向 |
| CM_TURN | `mir2.scenes.main.pc.operate.lua :: onMouseLeft_Alt_begin`(PC Alt+左键)、`mir2.scenes.pc.operate.lua :: onMouseLeft_Alt_begin`(移动端等价) | PC 转身 |

## 涉及源文件

| 文件 | 角色 |
|---|---|
| `console.controller.lua :: sendMove / moveTo / handleTouch` | 移动决策、阻挡检测、发包 |
| `pc.operate.lua`(main 与 pc 两份) | PC 键鼠操作的 CM_TURN |
| `mir2.scenes.main.ground.lua :: processMsg`(SM_ACT_GOOD/FAIL、SM_COMMON_INFORMATION、门回执分支) | 回执处理 |
| `role.role.lua :: addAct(wait)/executeSuccess/executeFail` | 预测动作与纠偏 |
| `mir2.single.net.lua :: handler/processLoop` | SM_ACT_GOOD/FAIL 直通分发 |
| `mir2.data.client.lua :: setLastTime/checkLastTime` | 开门等发包节流 |

## 详细报文说明

### CM_WALK(3011)/CM_RUN(3013)— 走与跑

- **时机**:`controller:sendMove(map, player, dir, step)`(`console.controller.lua`)。按方向表 `def.role.dir["_0"..7]`(每方向单位位移向量)逐步探测 `map:canWalk`:累计可走格数 dis——dis==1 发 CM_WALK,dis==2 发 CM_RUN(step 由输入决定,鼠标右键/长按=2,HP<10 时强制 1)。
- **TDefaultMessage 字段**:

| 字段 | CM_WALK | CM_RUN | CM_TURN |
|---|---|---|---|
| recog | 目标格 x(destx) | 两步后目标 x | 当前 x |
| param | 目标格 y(desty) | 两步后目标 y | 当前 y |
| tag | 未用(0) | 未用(0) | 未用(0) |
| series | dir(0-7) | dir(0-7) | dir(0-7) |

- **body**:无(strs/data 均无 → dataLen=0)。
- **本地伴随**:addAct(type=walk/run, 带 `wait={x,y,dir}` 记录出发前位置)进入 waits 预测队列;`helper:onUpdateAct` 顺带触发本地 enterRegion 引导脚本(无网络)。
- **应答**:SM_ACT_GOOD(629) → `player:executeSuccess()` 弹出 waits 队首并落定(hit 类同时更新 hitStatus);SM_ACT_FAIL(630) → `player:executeFail(x,y,dir)` 回拉到 wait 记录的原坐标并转 stand。**一句纠偏语义**:FAIL 的 param/tag>0 表示服务端给出权威坐标(直接瞬移过去),否则回退到本动作起点。
- **错误分支**:超时无回执不会自动重发;waits 会积压导致后续移动被锁(isExecuteFast 加速播放),(未核实客户端是否有主动超时清理)。

### 客户端放行规则(服务端校验预期)

`sendMove` 的探测循环:`not ret.block` 或(`isUnlimitedMove` 且 block 不是 "npc"/"map")才计入可走。即:

- 正常情况:任何阻挡(door/map/npc/hero/mon)都止步;
- `isUnlimitedMove = g_data.map:isInSafeZone(mapid,x,y) or g_data.player.isUnlimitedMove`:安全区内(或服务器标记)时,**door/mon/hero 阻挡被无视**(npc/map 仍挡)。

服务端重写时应实现同等宽容度:安全区内的穿怪/穿门行走要放行(CM_WALK/RUN 合法),否则客户端会持续收到 FAIL 造成抽搐。地图静态阻挡以本地地图文件为准(gettile.canWalk / doorIndex 位 0x80),服务端用同一份 Mir200 地图数据即可对齐。

### CM_TURN(3010)— 原地转身

- **时机**:`moveTo` 走不动且方向变化时;autoWa(按住拖动转向)分支;PC Alt+左键分支。三处字段一致:recog=当前 x,param=当前 y,series=新 dir,无 body。
- **应答**:同 SM_ACT_GOOD/FAIL(转身也进 waits 队列)。注意客户端在发送的同时已本地转好身,FAIL 时会执行 executeFail 复位(通常无坐标变化)。

### CM_HEAVYHIT(3015)— 挖掘边界场景

`moveTo` 中:目标是 "pos" 类型移动、身上穿戴 shape==19(镐类,M5 定义)且正前方为 map 阻挡时,改为发 CM_HEAVYHIT(recog=x,param=y,tag=dir)挖矿并置 autoMining 状态。属攻击包,细节归 M4;此处仅存档其移动链路中的触发条件。

### CM_OPENDOOR(1002)— 请求开门

- **时机**:sendMove 探测在第 1 步遇到 door 阻挡时;受 `g_data.client:checkLastTime("openDoor", 5)` **5 秒节流**(`data.client.lua`,setLastTime 存 socket.gettime,checkLastTime(key, cooldown))。
- **字段**:`recog = doorIndex & 0x7F`(门组号,取 tile 数据低 7 位),`param = 玩家所朝格 x`,`tag = 所朝格 y`。无 body。
- **应答**:
  - SM_OPENDOOR_OK(612):param/tag=门格坐标 → 该门组全部格切换为开门帧(doorOffset)并解除阻挡;
  - SM_CLOSEDOOR(614):同字段,关门恢复阻挡;
  - SM_OPENDOOR_LOCK(613):提示"此门被锁定.",不改变状态。
  - 收到任一 OK/CLOSE 都会 setLastTime("openDoor") 刷新节流基准。

### SM_ACT_GOOD(629)/SM_ACT_FAIL(630)— 直通回执

- **分发特殊性**:`net.handler` 对这两个 ident **跳过消息队列立即调用 processMsg**(`net.lua :: handler`),ground 分支同步执行:
  - GOOD:`self.player:executeSuccess()` + autoRat:onActGood(挂机辅助统计);
  - FAIL:param>0 且 tag>0 时取 dir=series、y=tag、x=param 作为权威位;`executeFail(x,y,dir)` 清空 waits、停止移动 tween、贴回坐标转 stand;autoRat:onActFail。
- **无 body、无错误分支**;服务端必须对每个消耗型动作(WALK/RUN/TURN/HIT/SPELL 等 CM_)恰好回一个 GOOD 或 FAIL,否则客户端 waits 队列失衡(卡动作或漂移)。
- 注意:GOOD/FAIL 是全局的(不带动作序号),依赖 FIFO 配对——**服务端必须按收到 CM_ 的顺序回执**。

### SM_COMMON_INFORMATION(2821)— 安全区进出(param==6 分支)

| 字段 | 含义 |
|---|---|
| param | 6=安全区进出通知(其他值由 ui.lua 其他分支处理,归各域) |
| tag | 1=进入安全区,0=离开 |

客户端提示文案并 `g_data.player:setIsUnlimitedMove(tag==1)`——直接改变 sendMove 的放行规则(见上)。服务端在玩家跨安全区边界时必须下发,否则安全区内穿怪体验不一致。该消息无 body。

### 骑乘(horse riding)相关

- 外观层:TFeature.riding(short,packed 第 8 字节起)随各描述包下发;身体状态位 csZaiMaShang=51/csHorseRider=52(`role.def.state.lua`)定义存在;
- 行为层:rebuilt-src 中**未发现**基于 riding/骑乘位的移速或动作分支(搜索仅命中定义处),骑乘对本模块的影响(未核实);保守实现:保持 TFeature.riding 字段透传即可,不要依赖客户端做骑乘速度差异。

### 发包节流键(g_data.client.lastTime,与本域相关的部分)

`mir2.data.client.lua :: setLastTime(key, v)/checkLastTime(key, cooldown)` 是通用节流表(socket.gettime 基准):

| 键 | 写入点 | 用途 |
|---|---|---|
| openDoor | controller.sendMove / ground 门回执分支 | CM_OPENDOOR 5s 节流 |
| fire / swordhit / spell | ground.lua(SM_FIREON/SM_SWORDHIT_ON/SM_MAGICFIRE 自施法分支) | 攻击状态开启后的本地一次性窗口(M4) |
| ping | scene ctor(DEBUG 心跳显示) | 仅调试 |

## 服务端实现要点

1. **顺序回执**:SM_ACT_GOOD/SM_ACT_FAIL 必须与 CM_ 请求严格 FIFO 配对且即时直通(客户端不等队列);批量积压回执会造成动作卡顿/连击错乱。
2. **FAIL 必须带权威坐标**(param/tag/x/y+series=dir)才能把预测误差收敛,否则只回退起点,反复失败会出现"橡皮筋";持续拒绝(如加速外挂)时可连续 FAIL。
3. **移动合法性校验口径**与客户端一致:普通区域一步/两步直线、不可穿 npc/map 静态阻挡;**安全区内放行穿 mon/hero/door**(isUnlimitedMove 语义),否则体验割裂。
4. CM_OPENDOOR 受客户端 5s 节流,服务端无需去重太狠;LOCK 态要显式回 SM_OPENDOOR_LOCK,否则玩家会停在门前。
5. 跨安全区边界下发 SM_COMMON_INFORMATION(param=6,tag=1/0),配合 SM_SAFE_ZONE_INFO 的圆圈数据使用。
6. 方向编码 0-7(0=上,顺时针),series 低字节;所有坐标为格子坐标(int16 即可)。
