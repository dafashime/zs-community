# M8-S4 货币与充值

> 所属主模块:[M8-经济交易系统](../主模块/M8-经济交易系统.md) · 基础版对照:[M8-S4 货币与充值](../../基础版/子模块/M8-S4-货币与充值.md)

## 与基础版差异摘要

货币推送(SM_GETDIAMNUM_EXT 1202 + TMessageCapitalInfo 24B / SM_GOLDCHANGED 653)与基础版一致(客户端无主动刷新 CM)。**充值流程差异显著**——白猪版用独立充值面板 chargeNew:

### 白猪版特有:chargeNew 充值面板(`core/mir2.scenes.main.panel.chargeNew.lua`)

1. **网页充值**:`device.openURL(充值页 URL)`——跳转浏览器/WebView,无游戏协议;充值页 URL 来自服务器列表配置(`g_data.login.localLastSer.chargeurl`,默认 `https://by.1234500000.com/cz/10YnRN?gid=16732`);
2. **到账轮询**(行 107-153):面板打开期间每 **1 秒** POST `czconfig.czcheck`(服务器下发的检查 URL),POST 数据:
   - `ex=<加密(角色名)>&svr=<czsvr 或 1>`(加密函数 `callback(text)` 未定位实现,推测 XXTEA/自研(未核实));
   - 响应 JSON `{value:"1", money:N}` → 提示"正在自动领取充值[数量:N]"并发 **`@getCharge` 命令**(`def.role.sendCM("@getCharge")`,经 CM_SAY 通道)→ 服务端据此发放充值货币,随后经 SM_GETDIAMNUM_EXT 同步余额;
3. **教程页**:`webView` 面板打开 `https://shimo.im/docs/...`(纯 WebView,无协议)。

### 服务端实现要点

1. 货币推送同基础版 M8-S4;
2. 若支持白猪充值闭环:①服务端列表/配置提供 chargeurl(网页充值页)与 czcheck(轮询检查接口,响应 `{value,money}`);②识别并处理 `@getCharge` 命令(CM_SAY 前缀,见 M7-S1 的 @命令通道);③发货后补推 SM_GETDIAMNUM_EXT。
3. GHOME 族(4482/4483/4484,基础版 M8-S4 的 IAP 流程)在白猪版是否仍用:白猪版 loginer.verifyReceipt 为空实现,充值走上述 chargeNew 网页流程;GHOME 族保留但非主路径(未核实是否仍触发)。
