# M3-S3 自身移动与位置交互

> 所属主模块:[M3-游戏世界与场景](../主模块/M3-游戏世界与场景.md) · 基础版对照:[M3-S3 自身移动与位置交互](../../基础版/子模块/M3-S3-自身移动与位置交互.md)

## 与基础版差异摘要

CM_WALK/CM_RUN/CM_TURN 及其应答与基础版一致;白猪版新增两个移动扩展消息:

### CM_RUN3(4108)——三格跑步

- 发送:`core/mir2.scenes.main.console.controller.lua :: sendMove`(行 1692-1710):目标与自身**距离=3 格**时(dis==3),发:

```lua
net.send({ CM_RUN3, recog = destx, param = desty, series = dir2 })
```

- TDefaultMessage:`recog`=目标 x、`param`=目标 y、`series`=方向 0-7;无 body。与 CM_RUN 同构(基础版 dis==2 发 CM_RUN,dis==1 发 CM_WALK;白猪版新增 dis==3 → CM_RUN3)。
- 服务端要点:收到后按"跑动 3 格"处理(校验路径 3 格、广播 SM_RUN 或专属动作);若服务端不支持,按普通 RUN 处理也不会卡客户端(客户端本地已播动作,靠 SM_ACT_GOOD/FAIL 纠偏)。

### CM_PICKUP_RANGE(4278)/SM_MAP_RANGE_PICK(5044)——范围拾取

- 上行 `controller:pickupRange`(行 1716-1746),触发条件:
  - 设置开启(`g_data.setting.job.isPickUpRange`);
  - **挂机中**(`autoRat.enableRat`);
  - 60 秒节流(`checkLastTime("dropItem", 60)`)+ 2 秒防抖(`lastPickupRangeTime`);
  - 拾取点范围内存在物品(`getRangeItems` 数量>0);
- 报文:`net.send({ CM_PICKUP_RANGE })`——**无参无 body**;
- 下行(`core/mir2.scenes.main.ui.lua` 行 2541):`SM_MAP_RANGE_PICK`: **`param==1` → 开启范围拾取,其余 → 关闭**(写 `g_data.player.isPickUpRange`);
- 服务端要点:应答必须回 SM_MAP_RANGE_PICK 才能改变客户端开关状态;范围拾取的实际物品获取走通用拾取链(CM_PICKUP 或服务端直接入包,客户端未发现专用拾取参数)。

### 非协议误报澄清

- `CM_TURN2`(controller 行 1195/1202):**局部变量名**(`local num, hitType, CM_TURN2 = math.random(3)`,承载 CM_HIT/CM_HEAVYHIT/CM_BIGHIT/CM_LONGHIT),非网络消息;
- `CM_HEAVYHIT2`(行 1560-1567):**局部变量**(`local CM_HEAVYHIT2 = CM_HEAVYHIT`,挖矿时可能替换为 `def.jobMaps[...].MiningActType`),实际发送的是 CM_HEAVYHIT(3015)。

## 服务端实现要点

1. 三格跑:CM_RUN3(4108) 参数同 CM_RUN;
2. 范围拾取:CM_PICKUP_RANGE(4278) 必须回 SM_MAP_RANGE_PICK(5044) 才生效;
3. 其余同基础版 M3-S3。
