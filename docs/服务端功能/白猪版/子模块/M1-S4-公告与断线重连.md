# M1-S4 公告与断线重连

> 所属主模块:[M1-登录与接入](../主模块/M1-登录与接入.md) · 基础版对照:[M1-S4 公告与断线重连](../../基础版/子模块/M1-S4-公告与断线重连.md)

## 与基础版差异摘要

**协议无差异。** 公告场景(`mir2.scenes.notice.scene.lua`)与断线重连链(recSession 二次连接 → `SM_LOGIN` → `CM_RECONNECT` + reconnectID → 重新进图)与基础版逐条一致:

- 公告:SM_SENDNOTICE → 确定 → `net.remove(self)` + `gotoscene("main")`,随后 main 场景 ctor 发 `CM_LOGINNOTICEOK(1018)`(body=80B 全零 TOsVersion3);
- 重连:四场景 reconectFuc 模板一致;`net.connect(g_data.login.recIP, recPort, self, recSession)`(**第二次连接,count2=1**,TigerGate 条件满足时的编码点之一);
- 网络可达性检测:`network.isHostNameReachable("www.baidu.com")`(白猪版 notice.scene 145 行,本地探测,非游戏协议)。

## 白猪版特有行为

1. **bz.scene(白猪专属开场场景)**:`mir2/mir2.scenes.bz.scene.lua` 纯本地(视频/动画播放 + 延迟跳转),**无任何网络报文**;结束后 `def.setLoginCenter(def.gateIP, def.gatePort, ...)` 并 `gotoscene("login")`,或 `def.skipSFselect` 时直接进 login、否则 `requestSfList()`(归 M2-S1);
2. 重连成功后若 TigerGate 开启,后续上行将走编码层(默认关闭)。

## 服务端实现要点

与基础版 M1-S4 一致:公告后接 CM_LOGINNOTICEOK 开始进图;重连凭 reconnectID 票据;11706 表示重连失败。
