# 客户端编译指南

> 适用工程：`client/lib/`（BaiZhuClient，Quick-Cocos2dx-Community 3.6.1 的 Win32/Android 客户端）
> 本指南记录在本仓库实际环境（Windows + VS2022）验证过的完整编译流程、踩坑与修复。

---

## 0. 获取工程（BaiZhuClient.zip → client/lib/）

本仓库**不包含引擎工程**（`client/lib/` 已在 .gitignore 排除，约 8.3 GB）。首次使用请：

1. 下载原始工程包 **BaiZhuClient.zip**（与 `client/src*` 对应的 Quick-Cocos2dx-Community 3.6.1 Win32/Android 工程，含引擎 `frameworks/`、资源 `res/`、Lua 壳 `src/`、`config.json`）——下载地址见仓库 Release 或 README；
2. 将 zip 解压到 `client/lib/`，**解压后应得到**：

```
client/lib/
├── build_android_*.bat          # Android 构建脚本
├── config.json                  # Quick Player 配置
├── src/                         # Lua 壳（app/ 空壳 + config.lua）
├── res/                         # 游戏资源（Lua 字节码包 + 数据）
└── frameworks/                  # Quick 3.6.1 引擎 + runtime-src 工程
```

3. 校验：`client/lib/frameworks/runtime-src/proj.win32/BaiZhuClient.sln` 存在即可。

> 说明：`client/src`（基础版 Lua 明文源码树）与 `client/lib/src`（Quick Lua 壳）是不同内容，勿混淆；
> 运行时的游戏逻辑包 `mir2.zip` 由 `client/src` 经第 4 节流程编译后覆盖到 `client/lib/res/`。

## 1. 工程结构与三条编译线

```
client/lib/
├── build_android_*.bat          # Android 构建脚本（v7a / arm64 / dual / x86-test）
├── config.json                  # Quick Player 配置（模拟器用，不参与正式构建）
├── src/                         # Lua 壳（app/ 空壳 + config.lua）
├── res/                         # 游戏资源（Lua 字节码包 + 数据）
│   ├── upt.zip                  # 启动引导包（XXTEA 加密 zip，sign "01"）
│   ├── an.zip                   # UI 框架包（同上加密）
│   ├── framework_precompiled.zip# Quick framework 包（同上加密）
│   ├── mir2.zip                 # 游戏主逻辑包（纯 LuaJIT 字节码 zip，不加密）
│   ├── mir2_encrypted.zip       # 旧包（NPJ 逐条目加密，当前引擎不可加载，勿用）
│   └── backup_orig_pkgs/        # 原始包的备份（重编译前的版本）
└── frameworks/
    ├── cocos2d-x/               # 自带引擎 Quick 3.6.1（勿替换/勿大改）
    └── runtime-src/
        ├── Classes/             # AppDelegate + Mir2* 原生兼容层（register_all_mir2）
        └── proj.win32/          # Win32 工程（BaiZhuClient.sln）
        └── proj.android_no_anysdk/  # Android 工程（Gradle + ndk-build）
```

- **Win32 线**：MSBuild 构建 `BaiZhuClient.sln`（引擎 4 库 + app exe）
- **Android 线**：`build_android_*.bat` → NDK r16.1 ndk-build + Gradle 打包（当前机器无 SDK，不可行）
- **Lua 打包线**：明文源码 → LuaJIT 字节码 → zip / XXTEA 加密（见第 4 节）

## 3. Win32 构建（Debug|Win32）

### 3.1 前置准备

1. **sln 引擎引用已改为相对路径**（原为 `%QUICK_V3_ROOT%`，msbuild.exe 命令行下不展开环境变量，会报 MSB3202）。已改：
   `BaiZhuClient.sln` 中 `"..\..\cocos2d-x\cocos\2d\libcocos2d.vcxproj"` 等 4 条。

2. **预编译库 LTCG 替换**（详见 5.2）——本仓库已替换为干净版，无需重复操作。

### 3.2 构建命令

```powershell
# 从仓库根目录(无需设置 QUICK_V3_ROOT——sln/vcxproj 已改为相对路径,见 5.1/5.6)
& "D:\Program Files\Microsoft Visual Studio\2022\Professional\MSBuild\Current\Bin\MSBuild.exe" `
  "client\cocos\frameworks\runtime-src\proj.win32\BaiZhuClient.sln" `
  /p:Configuration=Debug /p:Platform=Win32 /p:PlatformToolset=v143 /m /nologo
```

> `/p:PlatformToolset=v143` **必须**：sln/引擎 vcxproj 只在 VS10/11/12/14 条件下指定工具集，msbuild 命令行下 `VisualStudioVersion` 未设时 C++ 默认兜底为 **v100**，报 MSB8020。

Release 构建：`/p:Configuration=Release`（注意：Release 链接用的是引擎 `cocos\2d\Release.win32\` 下的预编译库，其中 libjpeg.lib 仍是 LTCG 版，**Release 构建前需同样替换**，见 5.2）。

### 3.3 产物

```
client/lib/frameworks/runtime-src/proj.win32/Debug.win32/
├── BaiZhuClient.exe      # 主程序（约 8 MB）
├── libcocos2d.dll        # 引擎动态库（约 11 MB）
├── libluacocos2d.lib     # Lua 绑定静态库（约 167 MB）
├── libbox2d.lib / libSpine.lib / libjpeg.lib 等
└── glew32.dll / libcurl.dll / OpenAL32.dll / sqlite3.dll ...  # 运行时 DLL（已齐）
```

### 3.4 运行

```powershell
$exe  = (Resolve-Path "client\cocos\frameworks\runtime-src\proj.win32\Debug.win32\BaiZhuClient.exe").Path
$work = (Resolve-Path "client\cocos\frameworks\runtime-src\proj.win32").Path
$env:PATH = "$work\Debug.win32;$env:PATH"     # DLL 搜索路径
Start-Process $exe -WorkingDirectory $work    # 工作目录决定 projectDir(../../..) = client/lib
```

> 直接双击运行可改用 `bin\run-win-client.bat`(已封装上述逻辑,ROOT 自动定位 `client/lib`)。

- 会弹出两个窗口：`mir2` 游戏窗口（1280×720）+ 控制台窗口（Debug 构建定义了 `USE_WIN32_CONSOLE`）。
- 启动链：`res/upt.zip`(XXTEA解密) → `require 'main'` → `framework_precompiled.zip` → `framework.init` → `an.zip` → `mir2.zip` → `an.init`/`mir2.init`。
- 可写目录：`Debug.win32/data/user/0/com.shengshi.tlc0709/files/upts/`（安卓布局模拟）。
- 控制台日志无法通过管道重定向捕获（AllocConsole + freopen CONOUT$）；`-write-debug-log` 是 Quick Player 的机制，独立 exe 不生效。观察日志请直接看控制台窗口。

## 4. Lua 字节码包重编译（核心！）

### 4.1 背景

`res/*.zip` 内的 LuaJIT 字节码原由开发者在另一台机器（`D:\BaiZhuCocos2dx33\`，2025-2026 工具链）用**新版 LuaJIT（2.1.0-beta3+ 格式）**编译，而本引擎运行时 lua51.dll 是 **2.1.0-beta2**——beta2 解析 beta3+ 字节码时常量池错位，执行即报：

```
[LUA ERROR] [string "main"]:0: attempt to perform arithmetic on a proto value
```

（"proto value" 是 LuaJIT 特有的裸函数原型类型名，= 数值常量被错读成函数原型。）

**修复 = 用 beta2 工具链从明文源码重编译全部 4 个包。**

### 4.2 明文源码与布局

源码：`战神Cocos/`（只读参考目录）——flat 命名，模块名 = 相对 src 路径去 `.lua`、`/` 转 `.`：

| 包 | 编译 src | 条目示例 |
|---|---|---|
| upt.zip | `战神Cocos/upt/` | `main`、`config`、`upt.scene` |
| an.zip | `战神Cocos/an/` | `an.init`、`an.ui.slider` |
| framework_precompiled.zip | `战神Cocos/framework_precompiled/` | `framework.init`、`framework.cc.ui.UIButton` |
| mir2.zip | `战神Cocos/` 下全部 `mir2.*.lua`（218 个 flat 文件） | `mir2.app`、`mir2.data.bag` |

### 4.3 工具链

- **luajit.exe（必须 beta2）**：`Quick-Cocos2dx-Community-3.6.5\quick\bin\win32\luajit.exe`（client-other 自带的是 beta1，编译出的字节码与 beta2 运行时同样不兼容）
- **php 工具链**：`Quick-Cocos2dx-Community-3.6.5\quick\bin\win32\php.exe` + `lib/quick/{init,ScriptsCompiler,xxtea}.php`（client-other 自带的 php 同版可用，但 luajit 必须换）
- **XXTEA 密钥**（AppDelegate.cpp `ORIGINAL_XXTEA_KEY`）：
  `08 75 4D 69 52 40 59 0B 47 6F 6D 67 21 38 34 07`（16 字节），sign = `"01"`

### 4.4 编译步骤

1. **复制源码到 ASCII 路径**（php 处理中文路径有编码问题）：
   ```
   client/lib/res/rebuilt-src/{upt,an,framework_precompiled,mir2}/
   ```

2. **GBK → UTF-8 转换**：legacy Lua 混合编码，非 UTF-8 文件（约 117 个）先按 GBK(936) 解码转 UTF-8，否则 luajit 把 GBK 注释当 UTF-8 解析会报伪语法错误。

3. **修复源码语法错误**（开发者 2026 年改动引入，本仓库已修，清单见 4.6）——用 `luajit check.lua <file>` 逐文件验证：
   ```lua
   -- check.lua
   local f, e = loadfile(arg[1])
   if not f then io.write(e or 'load error') os.exit(1) end
   os.exit(0)
   ```

4. **编译 + 加密**（php 脚本调用 ScriptsCompiler）：
   - `compile = zip`，`bit = 32`
   - upt/an/framework：`encrypt = xxtea_zip`，`sign = "01"`，**key = strrev(ORIGINAL_XXTEA_KEY)**
   - mir2：不加密（引擎对无 "01" 前缀的 zip 走明文路径）
   - **key 必须反转**：引擎 zip 级解密用的是 `std::reverse(key)`（CCLuaStack.cpp），compile_scripts 默认用原 key 加密会方向不匹配，解密后得到无效 zip。

5. **验证往返**：用 `xxtea.php` 的 `decrypt(strrev(key))` 解密产物，确认是有效 zip（能列出条目）。

6. **安装**：先备份原包到 `res/backup_orig_pkgs/`，再覆盖 `res/upt.zip`、`res/an.zip`、`res/framework_precompiled.zip`、`res/mir2.zip`。

## 5. 踩坑记录（已修复，供排查参考）

### 5.1 MSB3202 / MSB4019：`%QUICK_V3_ROOT%` / `$(QUICK_V3_ROOT)` 不展开

msbuild.exe 命令行下 .sln 里的 `%VAR%` 不展开（VS IDE 里可以）。已把 sln 的引擎项目引用改为相对路径（`..\..\cocos2d-x\...`），并把 `BaiZhuClient.vcxproj` 内全部 `$(QUICK_V3_ROOT)`（props Import 2 处 + 源文件/包含目录 136 处）替换为相对路径 `..\..\cocos2d-x`——**构建命令不再需要设置 QUICK_V3_ROOT 环境变量**（2026-08 社区版修复，原报错 MSB4019: `D:\cocos\2d\cocos2dx.props not found` 与 C1083: `\quick\lib\quick-src\...` 均已消除）。

### 5.2 LNK C1900：P1/P2 编译器版本不匹配

现象：
```
libjpeg.lib(jerror.obj) : MSIL .netmodule or module compiled with /GL found; restarting link with /LTCG
LINK : fatal error C1900: Il mismatch between 'P1' version '20251208' and 'P2' version '20240319'
```

根因：`external/{jpeg,chipmunk}/prebuilt/win32/*.lib` 是 2026-08-02 在另一台机器用 **v145 + LTCG(/GL)** 重建的（可用 `lib.exe /list` 看成员路径：`...\win32-libjpeg-v145\obj-v145-x86-release-md-ltcg\...`）。本机工具链链接时自动启用 LTCG，其代码生成器与 /GL 目标的 IL 版本不匹配。

修复：替换为无 LTCG 的干净版（主线仓库 2017 版）：
- `Quick-Cocos2dx-Community-3.6.5\external\jpeg\prebuilt\win32\libjpeg.lib`（792 KB）
- `Quick-Cocos2dx-Community-3.6.5\external\chipmunk\prebuilt\win32\libchipmunk.lib`（3.4 MB）

原 LTCG 文件备份在 `%TEMP%\libjpeg_ltcg_backup.lib`、`%TEMP%\libchipmunk_ltcg_backup.lib`（临时目录，可能被清）。
检测方法：提取 .lib 成员，`dumpbin /directives <obj>` 显示 `File Type: ANONYMOUS OBJECT` 即为 LTCG。

> **注意**：libcocos2d.vcxproj 的 PreBuildEvent 会 `xcopy external\...\prebuilt\win32\*.*` 到 OutDir，只改 OutDir 里的文件无效——必须替换 external 下的源文件。

### 5.3 MSB8020：v100 工具集不存在

见 3.2，`/p:PlatformToolset=v143` 解决。

### 5.4 C4819 / 声明被吞：UTF-8 源文件被按 GBK 解析

现象：`AppDelegate.cpp` 报 `kTargetFramesPerSecond undeclared`（行号还错位）、`CCCustomFilter.cpp` 报 `vertSource undeclared`。
根因：UTF-8 中文注释 + 老 vcxproj 未开 `/utf-8`，MSVC 按 GBK 误读导致注释吞代码。
修复：`BaiZhuClient.vcxproj` 两个配置的 ClCompile 加 `<AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>`。
（已扫描：app 工程源码 0 个 GBK 文件，全局开 /utf-8 安全。）

### 5.5 static_assert 'original pathFinder size'

`Classes/Mir2PathFinderCompat.h` 断言 `sizeof(pathFinder) == 0x1c` 是按 Android gnustl 的 `std::vector`（12 B）布局；MSVC 的 vector 为 16 B，必然不等。已用 `#if !defined(_MSC_VER)` 包住总大小断言，**成员偏移断言保留**（MSVC 下同样成立）。
